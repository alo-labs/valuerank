# ValueRank
**Frontier AI configurations ranked by value for software engineering and DevOps: benchmark quality against what the work costs**

**Version:** v3.1.0
**Updated:** November 26, 2026
**Methodology:** 3.1.0 · SDLC basket v1 · anchor version v3-2026-11-26-a4
**Scope:** 5 cohort configurations (5 with a value score) from a 45-model AA-mapped roster; value is a 25% cost score (nominal weight; 64% of API and 3% of Plan value variance) plus 75% quality over 14 benchmark leaves

## Current result

ValueRank ranks frontier AI model configurations (see Model inclusion) by value for software engineering and DevOps work, separately for API buyers and for subscription (Plan) buyers. It publishes 3 rankings (owner decision O53), each over the configurations that have its complete benchmark set: the **max-effort ranking** below (one configuration per model family at its top effort, scored on the AA leaves plus LiveBench 2.0 Overall and two Vals AI boards) and the AI Coding Daily ranking, the common-leaf diagnostic ranking after it. The max-effort ranking's leaves: FrontierCode 2.0 15%, Terminal-Bench 4.1 (AA run) 11%, Bug Hunt Bench 8%, Vibe Code Bench v1.1 (Vals) 5%, Code Migration v1.1 (Vals) 6%, LiveBench 2.0 Overall 15% (software engineering 60%, of which 51% is coding-specific: LiveBench 2.0 Overall counts as SDLC work (O61), but only its Coding and Long Agentic categories are coding tasks (O122)), plus the 8 leaves outside software engineering every ranking shares. Value is a fixed **25%** cost score plus **75%** benchmark quality. That weight is nominal: on the current panel cost accounts for 64% of the variance in API value and 3% in Plan value, because cost scores spread more than quality scores on the API basis and less on the other (see [methodology.md](methodology.md)). Cost is the contestant-model API token cost for the SDLC basket (not total agent or workflow operating cost): Artificial Analysis' (AA) published cost of running the Coding Agent Index, AA-Briefcase, GDP.pdf, AutomationBench-AA, Terminal-Bench 4.1 (AA Index run), FrontierCode 2.0 and Terminal-Bench-Science once at API rates (the max-effort ranking's basket; each ranking admits its own components, E254), scored on a log scale against frozen anchors so cost ratios keep their size. Coding and terminal tasks (Coding Agent Index, Terminal-Bench 4.1 (AA Index run), FrontierCode 2.0) make up 58% of the basket's cost (median over 5 configurations with the full basket; 53% to 60%); with Terminal-Bench-Science's terminal tasks, whose quality O136 files under science, 73% (69% to 76%; E343); AA-Briefcase, which has no quality leaf, makes up 15%; the Coding Agent Index's SWE-Atlas QnA (124 of its 322 tasks) has no quality leaf either, and its cost share is not separable because AA publishes one pooled cost. Quality is the weighted mean of 14 (in the max-effort ranking; 12 in the AI Coding Daily ranking, 11 in the common-leaf diagnostic ranking) benchmark leaves on fixed 0–100 anchors, and every configuration ranked in a ranking has all of that ranking's leaves for its exact configuration (O36): a leaf AA has not run comes from another party's run of the same benchmark, then from the model provider's published result, and a configuration still missing one after a logged exhaustive search is listed, not ranked. The Plan ranking divides the basket's API cost by a subscription route's Value Multiple at full utilisation, with one row per configuration and plan (O48), and uses the API cost, flagged, when no route is admitted. No Value Multiple is yet identified on the basket itself (0 of 19 rows), so the Plan ranking is labelled exploratory.

Values are rounded for display; ranks are competition ranks (equal values share the better rank). The Plan rank is that of the configuration's own plan row (its selected route) in the Plan ranking of every plan below. Benchmark sampling noise (O39, an independent-task approximation): two values must differ by about 2.7 value points (median, 95%) to separate, and 1 of 4 adjacent API ranks and 1 of 6 adjacent Plan ranks of different configurations do (12 more adjacent Plan pairs are one configuration on two plans, ordered by the plans' multiples alone; E258). Its net direction is not established: every configuration is scored on the same tasks, which correlates their errors and narrows the true threshold (API 1 at correlation 0.3, 1 at correlation 0.6; Plan 2 at correlation 0.3, 4 at correlation 0.6), while sources it leaves out widen it (run-to-run and harness variance, AA's single cost run and, for the 8 Plan rows on an owner assumption (7 owner-named transfers and 1 O198 published dollar limit), that assumption's error). The noise band column groups each row with the band's first row it cannot be told apart from (O42); a Plan band marked † rests on an owner assumption (an owner-named transfer, an O46 provider quota ceiling or an O198 published dollar limit) and excludes its error: an assumed multiple can be wrong by a factor of about 1.4 before the row's value moves by the median threshold (a tolerance, not an estimate of the assumption's error). The S1T scenario shares in [scores.md](scores.md) show each row's rank-1 and top-3 frequencies under that noise.

- **subset cost**: scored on the workload of the components it has, against that workload's own anchors; its ordering against main-workload rows is not identified (O17).
- **provider-claimed leaf**: a quality leaf comes from the model provider's own published result (O36's last source); the row competes but earns no interval label (E233).
- **provisional quality**: observed leaves cover under 70% of quality weight, fewer than two software-engineering leaves or under 40% software-engineering weight are observed, or a leaf weighing 20% or more of its ranking's quality is missing; ranked and flagged, never floored (O8).
- **partial component**: AA marks tasks of a basket component missing or declined (E37), or the component's cost cannot be reconciled with AA's prices (E170).
- **valuation basis unverified**: AA's cost reconciles with neither its displayed prices nor a registered price record; ranked, but outside interval outputs and cost anchors (E170 outcome 4).
- **no cost**: AA publishes no cost for the configuration, so it has no value score and no rank (AGENTS.md); its quality is shown.
- **AA cost caveat**: AA states that its published cost omits a pricing term.
- **API-cost fallback**: no admitted Plan route; the Plan ranking uses the API cost (O13).
- **route possibly superseded**: the selected Plan route's evidence (or its donor's) may be superseded by age or a detected change (E18, E151, O77-O79); it stays selected, and earns no interval label when the trigger is a detected limit or price change rather than age alone or a model-availability change (E228, O107).
- **fault window**: the selected Plan route rests on a controlled measurement inside an acknowledged accounting-fault window; it stays selected until two concordant user reports for its own model and plan replace it, and a transfer resting on it then follows the replacing figure (O91-O95).

## How v3 scores value

- **Cost is the SDLC basket.** SDLC basket v1: AA's published cost of running the Coding Agent Index, AA-Briefcase, GDP.pdf, AutomationBench-AA, Terminal-Bench 4.1 (AA Index run), FrontierCode 2.0 and Terminal-Bench-Science once at API rates, in USD per basket run. Pending capture: ITBench-AA. v2 used AA's cost to run the whole Intelligence Index per Index point.
- **Cost keeps its magnitude.** The cost score is 100 × (ln c_H − ln c) / (ln c_H − ln c_L), clipped to 0–100, against anchors frozen with anchor version `v3-2026-11-26-a4`. A model entering or leaving the cohort does not move another model's score. At the API anchors, doubling cost costs 3.13 value points, which 4.17 quality points offset.
- **Quality is measured, not ranked.** Each leaf (14 in the max-effort ranking) is placed on fixed 0–100 anchors from its raw value, so quality no longer depends on which other models are ranked. Only configurations with every leaf are ranked (O36), so all ranked rows are scored on the same benchmarks; each leaf filled from another party or a provider is listed in [raw-data.md](raw-data.md#leaf-gap-fills-and-searches-o36).
- **Plan value is route evidence.** Each subscription route carries its Value Multiple, evidence grade (controlled measurement, concordant reports, owner-named assumption) and identification status; the Plan ranking is labelled exploratory until multiples are identified on the basket.
- **Uncertainty is shown, not hidden.** Interval outputs certify which frontier and cheapest-above-a-bar claims the published record supports; scenario shares report frequencies over declared streams.
- v3 values are not numerically comparable with v2 or earlier releases.
