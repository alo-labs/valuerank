# Site data contract

The multi-page site is generated by `valuerank.site.build` from the committed snapshots in `data/`. The generator produces two things that other code depends on: **public JSON files** under `site/data/` (consumed by the client scripts and offered for download) and **page view models** (passed to the Jinja templates). This document is the contract between the view-model code (`valuerank/site/viewmodel.py`), the templates (`valuerank/site/templates/`) and the client scripts (`valuerank/site/assets/js/`). Change it before changing any of them.

All numbers are JSON numbers or `null`; no value is ever filled in. Identifiers are the model ids used in `data/scores.json` with dots replaced by hyphens (`slug = id.replace('.', '-')`, so `gpt-6.1-sol` is `gpt-6-1-sol`), called `slug` below. Model links everywhere are `/models/<slug>/`. Dates are ISO 8601 strings.

## Evidence grades

Every value that reaches a page carries a grade. One enum, rendered by one component (`badge`):

| Grade | Meaning | Examples |
|---|---|---|
| `measured` | Measured by the benchmark owner, or by a controlled account measurement for plan allowances | AA component values, DeepSWE chart rows, Bug Hunt owner scoreboard, LiveBench release data, Terminal-Bench official rows, SemiAnalysis controlled-account plan measurements |
| `claim` | Published by the model provider, exact benchmark version and evaluated variant | `data/provider_claims.json` entries with `eligibleForRanking: true` |
| `estimate` | Owner estimate or projection anchored to a measurement | AA `intelligenceIndexStatus: "estimated"`, user-reported allowance projections |
| `assumption` | Explicitly authorised assumption with no measurement | MiMo 1.5× plan multiple, common ChatGPT multiples applied across GPT variants |
| `missing` | No eligible value; the dimension is excluded from that model's renormalised score | Any `null` metric |

Rules:
- `dims` holds the normalised 0–100 score per non-cost dimension (`null` when missing). `costDims` holds the cost dimension score per basis; the client substitutes it for `costComposite` when recomputing.
- `overall[basis]` and `rank[basis]` are the committed values for each basis at the default cost weight. The client recomputes both when the cost-weight slider moves, using `dimensions[].weightPct`, `dims`, `costDims` and the fixed cost-share rule: cost takes the slider's share when the model has a cost score, and the available quality dimensions split the rest in proportion to their weights. Ties break by lower cost on the basis (`cost.apiUsdPerPoint` or the plan cost per point), then name. Cost has no `priority`; its `weightPct` is the fixed default share. `coverage.pct` is cost's share (when `costAvailable`) plus the quality share times `availablePriority / totalPriority`, both counted over quality priorities only.
- `models` contains every roster model (28), ranked ones first. Unranked models have `rank` values `null`, `overall` values `null`, and `exclusionReasons` filled.
- `modelInclusion` states the two-part model-inclusion policy and is read from `frontierSelection` in `data/scores.json` (a copy of `data/ranking_summary.json`): the frontier rule, the near-frontier rule (threshold from `nearFrontierPolicy.maxIntelligenceGap`, default 3, as a string in `nearFrontierGap`), the optional recorded `policyText`, the `observation` sentence (chart date, Index version, catalog, plotted and vertex counts, near-frontier counts), `nearFrontierStatus` (required and deferred model counts), the `frontierFamilies` and `nearFrontierFamilies` lists with the selected configuration (`gap` is the Index-point gap, as a string) and one `footnotes` entry per distinct Artificial Analysis footnote with the model names it applies to. Every optional part is `null` or an empty list when `frontierSelection` lacks the field; the two rules are always present.
- `aaFrontierTier` (`"frontier"`, `"near"` or `null`), `aaFrontierConfiguration`, `aaFrontierIntelligenceGap` (Index points below the rendered frontier at the model's cost, `0` on the frontier) and `aaFrontierFootnote` (Artificial Analysis' footnote for the model's points, for example the Claude Haiku 5.5 long-context pricing note) pass through unchanged from `data/scores.json` and are `null` when the snapshot lacks them. Frontier membership is the line Artificial Analysis renders, never recomputed. The rankings table shows a text badge ("AA frontier" or "Near frontier") with the configuration and gap in its tooltip; the model page shows the badge, the same fields under `frontier` (`tier`, `configuration`, `intelligenceGap`, `footnote`), and the footnote as a note beside the cost evidence (it is also the `note` of the `costComposite` dimension).
- `grade` on a model is the worst grade among the values that enter its score (`measured` < `claim` < `estimate` < `assumption`).
- `picks[basis]` holds three cards that show three different angles; each has `slug`, `label`, `reason` (under 25 words), `score` and `unit`, and is `null` when the cohort cannot supply it. `value` is rank 1 on that basis (label "Best overall value"). `other` is rank 1 on the other basis, labelled from `bases[other].pickLabel` ("Best at API rates" or "Best on a subscription") with a reason that states both ranks; when that is the same model as `value`, it becomes the quality leader ("Best quality, any cost") and, if that is also `value`, the runner-up overall ("Runner-up overall"). `budget` is the best overall model in the cheapest third by that basis' cost score, skipping models already picked when that third holds more than one model (and keeping them if skipping would leave nothing). `bases[key]` carries `pickLabel` and `pickPhrase` ("at API rates", "on a subscription") for the other-basis card. The client applies the same rule in `scoring.js` when the cost weight moves, scoring both bases at that weight.

### `site/data/benchmarks/terminal-bench-4.json`

The current `data/tb4.json` content plus `frontierCount` and the cohort mapping used by the Terminal-Bench page.

`rows[].costUsd` may be `null` when the leaderboard publishes no cost for a row; `rowsWithoutCostN` counts such rows. They keep their rank and resolution rate, are listed last when ordered by cost, never count towards `frontierCount`, are left off the cost axis of the chart, and render as "Not published" in the table.

### `site/data/changelog.json`

`{ "versions": [ {"version": "v1.9.6", "date": "October 8, 2026", "models": 16, "dimensions": 16, "summary": "…", "ranks": {"gpt-6-1-sol": 1}, "rankChanges": [ {"slug", "name", "from": 3, "to": 1} ], "added": [slug], "removed": [slug]} ] }`, newest first, built from `data/ranking_history_v1.5.json` and the current ranking.

`ranks` maps slug to the API-basis rank recorded for that version. It is never inferred: a version only lists the models it has a record for, and a version without a record for a model contributes nothing for it (the bump chart leaves a gap). Historic ranks predate the plan basis, so `rankChanges` compare API-basis ranks.

### `site/data/livebench.json`

`{ "release": "2026_06_25", "observedAt": "…", "rows": [ {"id": "gpt-5-5", "name": "GPT-5.5", "livebenchModel": "…", "overallScore": 82.9, "instructionFollowingScore": 75.8, "costPerSuccessfulTaskUsd": 1.4777, "pareto": false} ] }`

Matched rows only (roster models and supplemental ones that LiveBench has a verified exact result for), cheapest first. `id` is the slug (supplemental ids have no model page). `pareto` is true for the LiveBench frontier recorded in `data/livebench.json`. The LiveBench chart reads `rows`.

## Page view models

`build.py` renders each template with `page` (per-page object) plus shared `site`:

```python
site = {"version", "publishDate", "observedAt", "nav": [{"label", "href", "key"}], "baseUrl": "https://valuerank.alolabs.dev", "basis": rankings["bases"], "defaultBasis": "plan", "costWeightPct", "modelCount", "rosterCount", "dimensionCount"}
```

| Template | `page` keys |
|---|---|
| `index.html` | `headline` (one sentence per basis of at most 18 words, leading with the model name: `{"plan": "…", "api": "…"}`), `picks`, `models` (ranked 16, compact fields including `coverage`), `dimensions`, `chart`, `rankingsJson` (embedded as `rankings-data`) |
| `rankings.html` | `rankingsJson`, `nearFrontierGap` (string, from `modelInclusion`), `providers` (sorted developers), `grades`, `columns` (`[{key, label, sortable, default}]`; keys are the script catalogue: `rank`, `name`, `overall`, `quality`, `cost`, `grade`, `coverage`, `developer`, `qualityRank`, `speed`, `ii`, then one per non-cost dimension) |
| `models.html` | `models` (all 28 roster models, ranked first: `slug`, `name`, `developer`, `rank`, `overall`, `grade`, `rankingEligible`, `coveragePct`), `rankedCount`, `unrankedCount` |
| `model.html` | the model JSON above plus `related` (same developer) |
| `plans.html` | `plansJson`, `workedExample: {models: [{slug, name, routeLabel, planFeeUsd, valueMultiple, grade, evidenceLabel, indexValue, apiUsd, planUsdPerRun, planUsdPerPoint}]}`, `routesByProvider` |
| `benchmarks.html` | `benchmarksJson` |
| `benchmark_tb4.html` | `tb4Json` (`data/tb4.json` plus `frontierCount` and `cohortMapping`) |
| `methodology.html` | `dimensions`, `costWeightPct`, `weights`, `workedExample: {slug, name, basis, overall, availableWeightPct, availablePriority, totalPriority, steps: [{key, label, weightPct, normalized, included, effectiveWeightPct, contribution}], missing}`, `modelInclusion` (the `rankings.modelInclusion` object above, rendered as the "Model inclusion" section), `faq` (list of `{q, a}` without release notes), `limitations` |
| `changelog.html` | `changelogJson` |
| `data.html` | `files` (list of `{path, description, schema}`; `path` is absolute, for example `/data/rankings.json`) |
| `archive_banner.html` | `archiveDate`, `archiveHref`, `note` |
| `redirect.html` | `target`, `canonical`, `title` |

Every page gets `page.title` (the full document title; nothing is appended), `page.description`, `page.canonical`, `page.ogImage`, `page.key` (the page type, written to `<body data-page>`) and `page.scripts` (the module scripts it loads; see below). The catalogue is in `valuerank/site/build.py`.

## URL view state (client)

Query parameters, all optional, parsed on load (the URL wins over any default), written with `history.replaceState` on every change:

| Param | Pages | Values |
|---|---|---|
| `basis` | all with a toggle | `api` or `plan` |
| `w` | index, rankings | cost weight percent, 0–100, one decimal |
| `sort`, `dir` | rankings | dimension or column key; `asc` or `desc` |
| `cols` | rankings | comma-separated column keys |
| `provider` | rankings | comma-separated developers |
| `grade` | rankings | comma-separated grades |
| `route` | rankings | `all`, `eligible`, `fallback` |
| `cov` | rankings | minimum coverage percent |
| `q` | rankings | search text |
| `compare` | rankings | comma-separated slugs (2–4) |
| `chart` | index, rankings | chart tab key (default tab omitted) |

`urlstate.js` exposes `parseState(search, defaults)` and `serializeState(state, defaults)`; keys equal to their default are omitted so a clean URL stays clean. Only the theme is stored in `localStorage`.

## Client conventions

### Embedded JSON

`<script type="application/json" id="rankings-data">` holds `rankings.json` on `/` and `/rankings/`. Other pages with a document of their own (`/plans/`, `/benchmarks/`, `/benchmarks/terminal-bench-4/`, `/changelog/`) embed it as `id="page-data"`. Pages that need more than they embed fetch the public files (`/data/rankings.json`, `/data/livebench.json`).

### Boot modules (`page.scripts`)

`base.html` loads only `page.scripts`. Each entry in `assets/js/pages/` is two lines (import and call with `window`); the logic is in `pages/boot.js`.

| `page.key` | Script | Does |
|---|---|---|
| `index` | `pages/index.js` | `initIndex`, charts from the embedded rankings |
| `rankings` | `pages/rankings.js` | `initRankings`, charts from the embedded rankings |
| `benchmarks` | `pages/benchmarks.js` | charts from fetched `rankings.json` + `livebench.json` (`livebench: rows`) |
| `tb4` | `pages/tb4.js` | chart from the embedded Terminal-Bench document |
| `changelog` | `pages/changelog.js` | bump chart from the embedded versions + fetched `rankings.json`, API basis |
| everything else (`models`, `model`, `plans`, `methodology`, `data`) | `pages/static.js` | theme, menu, FAQ |

Every boot calls `initApp` (theme, menu, FAQ).

### DOM hooks

- Chrome: `[data-nav-toggle]` (with `aria-controls="site-nav-links"`), `[data-theme-toggle]` (`#theme-toggle`). The theme is the only thing stored locally, under `localStorage["vr-theme"]`.
- Basis: `#basis-toggle` containing `[data-basis]` buttons (`aria-pressed`). On every basis change `document.documentElement.dataset.basis` is set (the inline head script also sets it from `?basis=`); CSS shows `[data-basis-only="plan|api"]` accordingly. `[data-basis-label]` and `[data-cost-unit]` receive the active basis' label and unit.
- Cost weight: `#cost-weight` (range) and `#cost-weight-value` (output).
- Answer page: `#index-body`, `[data-pick]` with `[data-pick-name]` (the link), `[data-pick-score]`, `[data-pick-reason]`.
- Rankings: `form#filters` (`input[name=q|provider|grade|cov]`, radios `name=route`; no provider or grade selected means no filter), `[data-action="reset-filters"]` (any number), `#filter-cov-value`, `#column-picker-list` (filled by the script), `#rankings-head` and `#rankings-body` (filled by the script; the server renders a skeleton header and a `[data-state="loading"]` row), `#rankings-count`, `#rankings-empty`, `#rankings-error`, `#compare-drawer` / `#compare-body` / `#compare-clear`, `#export-csv` / `#export-json` (anchors; the script sets a blob `href` and `download` on click), `[data-share]`.
- Table cells carry `data-col` (the column key; the model column is `name`, rendered as a row header) and `data-label`. Rows carry `data-slug`; compare checkboxes carry `data-compare="<slug>"`.
- Charts: `[data-chart="<key>"]` containers inside `[data-chart-panel="<key>"]`, tabs `[data-chart-tab="<key>"]`, and a `[data-chart-summary]` element in the same panel. Keys: `pareto`, `decomposition`, `displacement`, `frontier2`, `bubble`, `heatmap` (rankings), `heatmapData`, `livebenchPareto` (benchmarks), `bump` (changelog), `tb4`. Panels hide through `hidden`; `data-chart-status` becomes `ready`, `empty` or `error`.

### Events

- `vr:statechange` on `document`, from the rankings and index scripts: `detail = {state, models, data}`.
- `vr:state` on `<body>` (charts): `detail = {basis, costWeightPct, models}`, bridged from `vr:statechange`.
- `vr:theme` on `<body>`: `detail = {dark}`, dispatched by the theme toggle.

The chart tab is written by `pages/boot.js` as `?chart=<key>` through the same URL sync as every other parameter; the first tab of the card is the default and leaves the URL clean. The state scripts preserve whatever `chart` the URL holds when they rewrite it.
