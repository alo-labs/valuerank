# ValueRank methodology — draft r05

## Objective and claim scope

AA's Pareto frontier of Intelligence Index vs. total USD cost to run its Intelligence Index does not answer the question ValueRank exists for: **which frontier AI model is actually lowest cost for the value it delivers in practice**, once (a) subscription-plan economics are considered and (b) benchmarks geared to real software-engineering work are weighed alongside general capability. ValueRank serves two buyers, ranked separately: **API buyers** (pay per token, incl. third-party agents) and **Plan buyers** (provider subscription apps/CLIs: Claude Code, Codex, ChatGPT, SuperGrok…).

Claim scope: "value among AA-selected frontier and near-frontier configurations, under the published benchmark mix and evidence". Not a market-wide optimum across all configurations and workloads.

## Outputs

1. **Headline**: value score per basis = 0.25 × cost score + 0.75 × quality score (owner decision). The implied exchange rate is printed beside it per basis (with the anchors below, doubling cost ≈ −2.9 value points ≈ 3.9 quality points on API, ≈ −2.3 ≈ 3.0 on Plan) and each release's within-cohort spread 0.25 × SD(S_C) vs 0.75 × SD(S_Q), together with cost-weight slider results in the main table. No quality floor (owner decision); provisional rows are flagged. **Leader rule**: the "recommended" label on either basis goes only to a row that is non-provisional, not strictly dominated on the definite frontier, and first in ≥ 90% of measurement scenarios with owner-authorised transfers off and AA sources included, and whose lead holds on its identification bounds. Every cohort row stays in the table; a row failing the rule can still hold rank 1 but carries no "recommended" label.
2. **Cost–quality frontier** per basis, bound-aware: "definite" vs "possible" frontier members.
3. **Cheapest above a quality bar**, with bars defined by named reference configurations (e.g. "at least the quality of the median definite-frontier model"), not raw numbers; bound-aware: a model is "confirmed qualifying" if its lower quality bound ≥ bar, "possibly qualifying" if only its upper bound is. A uniquely cheapest recommendation is named only if its worst-case cost beats every possibly-qualifying candidate's best-case cost; otherwise a candidate set is published.
4. **Diagnostics**: USD per AA Index point, AA Intelligence Index, AA tokens used to run the suite, output speed, raw values, evidence grades, measured-only Plan view.

## Source contract (versioned registry)

Machine-readable registry per release: AA chart identity, filters and snapshot timestamp (current: "Intelligence Index vs. Cost to Run Artificial Analysis Intelligence Index", x-axis "Cost to Run Intelligence Index (USD)", unit "USD to run all Intelligence Index evaluations", captured 2026-10-17); cost field, unit and accounting (as AA defines it, including any cache pricing AA applies); per model: version, effort, fallback, serving route and per-benchmark stack; per benchmark: version, raw metric, population, attempts, aggregation, source revision/commit, observation and retrieval dates; explicit missingness reason (not evaluated / incompatible variant / no public evidence / withdrawn). A change of AA chart or field is a versioned methodology migration, never a silent refresh.

## Cohort and configuration (fixed policy)

- AA rendered Pareto families as observed plus near-frontier families (rounded Index within 3 points of the frontier's best at equal or lower cost); 19 families now.
- Configuration rule: the configuration AA plots on (or nearest to) the frontier; manifest records model/version, effort, fallback, and per-benchmark harness/tool limits. Exact-variant evidence only; harness differences shown as separate stack evidence. Missing stays missing.

## Cost (25% of the value score)

- **API cost input** = AA total USD to run the full Intelligence Index suite (token efficiency × list price). **Rationale (owner decision)**: an end-to-end software project draws on nearly every kind of work AA benchmarks — research and knowledge, documents and spreadsheets (Briefcase, GDP.pdf), professional tasks, agents and terminals, science and long context — not only coding, so the whole-suite bill is the intended price of a model's work; it is deliberately not reweighted to ValueRank's quality mix. Not divided by the AA Index (that would count AA's capability mix twice); USD per Index point is a diagnostic only.
- **Matched-cost diagnostic**: AA's per-evaluation cost per task re-weighted by ValueRank's leaf weights (not AA's own weighted cost-per-task figure), plus cost per solved task, preferring the independent tbench.ai leaderboard's cost/token columns over AA-run data for the cross-check (dependence on AA disclosed). If a model's rank under matched cost differs from its total-cost rank by more than 3 places it is flagged, and it cannot receive the "recommended" label on that basis.
- **Plan cost input (full-utilisation effective cost, labelled)** = API cost input ÷ Value Multiple of the selected route. Computed per model–plan **tier**–surface–configuration route (tier and fee are part of route identity and published). To avoid winner's-curse bias, the route is chosen on the **lower bound** of each multiple's range (point value where only a point exists), after joining access conditions and evidence. **Full utilisation** means the API-equivalent value achievable when every simultaneous limit window (e.g. 5-hour and weekly) is saturated over the fee period: the minimum across binding windows, not the largest single cap. The fee is the amount paid for the measured period (no annual-discount conversion). **Token mix**: where category-specific multiples exist (input, cache read/write, reasoning, output), the route multiple is M = (Σ_k t_k / m_k)⁻¹ with t_k the category shares of the model's AA cost; otherwise the measurement's category mix is compared with AA's: L1 distance on category shares > 0.30 flags the route "mix-unmatched" (shown, not silently trusted). API-fallback rows are shown but excluded from Plan winner, frontier and threshold claims.
- **Admission rule for the official Plan ranking (owner decision)**: a measured route enters only via a controlled saturation measurement with receipts (e.g. SemiAnalysis) or ≥ 2 independent end-user reports concordant within ±20%. Single-source routes are diagnostics and cannot earn "recommended". Owner-named transfers (O4/O7) remain labelled assumptions. Each multiple records source count and sampling basis (power users who saturate plans are over-represented).
- **Quota schema**: the registry stores each plan's limit-schema version (windows such as 5-hour and weekly, shared pools across surfaces), how reset balances are treated (counted only if a measurement shows them spendable on the measured workload) and fee decomposition (bundled monthly API credits are subtracted at API list value before computing the multiple). A schema change triggers the 30-day soft expiry.
- **Value Multiple** = API-priced usage a plan delivers over a stated fee period ÷ fee for that period. Each multiple records fee period, workload, model/effort, token categories (input, cache read/write, reasoning, output), valuation price list and date, shared usage pools, whether capacity was exhausted and which rate-limit windows bound it. Where public token receipts exist, the numerator is repriced on the same price list as AA cost; otherwise the original valuation basis is kept and flagged. No extrapolation of short bursts to a billing period unless the controlled measurement establishes it. Evidence rules unchanged (no provider marketing quotas; end-user API-priced reports or SemiAnalysis controlled measurements).
- **Assumptions**: only the owner-named model-to-model transfers (Opus 5.5's measured Claude multiples to other Claude models; common GPT multiple; MiMo 1.5×) stay in the official Plan ranking, labelled, with donor measurement identified. Any other mismatch (effort, surface, workload, price basis) is "unmatched" and excluded from the official Plan ranking. A measured-only Plan view is published.
- **Scoring with frozen, per-basis anchors** in total-USD units: S_C = 100 × clip((ln c_H − ln c)/(ln c_H − ln c_L), 0, 1). API: c_L = $50, c_H = $20,000 (cohort spans ~$110–$8,700). Plan: c_L = $1, c_H = $2,000 (native routes span ~$3–$860 because Claude multiples are ~57–59×). Anchors are scaling constants from a frozen reference cohort's 1st/99th percentiles, versioned separately from data refreshes; dollars always displayed and unclipped values kept in the data release. Release gate: fail if more than 10% of rows sit at a clip bound on either basis.

## Quality (75% of the value score)

Normalisation on raw magnitudes with frozen, versioned anchors: z = 100 × clip((x − a_low)/(a_high − a_low), 0, 1); a_low = chance/baseline level, a_high = documented ceiling where one exists, else 100%; rounded inputs treated as rounding ranges; unclipped z kept in the data release. Each release publishes **effective weights** (w_i × SD(z_i), normalised), the leaf rank-correlation matrix and the **share of quality weight by data source** (today ≈75% AA-run: DeepSWE, FrontierCode, GDPval, AutomationBench, Omniscience, LCR, HLE, GPQA, SciCode, CritPt; ≈25% independent: Bug Hunt, Terminal-Bench, LiveBench). A group whose effective weight drifts more than ±50% from nominal is flagged. AA Intelligence Index and output speed are diagnostics, not quality.

- **One quality vector serves both bases (owner decision)**; harness differences (e.g. Bug Hunt run in vendor CLIs) are disclosed as a limitation.
- Missing data: quality renormalised over a row's available leaves (fixed leaf weights; no imputation). **Coverage** = observed share of total quality weight. A row is **provisional** (still ranked, per cohort policy, but flagged and excluded from "unique cheapest" claims) unless coverage ≥ 70%, at least 2 SWE leaves are observed, observed SWE weight ≥ 40% of quality, and no leaf with nominal weight ≥ 20% (DeepSWE) is missing. Identification bounds L (missing at 0) and U (missing at 100) are the formal interval; a separately labelled **sensitivity band** sets missing leaves to the cohort's observed min/max for that leaf (sensitivity analysis, not imputation). A row without a cost gets no value score.

## Attempts reconciliation

The manifest records, per leaf, attempts counted in quality (e.g. DeepSWE pass@1 averaged over 3) and attempts priced in cost (AA's run cost excludes repeats). Where they differ, the bias bound is carried as a draw in the identification layer.

## Uncertainty (three separate layers, one scenario engine)

A joint scenario simulation (N = 10,000) is the single engine. **Cost is drawn too**: price basis (first-party list vs cross-provider median), cache-hit rate within its manifest range, and token-use variance (clustered resampling where per-task/per-run costs are published, otherwise a declared parametric range); one shared "serving snapshot" draw couples a model's cost with its AA-run leaf values. Each scenario also draws leaf values from their measurement intervals, multiples from their ranges, identification bounds for missing leaves, a weight vector from a Dirichlet with α_i = 50 × nominal w_i, a source-drop flag (incl. drop-AA) and the owner-authorised transfer on/off flag; shared multiples and price lists are drawn once per scenario. Strata are cumulative and computable from the registry: **S0 measurement** = renormalised composite over observed leaves with measurement and cost draws; **S1** = S0 + identification draws (missing-leaf bounds, attempts bias, multiple ranges); **S2** = S1 + specification draws (weights, source drops, transfers, GDPval mapping). Draw kernels are declared per input: uniform on rounding ranges, clustered resampling on raw runs, triangular on observed-run ranges otherwise. Results are published **per stratum** (S0, S1, S2; transfers on/off; leave-AA-out), never averaged into one figure, as scenario shares (e.g. share of scenarios with rank ≤ 3, on the frontier, qualifying at a bar), labelled as scenario frequencies, not probabilities. A "unique cheapest" is named only when it holds in ≥ 90% of scenarios. Layers:

- **Measurement**: published intervals, rounding ranges, task- or run-clustered resampling where per-task/per-run data exist.
- **Identification**: missing-data bounds; unmeasured Plan quantities (multiple ranges).
- **Specification**: alternative leaf weights, leave-one-benchmark-out, leave-one-source-out (**leave-AA-out is a headline robustness column**), cost-weight slider, owner-authorised transfer on/off.
- **Workload cross-check (mandatory)**: where DeepSWE or Terminal-Bench 4.0 publish matched cost and success, compute cost per solved task and report its rank agreement with the AA-cost ranking; Spearman < 0.7 puts a warning on the headline and any model moving more than 3 places is flagged.
Shared dependencies move together (one multiple, price update or benchmark version affects all its rows jointly). Robust pairwise orderings are published only when they survive the declared joint scenarios; overlap is not treated as transitive tie groups.

## Governance

Evidence classes (measured / claim / estimate / assumption); provider claims never overwrite independent measurements. Plan evidence carries a 30-day soft expiry with change detection (a plan whose published limits or pricing page changed since measurement is flagged "possibly superseded") and a 90-day hard expiry (flagged stale, not replaced). Each row stores its AA price-list date; score changes are decomposed into price change vs token-use change vs method vs cohort. Freshness: AA cost snapshot and price list max age 45 days, with change-triggered refresh; monthly cadence. Each row publishes its own effective weights (per-row renormalisation changes them) and SD(S_C) with a cost-vs-quality variance decomposition of its value score. Release gates (on failure the release is **held** — fix the data or re-anchor as a versioned migration with a dual-run comparison; owner decision): clip rate > 10%, an unversioned AA chart/field change, or any score swing > 5 points without an attributed cause. The registry records, per row: chart field name; total cost and cost per task side by side; repeat inclusion; cache-hit-rate assumption and date; price rule (first-party list vs cross-provider median for open weights); fallback-token treatment; Elo anchor identity (e.g. GDPval-AA scale pinned to a named reference model) and judge-panel/grader versions for rubric-graded leaves. A change in any of these is a methodology migration. Score moves are decomposed into price, cache rate, token use, method and cohort. Leave-AA-out is suppressed when the remaining identified quality weight is under 40%.

## Known limitations

Full-utilisation Plan cost overstates value for light users; AA cost uses AA's token mix; Bug Hunt covers two repositories; DeepSWE/Bug Hunt/TB measure model+harness stacks; suite is primarily English text.
