# ValueRank methodology — draft r13

*Where prose and the Normative definitions differ, the Normative definitions govern.*

## Objective and claim scope

AA's Pareto frontier of Intelligence Index vs. total USD cost to run its Intelligence Index does not answer the question ValueRank exists for: **which frontier AI model is actually lowest cost for the value it delivers in practice**, once (a) subscription-plan economics are considered and (b) benchmarks geared to real software-engineering work are weighed alongside general capability. ValueRank serves two buyers, ranked separately: **API buyers** (pay per token, incl. third-party agents) and **Plan buyers** (provider subscription apps/CLIs: Claude Code, Codex, ChatGPT, SuperGrok…).

Claim scope: "value among AA-selected frontier and near-frontier configurations, under the published benchmark mix and evidence". Not a market-wide optimum across all configurations and workloads.

## Outputs

1. **Headline**: value score per basis = 0.25 × cost score + 0.75 × quality score (owner decision). The implied exchange rate is printed beside it per basis, computed from the active anchor version (unclipped region): a cost doubling changes value by −100·β·ln2 / ln(c_H/c_L) and is offset by +100·β·ln2 / ((1−β)·ln(c_H/c_L)) quality points, β = 0.25 and each release's within-cohort spread 0.25 × SD(S_C) vs 0.75 × SD(S_Q), together with cost-weight slider results in the main table. No quality floor (owner decision); provisional rows are flagged. **Leader rule (certification)**: the headline word "recommended" means **interval-certified among directly evidenced routes** (editor decision E7; the comparison set and exclusions are listed, exclusions are not failed margins). Certification is **pairwise on common support**: for each pair (i, j), leaves missing for either row are dropped from that difference (dropped weight published); common-support weight must be ≥ 70% with the SWE gates met; nominal weights, primary price rule, frozen route and linear GDPval map are fixed; shared prices, donor meters and quota pools move together; independent inputs take their adverse endpoints; [0,100] fills are never placed inside Θ_cert. A pair is uncertifiable if any scored input with nominal weight ≥ 5% has certificate_role "unidentified" without a pre-registered conservative bound. **Scenario-supported** = leads in ≥ 90% of S0 scenarios computed on the same common-support estimand (S2 is reported as maximum rank change, not a separate hurdle). **Not identified**: neither.
2. **Cost–quality frontier** per basis, bound-aware: "definite" vs "possible" frontier members.
3. **Cheapest above a quality bar**: each release pins named reference configurations (identity frozen at release, e.g. the model that was the median definite-frontier model at release time). Three relations are published: interval-certified qualification (Q_i^L ≥ Q_r^U), possible qualification (some jointly admissible state with Q_i ≥ Q_r), and scenario qualification (share of scenarios with Q_i ≥ Q_r, drawn jointly); bound-aware: a model is "confirmed qualifying" if its lower quality bound ≥ bar, "possibly qualifying" if only its upper bound is. A uniquely cheapest recommendation is named only if its worst-case cost beats every possibly-qualifying candidate's best-case cost; otherwise a candidate set is published.
4. **Diagnostics**: USD per AA Index point, AA Intelligence Index, AA tokens used to run the suite, output speed, raw values, evidence grades, measured-only Plan view.

## Source contract (versioned registry)

Machine-readable registry per release: AA chart identity, filters and snapshot timestamp (current: "Intelligence Index vs. Cost to Run Artificial Analysis Intelligence Index", x-axis "Cost to Run Intelligence Index (USD)", unit "USD to run all Intelligence Index evaluations", captured 2026-10-17); cost field, unit and accounting (as AA defines it, including any cache pricing AA applies); per model: version, effort, fallback, serving route and per-benchmark stack; per benchmark: version, raw metric, population, attempts, aggregation, source revision/commit, observation and retrieval dates; explicit missingness reason (not evaluated / incompatible variant / no public evidence / withdrawn). A change of AA chart or field is a versioned methodology migration, never a silent refresh.

## Cohort and configuration (fixed policy)

- AA rendered Pareto families as observed plus near-frontier families (rounded Index within 3 points of the frontier's best at equal or lower cost); 19 families now.
- Configuration rule: the configuration AA plots on (or nearest to) the frontier; manifest records model/version, effort, fallback, and per-benchmark harness/tool limits. Exact-variant evidence only; harness differences shown as separate stack evidence. Missing stays missing.

## Cost (25% of the value score)

- **API cost input = SDLC cost basket (owner decision O15, replaces total Index cost).** C_i = Σ over basket evaluations e of AA's published cost for the exact configuration (cost per task × the evaluation's task count). Basket = the AA benchmarks whose tasks are typically part of an end-to-end SDLC and DevOps/IT workflow: **Coding Agent Index** benchmarks (incl. DeepSWE), **FrontierCode**, **ITBench-AA**, **MMMU-Pro**, **AA-Briefcase**, **GDPval-AA**, **GDP.pdf**, **AutomationBench-AA**, **Terminal-Bench 4.0**, **SciCode**, **AA-LCR**. Excluded: HLE, AA-Omniscience, CritPt (knowledge/science recall). Feasibility today: the seven Index evaluations decompose exactly (AA total = Σ cost per task × fixed task counts: Briefcase 91, GDPval 220, GDP.pdf 100, AutomationBench 657, Terminal-Bench 66, SciCode 288, LCR 100; verified to <0.002%) for all 19 rows; the Coding Agent Index page publishes per-configuration cost; FrontierCode and MMMU-Pro publish "Cost to Run" charts that need a browser capture; an ITBench-AA cost source is not yet located. **Phasing**: an evaluation enters the scored basket only when exact-configuration cost is captured for every ranked row (common basket); until then it is listed as "pending capture", and the release publishes basket coverage. Total Index cost and USD per Index point remain diagnostics. **Workload object W** (versioned, hashed): the set of unique execution components (e, n_e) with frozen task multiplicities, configuration and deployment policy; C_i,W = Σ_e n_e × c_ie, where c_ie is cost per workload task for **one deployment-equivalent pass** (extra evaluation repetitions excluded, matching AA's totals; editor decision E9). Aggregates (e.g. a Coding Agent Index total) and their components are mutually exclusive in the accounting tree — an aggregate is either a reconciliation check or a substitute, never additive; a machine-checkable accounting tree is published. Basket membership is frozen within a workload version; adding or removing a component is a workload migration with an overlap bridge (old vs new basket costs, scores and ranks for configurations evidenced under both) and Plan-transport revalidation. **Missing component for a row (owner decision O17)**: the row is scored on its available subset, flagged "subset cost — not comparable for certification", with its cost compared on that same subset, never by summing fewer items against full-basket costs. **Subset calibration contract (editor decision E10)**: each subset used is a versioned workload W_S (hashed components and multiplicities) with its own frozen anchor pair (c_L,S, c_H,S) from the frozen reference configurations evidenced on W_S, using the same percentile convention; paired full/subset costs, scores, exchange rates and rank differences are published wherever both are evidenced; missing component costs are never filled to build the bridge. The row keeps its owner-required score and table position, labelled in the table "cross-workload ordering not identified". Release assertion: the scored field is the basket sum, not cost per task, not AA's 7:2:1 blended price, not total Index cost.
- **Matched-cost diagnostic**: the basket evaluations' costs re-weighted by ValueRank's leaf weights (AA exact-variant per-evaluation cost only; tbench.ai cost columns are never joined into it), plus cost per solved task. A row whose reweighted matched cost reverses its pairwise cost order against the leader, or whose rank differs by > 3 with a > 1.5× ratio gap, cannot be certified.
- **Plan cost input (full-utilisation effective cost, labelled)** = API cost input ÷ Value Multiple of the selected route. Computed per model–plan **tier**–surface–configuration route (tier and fee are part of route identity and published). The official route is chosen **lexicographically**: identified M_W first, then evidence grade, then the multiple's lower bound (point value where only a point exists), then lower fee; the lower-bound-only choice is published as sensitivity. Route key = plan × limit-schema version × purchase cohort (e.g. grandfathered pricing) × surface × model × effort; page diffs flag but do not clear a route — a new public measurement does; press round-numbers are never multiples. Plan scores without an identified M_W are kept (owner decision: keep scoring, flagged "workload-unmatched"); after joining access conditions and evidence, and is **frozen** for the primary ranking (no tier switching inside scenarios). All admissible routes are kept in the release data; a best-eligible-route ranking and route-selection sensitivity are published alongside the fixed-route ranking. **Full utilisation** means the API-equivalent value achievable when every simultaneous limit window (e.g. 5-hour and weekly) is saturated over the fee period: the minimum across binding windows, not the largest single cap. The fee is the amount paid for the measured period (no annual-discount conversion). **Token mix**: where category-specific multiples exist (input, cache read/write, reasoning, output), the route multiple is M = (Σ_k t_k / m_k)⁻¹ with t_k the category shares of the model's AA cost; otherwise the measurement's category mix is compared with AA's: L1 distance on category shares > 0.30 flags the route "mix-unmatched" (shown, not silently trusted). API-fallback rows are shown but excluded from Plan winner, frontier and threshold claims.
- **SWE cost companion (diagnostic only, O14)**: c_SWE from published SWE per-task costs; flagged when its ratio to basket cost deviates > 50% from the cohort median. Priced-mix coverage (share of quality weight whose leaves are priced in the basket) is published each release.
- **Admission rule for the official Plan ranking (owner decision)**: a measured route enters only via a controlled saturation measurement with receipts (e.g. SemiAnalysis) or ≥ 2 independent end-user reports concordant within ±20%. Single-source routes are diagnostics and cannot earn "recommended". Owner-named transfers (O4/O7) remain labelled assumptions. Each multiple records source count and sampling basis (power users who saturate plans are over-represented). Independence = distinct observers, measurement periods at least 7 days apart and no shared upstream source; concordant reports are pooled by geometric mean, concordance = max pairwise deviation ≤ 20% of the pooled value; step-based meter readings are preferred over self-declared totals. Where SemiAnalysis publishes a per-(plan, model) measurement for a model, it replaces any owner-named transfer for that model.
- **Quota schema**: the registry stores each plan's limit-schema version (windows such as 5-hour and weekly, shared pools across surfaces), how reset balances are treated (counted only if a measurement shows them spendable on the measured workload) and fee decomposition: the **primary multiple uses gross cash**: M = eligible API-priced usage delivered ÷ (subscription cash fee + any cash required for that usage); usage funded by credits bundled into the fee is counted once in the numerator; separately purchased usage is excluded unless its payment is in the denominator; the denominator must be positive and reconcile to receipts. Net-of-credit accounting is a diagnostic only. Each route publishes cash fee, additional cash, included credits and whether consumed, eligible API-valued consumption, and excluded consumption with its funding source. Pool scope is recorded per window (all-models vs per-model, e.g. Opus-only weekly limits); an owner-named transfer between models in different pool scopes carries a directional bias bound in the identification layer. A schema change triggers the 30-day soft expiry.
- **Value Multiple** = API-priced usage a plan delivers over a stated fee period ÷ fee for that period. Each multiple records fee period, workload, model/effort, token categories (input, cache read/write, reasoning, output), valuation price list and date, shared usage pools, whether capacity was exhausted and which rate-limit windows bound it. Where public token receipts exist, the numerator is repriced on the same price list as AA cost; otherwise the original valuation basis is kept and flagged. No extrapolation of short bursts to a billing period unless the controlled measurement establishes it. Evidence rules unchanged (no provider marketing quotas; end-user API-priced reports or SemiAnalysis controlled measurements).
- **Assumptions**: only the owner-named model-to-model transfers (Opus 5.5's measured Claude multiples to other Claude models; common GPT multiple; MiMo 1.5×) stay in the official Plan ranking, labelled, with donor measurement identified. Any other mismatch (effort, surface, workload, price basis) is "unmatched" and excluded from the official Plan ranking. A measured-only Plan view is published.
- **Scoring with frozen, per-basis anchors** in total-USD units: S_C = 100 × clip((ln c_H − ln c)/(ln c_H − ln c_L), 0, 1); anchors are re-derived for the basket unit from a frozen reference cohort's 1st/99th percentiles and versioned (API and Plan separately). Dollars always displayed; unclipped values kept. Release gate: fail if ≥ 2 rows clip on either basis.

## Quality (75% of the value score)

Normalisation on raw magnitudes with frozen, versioned anchors: z = 100 × clip((x − a_low)/(a_high − a_low), 0, 1); a_low = chance/baseline level, a_high = documented ceiling where one exists, else 100%; rounded inputs treated as rounding ranges; unclipped z kept in the data release. Each release publishes **effective weights** (w_i × SD(z_i), normalised), the leaf rank-correlation matrix and the **share of quality weight by data source** (today ≈75% AA-run: DeepSWE, FrontierCode, GDPval, AutomationBench, Omniscience, LCR, HLE, GPQA, SciCode, CritPt; ≈25% independent: Bug Hunt, Terminal-Bench, LiveBench). A group whose effective weight drifts more than ±50% from nominal is flagged; a leaf with cohort SD(z) < 3 points is marked **non-discriminating** (still scored and reported, excluded from drift-flag counting). AA Intelligence Index and output speed are diagnostics, not quality.

- **One quality vector serves both bases (owner decision)**; harness differences (e.g. Bug Hunt run in vendor CLIs) are disclosed as a limitation.
- Missing data: quality renormalised over a row's available leaves (fixed leaf weights; no imputation). **Coverage** = observed share of total quality weight. A row is **provisional** (still ranked, per cohort policy, but flagged and excluded from "unique cheapest" claims) unless coverage ≥ 70%, at least 2 SWE leaves are observed, observed SWE weight ≥ 40% of quality, and no leaf with nominal weight ≥ 20% (DeepSWE) is missing. Identification bounds L (missing at 0) and U (missing at 100) are the formal interval; a separately labelled **sensitivity band** sets missing leaves to the cohort's observed min/max for that leaf (sensitivity analysis, not imputation). A row without a cost gets no value score.

## Attempts reconciliation

The manifest records separately, per leaf: independent evaluation repetitions (e.g. DeepSWE pass@1 averaged over 3 repetitions — affects precision only) and deployment attempt policy (attempts permitted per task, retry/best-of-k/selection/verifier policy) with the cost coverage of those attempts. Only a genuine deployment-policy mismatch between the quality figure and the priced attempts is reconciled (as a bias bound in the identification layer); repetitions are not a bias.

## Uncertainty (three separate layers, one scenario engine)

A joint scenario simulation (N = 10,000) is the single engine. **Cost is drawn too**: price basis (first-party list vs cross-provider median), cache-hit rate within its manifest range, and token-use variance (clustered resampling where per-task/per-run costs are published, otherwise a declared parametric range); cost and AA-run leaf values are coupled only as the Dependence rule allows (paired public observations; otherwise dependence stress branches). Each scenario also draws leaf values from their measurement intervals, multiples from their ranges, identification bounds for missing leaves, a **hierarchical** weight draw that preserves the nominal means — group weights ~ Dirichlet(100 × (0.60, 0.20, 0.10, 0.10)), within-group weights ~ Dirichlet(50 × nominal within-group proportions); intent is modest perturbation around 60/20/10/10, not alternative buyer preferences (realised per-leaf CV published), and (as named stress-test branches, not random events) source removal, the GDPval mapping alternative and the owner-authorised transfer on/off; shared multiples and price lists are drawn once per scenario. Strata are cumulative and computable from the registry: **S0 measurement** = renormalised composite over observed leaves with measurement and cost draws; **S1** = S0 + identification draws (missing-leaf bounds, attempts bias, Plan transport and transfer bounds); **S2 core branch** = S1 + hierarchical weight draws (transfers off, all sources, linear GDPval map); other S2 branches (transfers on, logistic GDPval, each source removal) are published separately with explicit reasons when unevaluable. Draw kernels are declared per input: uniform on rounding ranges, clustered resampling on raw runs, triangular on observed-run ranges otherwise. Results are published **per stratum** (S0, S1, S2; transfers on/off; leave-AA-out), never averaged into one figure, as scenario shares (e.g. share of scenarios with rank ≤ 3, on the frontier, qualifying at a bar), labelled as scenario frequencies, not probabilities. A "unique cheapest" / scenario-supported leader is named only when the **simultaneous** leadership event (Normative definitions) holds in ≥ 90% of scenarios. Layers:

- **Measurement**: published intervals, rounding ranges, task- or run-clustered resampling where per-task/per-run data exist.
- **Identification**: missing-data bounds; Plan transport (M_W given the measured multiple) and owner-named transfer bounds. **Plan uncertainty split (E12)**: each route stores a measurement object (receipts, meter, repeat-measurement uncertainty of M_observed; drawn in S0) and a separate transport object (W hash, quota schema, mechanism, transport bounds; drawn from S1). Where public evidence cannot separate them the route is labelled "measurement and transport not separable" and its S0 result is not described as target-workload support.
- **Specification**: alternative leaf weights, leave-one-benchmark-out, leave-one-source-out (**leave-AA-out is a headline robustness column**), cost-weight slider, owner-authorised transfer on/off.
- **Workload cross-check (mandatory, diagnostic)**: per benchmark b (DeepSWE; Terminal-Bench 4.0), a common exact-configuration panel I_b; d_ib = mean cost per attempted task ÷ resolved fraction (∞ when zero, with uncertainty shown). Kendall τ-b between total-cost rank and d_ib rank within I_b, separately per benchmark (never pooled across benchmarks); task-cluster resampling where task-level results exist, otherwise a model-row bootstrap labelled as matched-set sensitivity; below n = 8 rows in I_b the statistic is suppressed. Low agreement puts a warning on the headline; it does not block the label.
Shared dependencies move together (one multiple, price update or benchmark version affects all its rows jointly). Robust pairwise orderings are published only when they survive the declared joint scenarios; overlap is not treated as transitive tie groups.

## Normative definitions (executable specification)

- **Coverage and scores.** p_i = Σ_{b∈O_i} w_b. Displayed observed-only quality Q̄_i = Σ_{b∈O_i} w_b z_ib / p_i. Full-composite score Q_i(θ) = Σ_{b∈O_i} w_b z_ib(θ) + Σ_{b∉O_i} w_b u_ib, u_ib ∈ [0,100]; so Q_i^L = p_i Q̄_i and Q_i^U = p_i Q̄_i + 100(1 − p_i), extended by measurement intervals in original-weight space. S0 uses Q̄_i; S1/S2 always use the full-composite equation. Any sampling law for wholly missing leaves is a declared scenario convention (with one published alternative), never evidence; formal bounds are distribution-free.
- **Pairwise certificate (governing; supersedes the full-composite form below for certification).** For pair (i, j): B_ij = leaves observed for both; p_ij = Σ_{b∈B_ij} w_b ≥ 0.70 with SWE gates; **pair SWE gate (E16)**: B_ij contains ≥ 2 SWE leaves and Σ_{b∈B_ij∩SWE} w_b ≥ 0.40 (the row gates applied to common support; a pair failing it is unevaluable, not loosened); Q_i^(ij)(θ) = Σ_{b∈B_ij} w_b z_ib(θ) / p_ij (renormalised within the pair, preserving 25:75 on retained evidence; editor decision E8; 1/p_ij published); **pairwise cost term (E14)**: Δ_ij(θ) = 0.25 κ_W [ln C_j,W(θ) − ln C_i,W(θ)] + 0.75[Q_i^(ij)(θ) − Q_j^(ij)(θ)], with κ_W = 100 / ln(c_H,W / c_L,W) fixed per release and basis from the full-workload frozen anchors and no clipping, so every edge uses the same dollar-to-quality exchange rate; both costs must be on the full workload W (a subset-cost row, O17, has no certifiable edges). Directed edge i → j certified iff the pair gates, cost-shape and Plan-identification checks pass and min_{θ∈Θ_ij} Δ_ij(θ) > 0, where Θ_ij holds uncertainty for retained evidence and costs only (no values for dropped leaves). **Margin-based validity (E11)**: every retained input, whatever its weight, enters Θ_ij either through a documented admissible constraint or at the worst case its documented score domain allows (e.g. [0,100] for z, the recorded cost range); no retained uncertainty is omitted because its weight is small. An input with neither a constraint nor a defensible domain makes the pair **unevaluable**. The 5% unidentified-input rule is kept only as a disclosure trigger. S0 scenario support uses exactly Δ_ij. A **directed certification matrix** (retained weight, dropped leaves, margin per pair) is published; each ordered pair has one of four states — certified win, certified loss, evaluated but unresolved, unevaluable. **Certified(i; J) ⇔ edge i → j is a certified win for every j ∈ J∖{i}** (outgoing edges; absence of a certified loss is not enough). "Undefeated" (no incoming certified loss) is a graph diagnostic only and never a certificate. **Simultaneous scenario leadership**: L_i(s) = 1 iff Δ_ij(s) > 0 for every j ∈ J∖{i} in the same scenario s; scenario-supported leadership requires mean_s L_i(s) ≥ 0.90; a comparison undefined in s makes L_i unevaluable for that scope (never a win); pairwise frequencies are published separately and never multiplied or combined into L_i. Cycles, no certified candidate, and a certified candidate different from the displayed-score leader are all allowed outcomes. Per ordered pair the release publishes a machine-readable record: comparison-set id and scope, common-support leaves and retained weight, gate results (failed vs unidentified), admissible-set definition and minimum margin, four-state outcome, S0 pairwise frequency. Full-composite missing-data bounds are used only for frontier and threshold outputs.
- **Certification set Θ_cert (editor decision; used for frontier/threshold outputs).** Fixed: nominal weights, primary price rule, frozen route, linear GDPval map. Variable: inputs whose certificate_role is "included constraint" — measurement intervals, missing-leaf bounds, the **AA-mix** multiple range, deployment-policy bias bounds. Every uncertain scored input carries a certificate_role (included constraint / specification-only stress / unidentified quantity) with rationale; missing repeatability evidence never becomes zero uncertainty (it is an unidentified quantity or a labelled stress allowance). Tests: widening an admissible set cannot create a certificate; removing competitor evidence cannot strengthen an unrestricted certificate.
- **Plan measurement vs transport.** M_observed = eligible API-valued measured consumption ÷ gross cash paid (the measured workload). **M_W** ∈ [L, U] = the multiple for the scored workload W (O15 basket; M_W in earlier drafts), bound to W's hash, the price-list version and the quota-schema version; transport evidence for the old AA-suite workload qualifies only if its capacity model or conservative bound also covers W, with its identification mechanism recorded: direct compatible-workload measurement / publicly evidenced additive capacity model / evidenced transport bound / unidentified. The Plan headline score uses M_W where identified, else M_observed (owner-named transfers as labelled assumptions). **Certification uses only an identified M_W**; otherwise target-mix Plan cost is "unidentified" and that row cannot be certified (it stays in the table and ranking). Cohort spread or arbitrary bands never convert "unidentified" into a bound.
- **Certificate scope.** Each certificate publishes its comparison set and exclusions. Two labels: "certified among directly evidenced routes" and "certified across all eligible native Plan routes"; the latter requires a valid positive margin against every eligible competitor, including assumption-dependent ones via conservative bounds; an undefined comparison is not a positive margin. Per row and basis the release publishes: displayed score and estimand, target-workload cost identification status, certification eligibility and failed gates, comparison set, unevaluable competitors with reasons. Shared constraints: prices, donor measurements, task/run observations, quota pools. V_i(θ) = 0.25 S_C(c_i(θ)) + 0.75 Q_i(θ); certified iff min_{θ∈Θ_cert}[V_i(θ) − V_j(θ)] > 0 for every competitor j, plus the eligibility gates. Wording: "interval-certified under the declared evidence bounds", not a confidence guarantee. Specification robustness (weights, price policy, GDPval map) is published separately. With transfers off, a Plan route that depends entirely on an owner-authorised transfer is **unevaluable** for certification (never silently replaced by API cost).
- **Certified cheapest above a bar.** Robust qualification: min_θ[Q_i(θ) − Q_r(θ)] ≥ 0. For each competitor j that can qualify: max over {θ: Q_j(θ) ≥ Q_r(θ)} of [c_i(θ) − c_j(θ)] < 0. Labels: "interval-certified cheapest", "scenario-supported cheapest" (simultaneous event in ≥90% of scenarios), "candidate set".
- **Workday-feasible Plan multiple (diagnostic, E15).** Owner decision O3 keeps full utilisation as the scored estimand. Where the quota schema is evidenced, the same time-indexed LP is also solved with consumption allowed only in a pre-registered 40-hour week (8 h × 5 days); M_workday and the ratio M_workday / M_full are published per route as a diagnostic, never scored.
- **Harness stress branch (E19).** Bug Hunt runs on vendor CLIs while DeepSWE and Terminal-Bench run in controlled harnesses. An S2 specification-stress branch applies a harness-mismatch band to Bug Hunt estimated from same-model cross-agent spreads on the tbench.ai leaderboard, pre-registered in the registry; it is published as stress, not used in certification.
- **Robustness outputs (E13).** Separate, named columns: (1) displayed-score rank sensitivity (scalar displayed score); (2) full-composite scenario-rank sensitivity (scalar Q_i(θ) composite); (3) pairwise recommendation robustness — per branch, changes in certified-win edges, unresolved and unevaluable comparisons, and whether the candidate still beats the whole declared set; (4) branch evaluability and exclusion reasons, with retained quality weight and gates shown before any rank statistic. Numerical rank change is computed only for (1) and (2) within evaluable branches; an unevaluable branch gets no rank. "S2 maximum rank change" refers to (1).
- **Cohort rule (executable).** F(c) = best rounded Index among rendered-frontier configurations with cost ≤ c; a family is near-frontier when a plotted configuration's rounded Index ≥ F(c) − 3; ties by lower cost then name.
- **Omniscience counts.** From AA counts (c correct, p partial, i incorrect, a not attempted): A = 100c/(c+p+i+a); AA's hallucination rate = i/(i+p+a), so N = 100[1 − i/(i+p+a)] (N = 100 when i+p+a = 0); z = (2A + N)/3. Test vector: c=60, p=0, i=10, a=30 → A=60, N=75, z=65. Reconstructed values are tested against AA's published fields.
- **Plan capacity under multiple pools.** Where public controlled measurements establish additive consumption per budget w (a_wk per token of category k, spendable capacity B_w over the fee period) and x_k = tokens of category k per AA-suite-equivalent workload: λ_w = B_w / Σ_k a_wk x_k, λ = min_w λ_w, M = λ × C_API / F_gross, where B_w must be attainable over the fee period: billing boundaries, reset phase (e.g. account-specific weekly reset times), carryover and evidenced throughput limits are recorded, and where windows and billing periods misalign capacity is computed by a small time-indexed linear program (maximise Σ_t y_t subject to Σ_{t∈W} a_wt y_t ≤ B_W for each evidenced window), or a conservative bound when scheduling feasibility is not established. This λ / time-indexed LP is the **only governing Plan formula** (the earlier harmonic expression is non-governing; release test: loosening a non-binding 5-hour cap cannot change a plan whose weekly cap binds). Harmonic-style category combination is used only where a common additive budget is established; otherwise the observed-mix multiple is kept with its mix-unmatched flag and target-mix capacity is reported as unidentified. Provider quota descriptions may document structure but never supply the numerator.
- **Matched-cost blocker (API cost-shape check).** Reference cost is C_i,W (basket), never the legacy Index total (C_i^Index, diagnostic only). Certification fails if **either** test fails: (a) pairwise reversal — for candidate i and any eligible rival j, C^match orders them opposite to C_W with both intervals separated (overlapping intervals = no reversal; ties = no reversal); (b) the ratio/rank rule below. It tests the API cost shape only; it is not reused as a Plan check (dividing both sides by one multiple leaves the ratio unchanged). The Plan workload check is the M_W identification status above; when unidentified the release says "API cost-shape check passed; Plan workload check unidentified". The priced-leaf panel B may include any leaf with exact-variant per-task cost — AA per-evaluation costs, DeepSWE (published mean tokens × the same price list), FrontierCode, Terminal-Bench — not only AA-index leaves (editor decision). Before release, a **certification-feasibility matrix** (row × priced leaf: exact-variant and stack compatibility, available cost, resulting common-panel weight; maximum feasible weight per row; selected panel; rows outside it; whether any comparison is certifiable) is published, with the panel-selection rule fixed before ranks are examined. One published common model panel I and priced-leaf panel B per comparison; w'_b = w_b / Σ_{h∈B} w_h; C_i^match = Σ_{b∈B} w'_b c_ib, with c_ib = cost per attempted task (evaluation repetitions divided out, deployment retries included), counting **model API token charges only** (input, cache read/write, reasoning, output × the primary price list; sandbox, environment-setup and verifier compute excluded; E17); where a source cannot separate retry or harness tokens the leaf is not priced for that row. R_i = (C_i^match / C_i,W) / median_{j∈I}(C_j^match / C_j,W); flag iff R_i > 1.5 or R_i < 1/1.5 **and** rank on C^match differs from rank on C_W by > 3 places, both ranks computed on I. Minimum priced coverage Σ_{b∈B} w_b ≥ 40% of quality weight (editor decision); below it, or when a row lacks the panel, the result is "cross-check unidentified" and the row cannot be certified.
- **Dependence.** Every uncertain input records interval meaning (rounding / published CI / observed range / identification bound / analyst stress range), sampling law with justification, and dependency identifier with supporting paired evidence. Costs and outcomes are resampled jointly only when paired task/run observations are public; otherwise shared factors (same price list) are kept and independent / positive / negative dependence stress branches are published; certification uses conservative joint bounds.
- **Bug Hunt estimand.** Each complete run's pooled fixed/105 is the measurement; repository differences are a repository sensitivity, not repeats. For n = 1 rows, published evidence uncertainty is separated from a labelled repeatability stress allowance (cohort spread is not used as exact-variant evidence).
- **Provenance.** Per leaf: dataset author, execution organisation, harness, grader. Evaluator-independent quality weight and task-overlap exposure are reported separately (e.g. Terminal-Bench is independently executed but its task family is also in AA's priced suite).
- **Versioning.** Methodology version, evidence/benchmark version and release snapshot are separate. A new observed price under an unchanged price rule is a data refresh; changing a rule is a methodology migration; a benchmark-version change triggers a comparability review with dual-run where feasible.
- **Release tests (additional).** Omniscience vector above; aggregate/component exclusivity (an exactly reconciled decomposition leaves basket cost unchanged); repetition invariance (averaging extra evaluation repetitions does not multiply workload cost); workload migration changes W's hash and invalidates unreviewed Plan transport; certificate isolation (changing a leaf dropped from B_ij cannot change that pair's certificate); a synthetic three-model cycle yields no global certificate; two rows whose comparison is unevaluable produce no certificate against each other even with no certified loss; a candidate that wins against different rivals in different scenarios gets L_i computed per scenario, not from marginal frequencies; adding a small-weight retained input with only a domain bound cannot create a certificate; every blocker reads C_W, never the Index diagnostic.
- **Release tests.** Shared price changes cancel where numerator and AA cost share a price basis; restoring a missing leaf moves correctly from S0 to S1; transfers-off never silently becomes API fallback in a certificate; a tighter quota cannot increase computed capacity; adding an unrelated row cannot change common-panel diagnostics except via declared cohort-dependent quantities; the reference configuration always qualifies against itself.

## Governance

Evidence classes (measured / claim / estimate / assumption); provider claims never overwrite independent measurements. Plan evidence carries a 30-day soft expiry with change detection (a plan is flagged "possibly superseded" when scoped change detection — pricing tables, rate-limit documentation sections and model-availability matrices, not full-page diffs — shows a change since measurement, or when ≥ 2 independent end-user reports (O11 independence) describe an undocumented limit change; E18) and a 90-day hard expiry; after a further 30-day grace an expired route is **demoted to diagnostic-only** and the model falls back to API cost (flagged) in the official Plan ranking (owner decision). Each row stores its AA price-list date; score changes are decomposed into price change vs token-use change vs method vs cohort. The scenario engine uses a published RNG seed and draw order per release, and per-stratum outputs are released as data files. Plan rows publish fee F and full-utilisation capacity M × F in API-priced USD so light users can judge fit. Freshness: AA cost snapshot and price list max age 45 days, with change-triggered refresh; monthly cadence. Each row publishes its own effective weights (per-row renormalisation changes them) and SD(S_C) with a cost-vs-quality variance decomposition of its value score. Release gates (on failure the release is **held** — fix the data or re-anchor as a versioned migration with a dual-run comparison; owner decision): clip rate > 10%, an unversioned AA chart/field change, or any score swing > 5 points without an attributed cause. The registry records, per row: chart field name; total cost and cost per task side by side; repeat inclusion; cache-hit-rate assumption and date; price rule (first-party list vs cross-provider median for open weights); fallback-token treatment; Elo anchor identity (e.g. GDPval-AA scale pinned to a named reference model) and judge-panel/grader versions for rubric-graded leaves. A change of rule in any of these is a methodology migration; a new value under an unchanged rule is a data refresh (see Versioning). Score moves are decomposed into price, cache rate, token use, method and cohort. Leave-AA-out is reported as "not identifiable under the coverage rule" when the remaining identified quality weight is under 40% (the case today, with ≈25% independent weight), and is excluded from any denominator.

## Known limitations

Full-utilisation Plan cost overstates value for light users; AA cost uses AA's token mix; Bug Hunt covers two repositories; DeepSWE/Bug Hunt/TB measure model+harness stacks; suite is primarily English text.
