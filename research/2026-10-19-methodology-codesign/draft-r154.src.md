# ValueRank methodology — draft r154

*Where prose and the Normative definitions differ, the Normative definitions govern. Every rule tagged with an owner (O) or editor (E) number is normative wherever it appears; between two tagged rules an owner decision governs an editor decision, and a rule that amends another governs it (E191); an editor record never amends or overrides an owner decision; between two editor rules where neither amends the other, the later-numbered record governs, and finding such a conflict is a defect corrected in the next revision. Each E number names one decision record; a record that holds several rules labels them, and an amendment cites the record it amends. The valuation outcome (4) once tagged E198 is E202.*

## Objective and claim scope

AA's Pareto frontier of Intelligence Index vs. total USD cost to run its Intelligence Index does not answer the question ValueRank exists for: **which frontier AI model is actually lowest cost for the value it delivers in practice**, once (a) subscription-plan economics are considered and (b) benchmarks geared to real software-engineering work are weighed alongside general capability. ValueRank serves two buyers, ranked separately: **API buyers** (pay per token, incl. third-party agents) and **Plan buyers** (provider subscription apps/CLIs: Claude Code, Codex, ChatGPT, SuperGrok…).

Claim scope: "value among the configurations ranked in one ranking (configurations AA plots on, or within the near gap of, its rendered frontier that have that ranking's full benchmark set; see Cohort), under that ranking's published benchmark mix and evidence". ValueRank publishes two rankings (owner decision O53): the **max-effort ranking**, which leads (site and README default, O54), and the **AI Coding Daily ranking**. Each has its own leaf set and weights (O55), anchors, bars, scenario run, basket admission and diagnostics (E253, E254); values, ranks and claims compare within one ranking only, never across the two. No configuration is ranked for its evidence alone outside the frontier and near-frontier cohort (O51). Every ranked row is a **configuration** (model version, effort, fallback, route), with a compact configuration ID and an expandable per-leaf execution manifest; tables and claims say "configuration", not "model" (E78). Not a market-wide optimum across all configurations and workloads.

## Normative definitions (executable specification)

- **Coverage and scores.** Every ranking-specific definition below (scores, anchors, bars, intervals, scenario labels) is evaluated within one ranking, on that ranking's leaf table, anchors, bars and cohort rows (E253); the cohort rule and the leaf formulas are common to both. Leaf weights w_b are percent points summing to 100, and z and u are on 0–100. p_i = Σ_{b∈O_i} w_b / 100. Displayed observed-only quality Q̄_i = Σ_{b∈O_i} w_b z_ib / (100·p_i). Full-composite score Q_i(θ) = (Σ_{b∈O_i} w_b z_ib(θ) + Σ_{b∉O_i} w_b u_ib) / 100, u_ib ∈ [0,100] (fixture: leaves worth 30 points missing, every other leaf at 60 → p_i = 0.70, Q̄_i = 60, Q_i ∈ [42, 72]). **Formal bounds** (E35): Q_i^L = min_{θ∈Θ} Q_i(θ) and Q_i^U = max_{θ∈Θ} Q_i(θ) over the joint admissible set Θ below (measurement intervals of observed leaves and u_ib ∈ [0,100] for missing leaves); "missing at 0/100 at the point estimate" is not the bound. S0 uses Q̄_i; S1/S2 use the full-composite equation. - **Interval decision procedure (E40, amended by E43).** Interval labels are decided by deterministic, decision-specific feasibility problems over Θ, never from scenario draws. Primitive domains have a box enclosure (per-row input boxes and a box of declared shared factors, e.g. a common price list or a donor multiple shared by several rows); Θ itself is the constrained subset defined by E73, and a product-box representation may replace it only under a decision-specific equivalence proof (E169). **Constrained evidence model (E73)**: the primitive-variable constraint graph Θ = {v : ℓ ≤ v ≤ u, h(v) = 0, g(v) ≤ 0} is authoritative; costs, quality, capacities and multiples are derived quantities of v (an identity such as API-valued capacity = λ × C_API survives uncertainty propagation). A box reduction is used only with a decision-specific equivalence proof; otherwise the box is an outer enclosure for pruning, and every witness is certified against the original constraints (release fixture: an enclosing box containing a favourable state the original constraints exclude must never return a certified possible membership). **Separability condition (E89)**: with no shared factor **and no row-local coupling** — each row's C and Q depend on disjoint primitives with no joint constraint, so the row's feasible set is the product of its C and Q ranges — each label is decided exactly by monotone extremes (Q is linear in leaf values; basket cost is monotone in component costs; each row's inputs move only its own C and Q): e.g. possible-frontier membership of i is established by setting i to its best corner and every j to its worst. A row-local primitive or constraint that enters both C_i and Q_i is a coupled variable and is branched over like a shared factor; a constraint class the solver does not support returns unresolved (release test: i with C_i = 1 + t, Q_i = t, t ∈ [0, 1]; j with C = 1, Q = 0.5; k with C = 1.5, Q = 1 — i is dominated for every t although its box corner (1, 1) is undominated, so the solver must return disproved and never a possible membership). In v1 every row's C and Q come from distinct published records, so the condition holds and is asserted per release; the one cross-row factor the Plan basis can create, a donor multiple shared by several configurations, is checked by the build: when two configurations among a decision's Plan candidates rest on one donor multiple identified only as a range, the Plan interval outputs are unresolved, with the shared donor named, and never computed by corners (E273). With shared factors or row-local coupling, labels are decided by **certified interval branch-and-bound** over the shared-factor box: on each sub-box, interval bounds either certify the condition for every point (witness), refute it for every point (prune), or the sub-box is split, up to a published depth; a sub-box still undecided at that depth returns **unresolved**. Endpoint search alone is not sufficient (release test: competitors with Q_j = 2t and Q_k = 2(1 − t), C_j = C_k = 0, and i with C_i = 1, Q_i = 1.2: i is a possible-frontier member via the interior witness t = 0.5). Possible-frontier membership solves, in one common θ, for every j ≠ i: C_j(θ) > C_i(θ) ∨ Q_j(θ) < Q_i(θ) ∨ [C_j(θ) = C_i(θ) ∧ Q_j(θ) = Q_i(θ)]; definite membership is disproved by one θ and one dominating j; strict inequalities are decided exactly, never by tolerance alone. Every returned witness is re-checked against the original equations and shared constraints. The monotone-corner shortcut is used only for decisions with a documented corner-reduction proof; dependencies are compiled from the complete decision equations, so a varying reference quality Q_r is a shared variable for every qualification condition even when all row inputs are independent (E50; a frozen bar level is a constant and adds no shared variable, but the rule binds any registered varying reference): bar decisions partition at qualification breakpoints (exact enumeration for affine one-dimensional thresholds) or use the certified branch-and-bound (regression test: i with C = 1, Q = 5; j with C = 0, Q = 4; Q_r ∈ [0, 10] — i ∈ K_r via the interior witness Q_r = 4.5, which neither endpoint shows). Feasible witnesses and infeasibility certificates have separate proof obligations, and numerical bounds may not discard feasible points through floating-point error. Statuses: certified / disproved / unresolved / unevaluable, with solver status, depth and witness (or counterexample) stored; an unresolved solve is never shown as certified. **Certification grammar (E108)**: each decision is compiled into (1) primitive domains and the original constraints, (2) a reduced problem obtained only by documented, equivalence-preserving substitutions (definitional equalities are eliminated by substitution wherever possible) and (3) a certificate checked independently against the original problem. Supported v1 classes: boxes, affine constraints decided in exact rational arithmetic on the published decimal inputs, separable monotone transforms and the documented corner reductions; a nonlinear equality is supported only with a validated existence certificate (e.g. a sign change of a continuous univariate function evaluated exactly at rational endpoints); every other class returns unresolved, and a small numerical residual is never a feasibility certificate (fixtures: x² = 2 with x ∈ [1, 2] is certified feasible without a rational witness; x² = 2 with x ∈ [1, 1.4] is certified infeasible; an approximate point with residual 10⁻⁶ certifies nothing). **Feasibility prerequisite (E79)**: before any decision, the decision's full constraint component (all connected shared variables and identities) must have a certified feasible witness checked against the original constraints; certified infeasible → "inconsistent evidence", no frontier or bar labels for the affected output, release-blocking for that output with the conflicting records listed; feasibility unresolved → "unresolved", no confirmed or definite label (fixtures: individually valid intervals whose shared identity has an empty intersection; a feasible outer box whose original constrained set is empty — neither may produce a confirmed, definite or certified-possible result).
