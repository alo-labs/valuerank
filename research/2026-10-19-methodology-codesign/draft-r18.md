# ValueRank methodology — draft r18

*Where prose and the Normative definitions differ, the Normative definitions govern.*

*r18 replaces the generic extreme-point search with decision-specific solver contracts, adds completeness statuses, a workload-demand evidence object and the possible-cheapest set (after reviewer 18). r17 added executable eligibility, scope and decision procedures for the interval outputs. r16 change summary: the owner dropped the "recommended" label and every rule that existed only to award it (pairwise certification, the frozen contest, the matched-workload value blocker; owner decision O22). MMMU-Pro leaves the cost basket (O23); both priced Terminal-Bench executions stay (O24). Frontier and cheapest-above-a-bar outputs keep their interval logic.*

## Objective and claim scope

AA's Pareto frontier of Intelligence Index vs. total USD cost to run its Intelligence Index does not answer the question ValueRank exists for: **which frontier AI model is actually lowest cost for the value it delivers in practice**, once (a) subscription-plan economics are considered and (b) benchmarks geared to real software-engineering work are weighed alongside general capability. ValueRank serves two buyers, ranked separately: **API buyers** (pay per token, incl. third-party agents) and **Plan buyers** (provider subscription apps/CLIs: Claude Code, Codex, ChatGPT, SuperGrok…).

Claim scope: "value among AA-selected frontier and near-frontier configurations, under the published benchmark mix and evidence". Not a market-wide optimum across all configurations and workloads.

## Outputs

1. **Headline ranking** per basis by value score = 0.25 × cost score + 0.75 × quality score (owner decisions O2, cost weight 25%). There is **no "recommended" label** (O22). Uncertainty is shown beside each rank as per-stratum scenario shares (Uncertainty). Two named quantities are printed per basis: (a) the **anchor exchange rate** — in the unclipped region a cost doubling changes value by −100·β·ln2 / ln(c_H/c_L) points and is offset by +100·β·ln2 / ((1−β)·ln(c_H/c_L)) quality points, β = 0.25, from the active anchor version; (b) the **within-cohort influence** 0.25·SD(S_C) vs 0.75·SD(S_Q). A release is flagged (not held) when cost's share of within-cohort influence, 0.25·SD(S_C) / (0.25·SD(S_C) + 0.75·SD(S_Q)), is under 10%; β never changes. Cost-weight slider results appear in the main table. No quality floor (O8); provisional rows are flagged.
2. **Cost–quality frontier** per basis, bound-aware: "definite" vs "possible" frontier members (Normative definitions).
3. **Cheapest above a quality bar**: each release pins named reference configurations (identity frozen at release, e.g. the model that was the median definite-frontier model at release time). Qualification and cheapest labels follow only the joint definitions in Normative definitions ("Cheapest above a bar").
4. **Diagnostics**: USD per AA Index point, AA Intelligence Index, total Index cost, AA tokens used to run the suite, output speed, raw values, evidence grades, measured-only Plan view, matched-cost and workload cross-checks, SWE cost companion, target-basket readiness.

## Source contract (versioned registry)

Machine-readable registry per release: AA chart identity, filters and snapshot timestamp (current: "Intelligence Index vs. Cost to Run Artificial Analysis Intelligence Index", x-axis "Cost to Run Intelligence Index (USD)", unit "USD to run all Intelligence Index evaluations", captured 2026-10-17); cost field, unit and accounting (as AA defines it, including AA's cache-pricing protocol and its date); per model: version, effort, fallback, serving route and per-benchmark stack; per benchmark: version, raw metric, **pinned source field**, population, attempts, aggregation, source revision/commit, observation and retrieval dates; explicit missingness reason (not evaluated / incompatible variant / no public evidence / withdrawn). Pinned fields today (E31): AutomationBench-AA = AA field `automationBenchPartialScore` (the value AA's Index uses); Omniscience = AA `omniscienceBreakdown.accuracy` and `omniscienceBreakdown.hallucinationRate`; GPQA Diamond = AA `gpqa` (legacy, not in Index v4.3.2; AA evaluation page /evaluations/gpqa-diamond); Coding Agent Index cost = AA "Total Cost Across the Coding Agent Index" (`sums.costUsd`) with per-task `mean.costUsd`; Bug Hunt = owner-published run results and means. A change of AA chart or field is a versioned methodology migration, never a silent refresh.

## Cost (25% of the value score)

- **API cost input = SDLC cost basket (owner decision O15, as amended by O23).** C_i,W = Σ over admitted basket components of AA's published cost for the exact configuration. Target basket = the AA evaluations whose tasks are typically part of an end-to-end SDLC and DevOps/IT workflow: **Coding Agent Index** (DeepSWE v1.1, 113 tasks; SWE-Atlas QnA, 124; Terminal-Bench v4, 66), **FrontierCode**, **ITBench-AA**, **AA-Briefcase**, **GDPval-AA**, **GDP.pdf**, **AutomationBench-AA**, **Terminal-Bench 4.0** (AA Index run), **SciCode**, **AA-LCR**. Excluded: HLE, AA-Omniscience, CritPt (knowledge/science recall) and MMMU-Pro (academic multimodal QA; O23).
- **Accounting identities.** AA's total Index cost decomposes exactly into its **ten** evaluations (Σ cost per task × task counts: Briefcase 91, GDPval 220, GDP.pdf 100, AutomationBench 657, Terminal-Bench 66, SciCode 288, LCR 100, HLE 2,158, CritPt 70, Omniscience 6,000; verified to < 0.002% for every row of the 2026-10-17 snapshot). C_W takes the seven SDLC evaluations; C_Index = C_7 + C_HLE + C_Omniscience + C_CritPt is reconciled to AA's chart each release, and that residual never enters C_W. Coding Agent Index cost is AA's published total (`sums.costUsd` = per-task mean cost × the number of tasks with cost telemetry; one deployment-equivalent pass with repeats averaged, consistent with E9); the count of tasks included is stored, and tasks lacking cost telemetry are recorded as missing and the row flagged "partial component", never charged at the mean. Chart-captured totals (FrontierCode, ITBench-AA) are rounded to USD 1 and treated as rounding intervals; AA's "*" mark ("the model or provider declined some tasks on safety grounds") also flags "partial component".
- **Capture status (2026-10-19).** Exact model-and-effort cost: Coding Agent Index 16 of 19 ranked rows (none for GPT-6 Astra (xhigh) — only max is run — or the two MiMo rows), of which 13 have complete cost telemetry (AA total ÷ per-task mean = 303 tasks) and 3 are partial (Gemini 4 Argon: 302 tasks priced; GPT-6.1 Sol and Qwen3.8 Max: ratios 301.6 and 301.3 of 303); FrontierCode 11 of 19; ITBench-AA 7 of 19. Under the admission rule only the Coding Agent Index is admissible now; FrontierCode and ITBench-AA are "pending capture".
- **Cost completeness (E37).** Per row and component the registry stores component identity, task-support identity, required / executed / cost-observed task counts, completeness status and exclusion reason. An attempted task with missing telemetry has missing cost (never zero); a measured refusal or early termination keeps its actual cost and outcome; an unexecuted task is recorded as such. CompleteCostEvidence(i, e) ⇔ every required task of e is cost-observed for i. **Completeness status (E47)** per row and component: *confirmed complete* — explicit matching task-level records or counts, or, for an aggregate published as an unrounded total T and unrounded per-task mean μ over a fixed task set of size n, the identity T = n·μ holds to the sources' floating-point precision (relative 10⁻⁹; the mean is AA's average over cost-observed tasks, so n cost-observed tasks of an n-task fixed set is the full support), with per-component attempt counts published; for chart totals, the absence of AA's declined-tasks marker; *completeness unresolved* — rounded or otherwise imprecise fields whose intervals are compatible with n but do not establish it; *confirmed incomplete* — the identity fails at source precision, the source marks declined tasks, or missing telemetry is explicit. Fractional missing-task counts are never inferred. Only confirmed-complete components satisfy CompleteCostEvidence. FullCost(i, W) ⇔ CompleteCostEvidence(i, e) for every admitted e. The **displayed** score uses AA's published totals, with a "partial component (k of n tasks priced)" flag where a component is incomplete; the **interval outputs** require FullCost(i, W) (otherwise the row is unevaluable there).
- **Terminal-Bench (O24).** One task family appears in three executions: the AA Index run (priced), the Coding Agent Index run under vendor agents (priced, inside AA's single total and not separable), and the tbench.ai leaderboard (the quality leaf; not priced). Both priced executions stay in the basket as the owner listed them; the overlap is disclosed.
- **Admission and persistence (E26).** A component is admitted to workload version W when exact-configuration cost exists for every configuration in W's frozen, named **reference panel**, published with W and containing at least two-thirds of the ranked rows at admission; until admitted it is listed as "pending capture". Once admitted, membership is frozen for W. Later missingness (a new cohort row, withdrawn or failed evidence) invokes O17/E10 subset scoring for that row without changing W or its hash; adding cohort rows never invalidates an admission. The target-basket readiness table (E22) is published each release. Total Index cost and USD per Index point remain diagnostics.
- **Workload object W** (versioned, hashed): the set of unique execution components (e, n_e) with frozen task multiplicities, configuration and deployment policy; C_i,W = Σ_e n_e × c_ie, where c_ie is cost per workload task for **one deployment-equivalent pass** (extra evaluation repetitions excluded, matching AA's totals; E9). Aggregates (e.g. the Coding Agent Index total) and their components are mutually exclusive in the accounting tree — an aggregate is either a reconciliation check or a substitute, never additive; a machine-checkable accounting tree is published. Adding or removing a component is a workload migration with an overlap bridge (old vs new basket costs, scores and ranks for configurations evidenced under both) and Plan-transport revalidation.
- **Missing component for a row (O17)**: the row is scored on its available subset, flagged "subset cost — cross-workload ordering not identified", with its cost compared on that same subset, never by summing fewer items against full-basket costs. **Subset calibration contract (E10)**: each subset used is a versioned workload W_S (hashed components and multiplicities) with its own frozen anchor object from the reference configurations evidenced on W_S, built by the same rule; paired full/subset costs, scores, exchange rates and rank differences are published wherever both are evidenced; missing component costs are never filled to build the bridge. The row keeps its owner-required score and table position with that label, and is "unevaluable" for the frontier and bar outputs on W. Release assertion: the scored field is the basket sum, not cost per task, not AA's 7:2:1 blended price, not total Index cost.
- **Matched-cost diagnostic (diagnostic only).** C_i^match = Σ_{b∈B} w'_b P_ib over a published priced-leaf panel B: quality-weighted **complete benchmark passes** (E24), with P_ib = cost of one complete deployment-equivalent pass of leaf b for configuration i (published task count T_b × mean cost per attempted task) and w'_b = w_b / Σ_{h∈B} w_h; model API token charges only (input, cache read/write, reasoning, output × the primary price list; sandbox, environment-setup and verifier compute excluded; E17); where a source cannot separate retry or harness tokens the leaf is not priced for that row; tbench.ai cost columns are never joined. B may include any leaf with exact-variant per-task cost (AA per-evaluation costs, DeepSWE published mean tokens × the same price list, FrontierCode, Terminal-Bench). Published warnings (reference cost C_i,W, never the Index total): (a) pairwise reversal — C^match orders two rows opposite to C_W with both intervals separated (overlap or tie = no reversal); (b) R_i = (C_i^match / C_i,W) / median_{j∈I}(C_j^match / C_j,W) > 1.5 or < 1/1.5 **and** a rank difference on C^match vs C_W of more than 3 places within the common model panel I. Below 40% priced quality weight, or when a row lacks the panel, the cross-check is "unidentified". A feasibility matrix (row × priced leaf: exact-variant and stack compatibility, available cost, panel weight) is published with the panel-selection rule fixed before ranks are examined. Cost per solved task is shown alongside. These warnings test the API cost shape only; on the Plan basis the workload question is the M_W identification status.
- **Plan cost input (full-utilisation effective cost, labelled)** = API cost input ÷ Value Multiple of the selected route. Computed per model–plan **tier**–surface–configuration route (tier and fee are part of route identity and published). The official route is chosen **lexicographically**: identified M_W first, then evidence grade, then the multiple's lower bound (point value where only a point exists), then lower fee; the lower-bound-only choice is published as sensitivity. Route key = plan × limit-schema version × purchase cohort (e.g. grandfathered pricing) × surface × model × effort; page diffs flag but do not clear a route — a new public measurement does; press round-numbers are never multiples. Plan scores without an identified M_W are kept (O16), flagged "workload-unmatched"; the selected route is **frozen** for the primary ranking (no tier switching inside scenarios). All admissible routes are kept in the release data; a best-eligible-route ranking and route-selection sensitivity are published alongside. **Full utilisation** means the API-equivalent value achievable when every simultaneous limit window (e.g. 5-hour and weekly) is saturated over the fee period, as computed by the governing Plan capacity formula. The fee is the amount paid for the measured period (no annual-discount conversion). **Token mix**: where category-specific consumption is evidenced, the multiple comes from the governing Plan capacity formula; otherwise the measurement's category mix is compared with AA's: L1 distance on category shares > 0.30 flags the route "mix-unmatched" (shown, not silently trusted). API-fallback rows are shown but excluded from Plan frontier and bar outputs.
- **SWE cost companion (diagnostic only, O14)**: c_SWE from published SWE per-task costs; flagged when its ratio to basket cost deviates > 50% from the cohort median. Priced-mix coverage (share of quality weight whose leaves are priced in the basket) is published each release.
- **Admission rule for the official Plan ranking (O11)**: a measured route enters only via a controlled saturation measurement with receipts (e.g. SemiAnalysis) or ≥ 2 independent end-user reports concordant within ±20%. Single-source routes are diagnostics. Owner-named transfers (O4/O7) remain labelled assumptions. Each multiple records source count and sampling basis (power users who saturate plans are over-represented). Independence = distinct observers, measurement periods at least 7 days apart and no shared upstream source. **Concordance is checked on the unpooled reports before pooling** (E33): max_k x_k / min_k x_k ≤ 1.20; concordant reports are then pooled by geometric mean; step-based meter readings are preferred over self-declared totals. Where SemiAnalysis publishes a per-(plan, model) measurement for a model, it replaces any owner-named transfer for that model.
- **Quota schema**: the registry stores each plan's limit-schema version: windows (e.g. 5-hour and weekly) with their **semantics** — session-anchored (starts at first use), fixed reset (calendar or account reset time) or sliding — shared pools across surfaces (e.g. one pool for chat and CLI), pool scope per window (all-models vs per-model), model-specific sub-caps within a shared pool and model-specific consumption (burn) coefficients where measured; how reset balances are treated (counted only if a measurement shows them spendable on the measured workload); and fee decomposition: the **primary multiple uses gross cash**: M = eligible API-priced usage delivered ÷ (subscription cash fee + any cash required for that usage); usage funded by credits bundled into the fee is counted once in the numerator; separately purchased usage is excluded unless its payment is in the denominator; the denominator must be positive and reconcile to receipts. Net-of-credit accounting is a diagnostic only. Each route publishes cash fee, additional cash, included credits and whether consumed, eligible API-valued consumption, and excluded consumption with its funding source. An owner-named transfer between models in different pool scopes or with different burn coefficients carries a directional bias bound in the identification layer; a sub-cap or burn coefficient is never borrowed from another model to identify M_W. A schema change triggers the 30-day soft expiry.
- **Value Multiple** = API-priced usage a plan delivers over a stated fee period ÷ fee for that period. Each multiple records fee period, workload, model/effort, token categories (input, cache read/write, reasoning, output), valuation price list and date, shared usage pools, whether capacity was exhausted and which rate-limit windows bound it. Where public token receipts exist, the numerator is repriced on the release price list (the list AA cost uses). **Otherwise M_W is unidentified** (E32): the displayed Plan score keeps the multiple's original valuation basis under O16, flagged "valuation basis differs", and the row is excluded from Plan interval outputs. No extrapolation of short bursts to a billing period unless the controlled measurement establishes it. Evidence rules unchanged (no provider marketing quotas; end-user API-priced reports or SemiAnalysis controlled measurements).
- **Assumptions**: only the owner-named model-to-model transfers (Opus 5.5's measured Claude multiples to other Claude models; common GPT multiple; MiMo 1.5×) stay in the official Plan ranking, labelled, with donor measurement identified; a transfer never identifies M_W. Any other mismatch (effort, surface, workload, price basis) is "unmatched" and excluded from the official Plan ranking. A measured-only Plan view is published.
- **Scoring with frozen, per-basis anchors** in total-USD units: S_C = 100 × clip((ln c_H − ln c)/(ln c_H − ln c_L), 0, 1); **anchor object (E20)**, versioned per basis and workload hash: reference configuration ids and frozen costs; c_L = min reference cost ÷ 2 and c_H = max reference cost × 2 (a fixed ln 2 log padding, so the reference cohort itself never clips); units; expected clipping (none for the reference cohort). A first-release fixture on the actual reference cohort must pass without re-anchoring. Dollars always displayed; unclipped values kept. **Clip gate (single governing gate)**: per basis, hold the release (O12) when more than max(1, 10% of ranked rows) clip, or any row lies beyond an anchor by more than a factor of 2.

## Quality (75% of the value score)

Normalisation on raw magnitudes with frozen, versioned anchors: z = 100 × clip((x − a_low)/(a_high − a_low), 0, 1); a_low = chance/baseline level, a_high = documented ceiling where one exists, else 100%; rounded inputs treated as rounding ranges; unclipped z kept in the data release. Each release publishes **effective weights** (w_i × SD(z_i), normalised), the leaf rank-correlation matrix and the **share of quality weight by data source** (today ≈75% AA-run: DeepSWE, FrontierCode, GDPval, AutomationBench, Omniscience, LCR, HLE, GPQA, SciCode, CritPt; ≈25% independent: Bug Hunt, Terminal-Bench, LiveBench). A group whose effective weight drifts more than ±50% from nominal is flagged; a leaf with cohort SD(z) < 3 points is marked **non-discriminating** (still scored and reported, excluded from drift-flag counting). AA Intelligence Index and output speed are diagnostics, not quality.

- **One quality vector serves both bases (O10)**; harness differences (e.g. Bug Hunt run in vendor CLIs) are disclosed as a limitation.
- Missing data: displayed quality renormalised over a row's available leaves (fixed leaf weights; no imputation). **Coverage** = observed share of total quality weight. ## Attempts reconciliation

The manifest records separately, per leaf: independent evaluation repetitions (e.g. DeepSWE pass@1 averaged over 3 repetitions — affects precision only) and deployment attempt policy (attempts permitted per task, retry/best-of-k/selection/verifier policy) with the cost coverage of those attempts. Only a genuine deployment-policy mismatch between the quality figure and the priced attempts is reconciled (as a bias bound in the identification layer); repetitions are not a bias.

## Uncertainty (three separate layers, one scenario engine)

A joint scenario simulation (N = 10,000) is the single engine. **Cost is drawn too**: price basis (first-party list vs cross-provider median) and token-use variance (clustered resampling where per-task/per-run costs are published, otherwise a declared parametric range). AA's published cost already embeds AA's cache-pricing protocol (registry: protocol and date), so cache-hit variation is a **named S2 specification-stress branch** around that protocol, not an S0 redraw (E34). Cost and AA-run leaf values are coupled only as the Dependence rule allows (paired public observations; otherwise dependence stress branches). Each scenario also draws leaf values from their measurement intervals, multiples from their ranges, identification bounds for missing leaves, a **hierarchical** weight draw that preserves the nominal means — group weights ~ Dirichlet(100 × (0.60, 0.20, 0.10, 0.10)), within-group weights ~ Dirichlet(50 × nominal within-group proportions); intent is modest perturbation around 60/20/10/10, not alternative buyer preferences (realised per-leaf CV published), and (as named stress-test branches, not random events) source removal, the GDPval mapping alternative, cache-rate variation, the Bug Hunt harness band and the owner-authorised transfer on/off; shared multiples and price lists are drawn once per scenario. Strata are cumulative and computable from the registry: **S0 measurement** = renormalised composite over observed leaves with measurement and cost draws; **S1** = S0 + identification draws (missing-leaf bounds, attempts bias, Plan transport and transfer bounds); **S2 core branch** = S1 + hierarchical weight draws (transfers off, all sources, linear GDPval map); other S2 branches are published separately with explicit reasons when unevaluable.

**Draw-kernel objects (E25)**: every sampled input carries interval_interpretation, kernel_family, kernel_parameters (incl. truncation and mode where relevant), parameter_derivation, dependency_id and alternative_kernel_id. Hierarchy: public paired observations → clustered resampling; rounding interval → uniform; published estimate with documented standard error and an applicable approximation → that declared approximate distribution; interval endpoints only → an explicitly conventional kernel (uniform on the interval) published with an endpoint-heavy alternative (scenario outputs shown under both); no defensible convention → bounds-only, and no scenario-share claim may depend on that input. A "95% interval" is never assumed normal; Terminal-Bench intervals and AA fitted-rating intervals keep their source interpretations. An unspecified kernel fails the scenario build.

Results are published **per stratum** (S0, S1, S2; transfers on/off; leave-AA-out), never averaged into one figure, as scenario shares (e.g. share of scenarios with rank ≤ 3, on the frontier, qualifying at a bar; pairwise ordering shares), labelled as scenario frequencies, not probabilities. Overlap is not treated as transitive tie groups. Layers:

- **Measurement**: published intervals, rounding ranges, task- or run-clustered resampling where per-task/per-run data exist.
- **Identification**: missing-data bounds; Plan transport (M_W given the measured multiple) and owner-named transfer bounds. **Plan uncertainty split (E12)**: each route stores a measurement object (receipts, meter, repeat-measurement uncertainty of M_observed; drawn in S0) and a separate transport object (W hash, quota schema, mechanism, transport bounds; drawn from S1). Where public evidence cannot separate them the route is labelled "measurement and transport not separable" and its S0 result is not described as target-workload support.
- **Specification**: alternative leaf weights, leave-one-benchmark-out, leave-one-source-out (**leave-AA-out is a headline robustness column**), cost-weight slider, owner-authorised transfer on/off, cache-rate stress, Bug Hunt harness stress.
- **Workload cross-check (mandatory, diagnostic)**: per benchmark b (DeepSWE; Terminal-Bench 4.0), a common exact-configuration panel I_b; d_ib = mean cost per attempted task ÷ resolved fraction (∞ when zero, with uncertainty shown). Kendall τ-b between basket-cost rank and d_ib rank within I_b, separately per benchmark (never pooled); task-cluster resampling where task-level results exist, otherwise a model-row bootstrap labelled as matched-set sensitivity; below n = 8 rows in I_b the statistic is suppressed. **Pre-registered threshold (E41)**: a headline warning when the point estimate τ_b < 0.5 (a policy choice, not a statistical fact); "uncertain agreement" when the resampling interval spans 0.5; the exact matched configuration panel is published beside the statistic.

Shared dependencies move together (one multiple, price update or benchmark version affects all its rows jointly).

## Normative definitions (executable specification)

- **Coverage and scores.** p_i = Σ_{b∈O_i} w_b. Displayed observed-only quality Q̄_i = Σ_{b∈O_i} w_b z_ib / p_i. Full-composite score Q_i(θ) = Σ_{b∈O_i} w_b z_ib(θ) + Σ_{b∉O_i} w_b u_ib, u_ib ∈ [0,100]. **Formal bounds** (E35): Q_i^L = min_{θ∈Θ} Q_i(θ) and Q_i^U = max_{θ∈Θ} Q_i(θ) over the joint admissible set Θ below (measurement intervals of observed leaves and u_ib ∈ [0,100] for missing leaves); "missing at 0/100 at the point estimate" is not the bound. S0 uses Q̄_i; S1/S2 use the full-composite equation. Any sampling law for wholly missing leaves is a declared scenario convention (with one published alternative), never evidence; formal bounds are distribution-free.
- **Joint admissible set Θ (for interval outputs: frontier and bar).** Fixed: nominal weights, primary price rule, frozen route, linear GDPval map (E1). Variable: measurement intervals, missing-leaf domains, identified M_W ranges, deployment-policy bias bounds. **Constraint basis (O19, restated for interval outputs)**: each uncertainty object records constraint_basis (published interval / public repeated runs / structural bound / analyst assumption / score domain), estimand, randomness_unit, constraint_target, coverage_claim and supporting_public_evidence (E46). The declared target for quality leaves is the configuration's expected performance over repeated executions of the fixed published suite under its stated deployment policy — not generalisation to new tasks. A rounding interval bounds the reported value; a published confidence interval keeps its source's stated target; an observed run range keeps its meaning as an observed range (coverage claim: the observed executions only); a full score domain expresses the absence of a narrower admissible constraint. No transformation may silently convert one target into another; Θ uses only published intervals, public repeated runs, structural bounds or the full score domain. Analyst-assumed allowances (e.g. a repeatability band) are sensitivity-only and never enter Θ. **Completeness (E11)**: every input, whatever its weight, enters Θ through a documented constraint or its full domain; an input with neither makes the affected output "unevaluable" for that row. Missing repeatability evidence never becomes zero uncertainty. Published benchmark intervals are consumed with their stated interpretation. Shared constraints (prices, donor measurements, task/run observations, quota pools) move jointly. With transfers off, a Plan route that depends entirely on an owner-authorised transfer is "unevaluable" in interval outputs (never silently replaced by API cost). Tests: widening Θ cannot move a row from "possible" to "definite" or create a confirmed result; evidence loss is tested in two stages (E38) — the result within R_W may change when a competitor leaves R_W, but the selected-cohort extension can never strengthen.
- **Plan measurement vs transport.** M_observed = eligible API-valued measured consumption ÷ gross cash paid (the measured workload). **M_W** ∈ [L, U] = the multiple for the scored workload W (O15 basket), bound to W's hash, the release price-list version and the quota-schema version; transport evidence for another workload qualifies only if its capacity model or conservative bound also covers W, with its identification mechanism recorded: direct compatible-workload measurement / publicly evidenced additive capacity model / evidenced transport bound / unidentified. The Plan headline score uses M_W where identified, else M_observed (owner-named transfers as labelled assumptions; O16 flag). **Workload-demand evidence (E44)**: additive-capacity transport needs, per configuration and workload version, the demand vector x_iW (category-k tokens per deployment-equivalent task: input, cache read, cache write, reasoning, output), with execution stack, task support, category definitions, source precision and cache-policy compatibility, plus evidence that the capacity mechanism covers the relevant context lengths, tool use and effort (or conservative bounds). Where only partial token information is public, x ranges over the feasible set X_iW and capacity is optimised over it: M_W^L = min_{x∈X, (a,B)∈A} M(x, a, B), M_W^U = max over the same set. A dollar total alone never identifies x; without a demand object this transport mechanism is unidentified (the displayed score stays under O16). A feasible schedule certifies attainability conditional on its demand and quota inputs, not those inputs. **Plan interval outputs use only an identified M_W**; otherwise the row's Plan cost is "unidentified" for those outputs (it stays scored and ranked). Cohort spread or arbitrary bands never convert "unidentified" into a bound.
- **Frontier (E21).** For a basis and workload W, over the evaluable set R_W = ranked rows with FullCost(i, W) (and, on the Plan basis, identified M_W; subset-cost, partial-component, API-fallback and Plan-unidentified rows are listed as unevaluable): j ≻_θ i ⇔ C_j(θ) ≤ C_i(θ) ∧ Q_j(θ) ≥ Q_i(θ) with at least one strict, using full-composite Q. DefiniteFrontier(i) ⇔ ∀θ∈Θ ∄ j∈R_W∖{i}: j ≻_θ i; PossibleFrontier(i) ⇔ ∃θ∈Θ ∄ j∈R_W∖{i}: j ≻_θ i. Shared dependencies are kept. Scenario frontier frequencies are a separate output.
- **Cheapest above a bar.** Over R_W and a pinned reference r: **confirmed qualification** ⇔ min_{θ∈Θ}[Q_i(θ) − Q_r(θ)] ≥ 0; **possible qualification** ⇔ max_{θ∈Θ}[Q_i(θ) − Q_r(θ)] ≥ 0; **scenario qualification** = share of scenarios with Q_i(s) ≥ Q_r(s). **Confirmed cheapest** (interval, E38): i qualifies confirmed, is not provisional, and for every j ∈ R_W∖{i} that can possibly qualify, max over {θ ∈ Θ: Q_j(θ) ≥ Q_r(θ)} of [c_i(θ) − c_j(θ)] < 0 (strict; i never competes with itself). **Scenario-supported cheapest**: in ≥ 90% of scenarios s, i qualifies in s and is strictly cheaper than every j ∈ R_W∖{i} qualifying in that same s (the simultaneous event; a row undefined in s makes the event unevaluable, never a win). Ties are never broken: equal-cost qualifiers prevent a unique label. **Possible-cheapest set (E45)**: i ∈ K_r ⇔ ∃θ ∈ Θ: Q_i(θ) ≥ Q_r(θ) ∧ ∀ j ∈ R_W∖{i}: [Q_j(θ) < Q_r(θ) ∨ C_i(θ) ≤ C_j(θ)] — rows that are cheapest (ties allowed) among qualifiers in at least one common admissible state; rows that can never be cheapest are excluded. Published per bar: the confirmed unique cheapest (if any), the certified members of K_r, unresolved memberships, and provisional status beside each candidate. Fixtures: a singleton, confirmed-qualified, non-provisional row → confirmed cheapest; a provisional singleton → no confirmed-cheapest label (it may be in K_r); a uniquely cheapest candidate; two equal-cost qualifiers → both in K_r, no unique label. The reference configuration always qualifies against itself. **Scope (E38)**: every frontier and bar result publishes its universe ("among these n evaluable configurations") and whether it **extends to the selected cohort** — established only when every row outside R_W is ruled out by structural bounds (e.g. full-domain quality bounds below the bar, or a cost lower bound above the candidate's cost upper bound); otherwise "not established", with the omitted competitors listed.
- **Interval decision procedure (E40, amended by E43).** Interval labels are decided by deterministic, decision-specific feasibility problems over Θ, never from scenario draws. Θ = per-row input boxes (independent across rows) × a box of declared shared factors (e.g. a common price list or a donor multiple shared by several rows). With no shared factor, each label is decided exactly by monotone extremes (Q is linear in leaf values; basket cost is monotone in component costs; each row's inputs move only its own C and Q): e.g. possible-frontier membership of i is established by setting i to its best corner and every j to its worst. With shared factors, labels are decided by **certified interval branch-and-bound** over the shared-factor box: on each sub-box, interval bounds either certify the condition for every point (witness), refute it for every point (prune), or the sub-box is split, up to a published depth; a sub-box still undecided at that depth returns **unresolved**. Endpoint search alone is not sufficient (release test: competitors with Q_j = 2t and Q_k = 2(1 − t), C_j = C_k = 0, and i with C_i = 1, Q_i = 1.2: i is a possible-frontier member via the interior witness t = 0.5). Possible-frontier membership solves, in one common θ, for every j ≠ i: C_j(θ) > C_i(θ) ∨ Q_j(θ) < Q_i(θ) ∨ [C_j(θ) = C_i(θ) ∧ Q_j(θ) = Q_i(θ)]; definite membership is disproved by one θ and one dominating j; strict inequalities are decided exactly, never by tolerance alone. Every returned witness is re-checked against the original equations and shared constraints. Statuses: certified / disproved / unresolved / unevaluable, with solver status, depth and witness (or counterexample) stored; an unresolved solve is never shown as certified.
- **Workday-feasible Plan multiple (diagnostic, E15).** Owner decision O3 keeps full utilisation as the scored estimand. Where the quota schema is evidenced, the same capacity program is also solved with consumption allowed only in a pre-registered 40-hour week (8 h × 5 days); M_workday and the ratio M_workday / M_full are published per route as a diagnostic, never scored.
- **Harness stress branch (E19).** Bug Hunt runs on vendor CLIs while DeepSWE and Terminal-Bench run in controlled harnesses. An S2 specification-stress branch applies a harness-mismatch band to Bug Hunt estimated from same-model cross-agent spreads on the tbench.ai leaderboard, pre-registered in the registry; published as stress, never in Θ.
- **Target-basket readiness (E22, diagnostic).** Per target component: inclusion status, missing configurations, task multiplicity, cost availability, priced quality weight. Per scored model: expenditure share s_ie = n_e c_ie / C_i,W per component and concentration HHI_i = Σ_e s_ie². A **task-family overlap matrix** (E42) accompanies it (e.g. Terminal-Bench inside both the Index run and the Coding Agent Index); family-level concentration is "unidentified" where aggregate costs cannot be separated. No single unlabelled coverage percentage.
- **Robustness outputs (E13, amended by O22).** Separate, named columns: (1) displayed-score rank sensitivity (scalar displayed value score); (2) full-composite scenario-rank sensitivity (scalar V_i(θ) = 0.25 S_C(c_i(θ)) + 0.75 Q_i(θ)); (3) branch evaluability and exclusion reasons, with retained quality weight shown before any rank statistic. Numerical rank change is computed only within evaluable branches; an unevaluable branch gets no rank. "S2 maximum rank change" refers to (1).
- **Cohort rule (executable).** F(c) = best rounded Index among rendered-frontier configurations with cost ≤ c; a family is near-frontier when a plotted configuration's rounded Index ≥ F(c) − 3; ties by lower cost then name.
- **Omniscience counts.** From AA counts (c correct, p partial, i incorrect, a not attempted): A = 100c/(c+p+i+a); AA's hallucination rate = i/(i+p+a), so N = 100[1 − i/(i+p+a)] (N = 100 when i+p+a = 0); z = (2A + N)/3. Test vector: c=60, p=0, i=10, a=30 → A=60, N=75, z=65. Reconstructed values are tested against AA's published fields.
- **Plan capacity under multiple pools.** Where public controlled measurements establish additive consumption per budget w (a_wk per token of category k, spendable capacity B_w over the fee period) and x_k = tokens of category k per unit of workload W: λ_w = B_w / Σ_k a_wk x_k, λ = min_w λ_w, M = λ × C_API / F_gross, where B_w must be attainable over the fee period: billing boundaries, reset phase (e.g. account-specific weekly reset times), carryover and evidenced throughput limits are recorded, and where windows and billing periods misalign capacity is computed by a small time-indexed linear program (maximise Σ_t y_t subject to the window constraints), or a conservative bound when scheduling feasibility is not established. **Window semantics (E30)**: each window is encoded as recorded in the quota schema — session-anchored windows start at first use; fixed-reset windows at their recorded reset times; sliding windows as ∀t: Σ_{τ∈(t, t+h]} a_wτ y_τ ≤ B_w; unknown semantics use the conservative sliding form. Model-specific sub-caps inside a shared pool and model-specific burn coefficients are separate constraints, never borrowed from another model. **Schedule contract (E39)**: time is discretised on a published grid (default 15 minutes) with stated boundary treatment; fixed-phase windows are ordinary time-indexed constraints; session-anchored windows use explicit session-start variables (a session starts at the first consuming step after the previous session ends) or, equivalently, enumeration of admissible session schedules on the grid; where public semantics are insufficient, a documented feasible conservative schedule is used instead of an unconstrained optimum. Every identified capacity result publishes a feasible consumption schedule that attains it; where the optimum is not established, a lower bound from a feasible schedule and an upper bound give an interval for M_W. This λ / time-indexed LP is the **only governing Plan formula** (release tests: loosening a non-binding 5-hour cap cannot change a plan whose weekly cap binds; two bursts one hour apart, each 60% of a 5-hour cap, are infeasible; the same bursts six hours apart are feasible). Harmonic-style category combination is used only where a common additive budget is established; otherwise the observed-mix multiple is kept with its mix-unmatched flag and target-mix capacity is reported as unidentified. Provider quota descriptions may document structure but never supply the numerator.
- **Dependence.** Every uncertain input records interval meaning (rounding / published CI / observed range / identification bound / analyst stress range), sampling law with justification, and dependency identifier with supporting paired evidence. Costs and outcomes are resampled jointly only when paired task/run observations are public; otherwise shared factors (same price list) are kept and independent / positive / negative dependence stress branches are published; interval outputs use conservative joint bounds.
- **Bug Hunt estimand (E29).** The measurement is the mean of the published runs for the exact model, effort and harness (pooled fixed/105 per complete run; run count recorded; owner-published means and run-level results where public). Run-to-run spread from public repeated runs is measurement evidence; repository differences are a repository sensitivity, not repeats. For a single-run row, interval outputs use the full score domain for this leaf (O19); any analyst repeatability band is sensitivity-only; cohort spread is never used as exact-variant evidence.
- **Provenance.** Per leaf: dataset author, execution organisation, harness, grader. Evaluator-independent quality weight and task-overlap exposure are reported separately (e.g. Terminal-Bench: independently executed quality leaf, two further AA executions priced in the basket).
- **Versioning.** Methodology version, evidence/benchmark version and release snapshot are separate. A new observed price under an unchanged price rule is a data refresh; changing a rule is a methodology migration; a benchmark-version change triggers a comparability review with dual-run where feasible.
- **Release tests.** Omniscience vector above; Bug Hunt vector above; Index reconciliation (C_7 + HLE + Omniscience + CritPt reproduces AA's total within tolerance; the residual never enters C_W); Coding Agent Index fixture (published total = per-task mean × tasks included; tasks without telemetry recorded as missing, not imputed); aggregate/component exclusivity (an exactly reconciled decomposition leaves basket cost unchanged); repetition invariance (averaging extra evaluation repetitions does not multiply workload cost); workload migration changes W's hash and invalidates unreviewed Plan transport; basket persistence (a new cohort row with missing costs does not change W's hash); single clip predicate (all gate consumers call one function, with integer-boundary fixtures for several cohort sizes); split/merge invariance (splitting an execution component into accounting subcomponents, or a quality leaf into two leaves with the same total weight and execution workload, leaves C^match unchanged); kernel completeness (every stochastic input has executable parameters); price tests (E23): uniform price scaling cancels in Plan cost; arbitrary category-price changes cancel when measured consumption is proportional to the target-workload token vector; otherwise category repricing changes Plan cost by (p·x / p·u) and triggers a transport identification recheck (two-category fixture with different measured and target mixes); restoring a missing leaf moves correctly from S0 to S1; transfers-off never silently becomes API fallback in an interval output; a tighter quota cannot increase computed capacity; window-semantics fixtures above; adding an unrelated row cannot change common-panel diagnostics except via declared cohort-dependent quantities; the reference configuration qualifies against itself; cheapest fixtures (non-provisional and provisional singletons, unique cheapest, equal-cost tie → both in K_r; no self-comparison); interior-witness possible-frontier fixture (E43); completeness statuses (identity at source precision → confirmed complete; a failing identity → confirmed incomplete; rounded fields → unresolved); completeness (a component with fewer cost-observed than required tasks fails FullCost and removes the row from R_W without changing its displayed score); session-start fixture (a schedule whose second burst starts a new session after the first session ends is feasible; capacity results carry a feasible schedule); interval decision statuses (an unresolved solve is never certified); widening Θ cannot create a confirmed or definite result; every cost check reads C_W, never the Index diagnostic.

## Governance

Evidence classes (measured / claim / estimate / assumption); provider claims never overwrite independent measurements. Plan evidence carries a 30-day soft expiry with change detection (a plan is flagged "possibly superseded" when scoped change detection — pricing tables, rate-limit documentation sections and model-availability matrices, not full-page diffs — shows a change since measurement, or when ≥ 2 independent end-user reports (O11 independence) describe an undocumented limit change; E18) and a 90-day hard expiry; after a further 30-day grace an expired route is **demoted to diagnostic-only** and the model falls back to API cost (flagged) in the official Plan table (O13), labelled "cross-estimand ordering not identified" and excluded from Plan interval outputs (E36). Each row stores its AA price-list date; score changes are decomposed into price change vs token-use change vs method vs cohort. The scenario engine uses a published RNG seed and draw order per release, and per-stratum outputs are released as data files. Plan rows publish fee F and full-utilisation capacity M × F in API-priced USD so light users can judge fit. Freshness: AA cost snapshot and price list max age 45 days, with change-triggered refresh; monthly cadence. Each row publishes its own effective weights (per-row renormalisation changes them) and SD(S_C) with a cost-vs-quality variance decomposition of its value score. Release gates (on failure the release is **held** — fix the data or re-anchor as a versioned migration with a dual-run comparison; O12): the clip gate defined under Cost, an unversioned AA chart/field change, or any score swing > 5 points without an attributed cause. The registry records, per row: chart field name; total cost and cost per task side by side; repeat inclusion; AA cache protocol and date; price rule (first-party list vs cross-provider median for open weights); fallback-token treatment; Elo anchor identity (e.g. GDPval-AA scale pinned to a named reference model) and judge-panel/grader versions for rubric-graded leaves. A change of rule in any of these is a methodology migration; a new value under an unchanged rule is a data refresh (see Versioning). Leave-AA-out is reported as "not identifiable under the coverage rule" when the remaining identified quality weight is under 40% (the case today, with ≈25% independent weight), and is excluded from any denominator.

## Known limitations

Full-utilisation Plan cost overstates value for light users (workday diagnostic shown); AA cost uses AA's token mix and cache protocol; Terminal-Bench work is priced in two executions; Bug Hunt covers two repositories; DeepSWE/Bug Hunt/TB measure model+harness stacks; suite is primarily English text; FrontierCode and ITBench-AA remain pending capture until exact-variant cost covers two-thirds of ranked rows.
