## 1. Findings by severity

**Critical**

None.

**High**

- **Terminal-Bench 4.0 is priced twice inside one basket (Owner decision challenge to O24).** In the max-effort ranking the basket admits both the AA Index Terminal-Bench 4.0 run (66 tasks, bare model) and the Coding Agent Index v2.0, whose single pooled cost contains Terminal-Bench 4.0 run by vendor agents (66 tasks) . The draft's stated rationale — "each is what a user of that deployment pays"  — no longer holds as a defence, and that is the new argument: O123 subsequently made the vendor agent *part of the configuration being costed* for the Coding Agent Index , so for CAI-admitted rows the costed configuration is the agent deployment, while the Index TB run simultaneously charges a bare-model deployment the buyer of that configuration does not run. The effect is a per-task-family weight distortion: TB 4.0 tasks carry roughly twice the per-task weight of every other task family in the basket, non-uniformly across rows (CAI share spans 16–74% of basket cost in that ranking ), feeding directly into the 25% cost weight of the headline. The FrontierCode case is explicitly different — 1.1 vs 2.0, different tasks  — which confirms TB is the only task family double-priced. Recommended change: publish a de-overlapped sensitivity, C′_W = C_W − c_Index-TB for CAI-admitted rows, with the resulting value-score and rank deltas, until the owner decides whether one execution substitutes for the other when the CAI is admitted.

**Medium**

- **The completeness test cannot localize a mispriced component.** Completeness of the six Index SDLC evaluations is decided by whether the nine evaluation costs reproduce the published Index total within 0.1% (O175) . That is a joint test: offsetting component errors (e.g. one component priced on a stale price record, another on a fresh one) pass, and every component is flagged or cleared together. Why it hurts: C_W is a sum over components, so a row-level residual hides where the error sits even though the draft itself treats the Claude Opus 5.5 same-sign residual as "a pattern and not noise" . Recommended change: add a within-component reconciliation diagnostic — for every component where AA publishes both a per-evaluation cost and a per-task mean, publish r_ie = c_ie − n_e × mean_ie, with task counts already frozen in the accounting identities ; a row passes as today, but the published residual table localizes drift.

- **Admission alternatives are published without their subset-row consequence.** E140's lexicographic order maximises admitted components first, panel size second , so a maximal-component set can demote many rows to subset workloads (scored separately under O17/E10 ). The admission object publishes marginal coverage and joint coverage , but not how many cohort rows each feasible maximal set would demote to subset scoring. Why it hurts: the owner cannot see the ranking-coverage cost of component-count primacy at the freeze where the choice is made, which is exactly the trade-off the enumeration is deciding. Recommended change: annotate each published feasible alternative with its projected subset-row count (and the configurations demoted); this is a pure publication change, computable before scores are inspected, and does not alter E140's determinism.

- **Frozen admission (O169) has no escalation path for sustained coverage collapse.** An admitted component stays in W until the next re-freeze whatever its coverage does, published only via `frozenBelowThreshold` . Why it hurts: if AA withdraws or degrades a component's cost publication, every refresh between freezes adds subset rows and shrinks the main workload indefinitely, and the only signal is a flag with no trend. O169's rationale was that *processing order* cannot matter; a trigger keyed to release counts does not reintroduce that problem. Recommended change: publish a per-component coverage series across releases (the marginal-coverage data already exists), and add an owner-gated rule that two consecutive refreshes below the two-thirds threshold schedule an off-cycle re-freeze evaluation (the O12 dual-run machinery decides whether it proceeds).

**Low**

- **E26's lead sentence says "exact-configuration cost exists" while admission is actually decided on P_K / CompleteCostEvidence** (exact *and* no missing/declined marker *and* the O175 band) . The two public matrices P_A and P_K exist precisely because these differ ; the legacy wording in the operative first sentence invites misreading. Reword the E26 opening to name CompleteCostEvidence and P_K.

- **The degenerate empty-admission case is unspecified.** If no subset of the eight units reaches the two-thirds threshold, the lexicographic maximisation over feasible sets can select the empty set (|P(∅)| = N trivially qualifies), leaving W with no components and C_i,W undefined. State that the build fails (release held under O12) when the admitted set is empty, rather than leaving the case to inference.

- **The Opus 5.5 residual's cause "stays unregistered"**  although the draft already treats it as a systematic pattern re-read each release. Register candidate cause classes (price-snapshot date mismatch per E176's bridge-cause machinery; per-task rounding) in `indexReconciliation`, so that a growing residual at the next capture is immediately interpretable rather than re-derived from scratch.

- **Reliance on silent-fallback matching is not quantified.** A third-party record silent on fallback matches by model and effort "whichever way AA plots the model"  — a pragmatic rule, but the extent to which leaf evidence rests on unverifiable fallback state is invisible. Add a registry field (silent / explicit-match / explicit-mismatch-decided) per leaf record and publish the silent share per benchmark, so the exact-variant claim's weakest link is measurable.

- **The Plan subset stratum reports "undefined (one configuration)" despite having five rows** . E180 defines SDs over rows, undefined below two rows; here five Plan rows (one configuration × plans) are declared undefined because dispersion is evidently measured across configurations. Either state the estimand E324 uses, or compute across-plan dispersion for Plan strata — five rows of the same configuration at different plan costs is real Plan-basis variance being reported as undefined.

## 2. Methodology design recommendations

Prioritised, all implementable from public AA data within the existing build:

1. **De-overlap bridge for Terminal-Bench 4.0 (addresses the High finding).** For every ranking that admits the Coding Agent Index, compute and publish C′_i,W = C_i,W − c_i,Index-TB for the CAI-admitted rows, with the value scores, ranks and exchange-rate deltas that follow (same machinery as the E184 overlap bridge). This is a labelled sensitivity unless the owner promotes it; it makes the O24 double-count's rank effect visible for the first time.
2. **Per-component residual table.** Publish r_ie = c_ie − n_e × mean_ie wherever AA publishes both figures, using the task multiplicities already frozen in the accounting identities (91 / 657 / 100 / 132 / 66 / 70 / 40 / 3,000 / 1,000) . Threshold-free diagnostics; complements the 10⁻⁶/0.1% row-level test without gating anything.
3. **Subset-demotion annotation on admission alternatives.** Add `demotedRows` (count and configuration IDs) to each feasible alternative in the published admission object ; the enumeration already computes P(S) for every subset, so this is a publication change only.
4. **Frozen-component coverage trend with an owner-gated re-freeze trigger** after two consecutive sub-threshold refreshes, plus the per-release coverage series. Keeps O169's order-independence intact while removing the unbounded degradation window.
5. **Evidence-provenance typing for fallback matching and residuals**: a per-record fallback-state field (silent/explicit) with published shares, and a cause-class register for the Opus 5.5 residual, both in existing registry files (`scores.json`, manifest) with no scoring impact.
