**Medium**

- **Two-reference Plan anchor panels give a fragile cost scale with no robustness disclosure.** E160/O157 set the Plan anchors from measured plan rows only, with a minimum of two references . With two references at similar prices, the padded range is little more than ln 4, so a plan 2× the dearer reference already scores 0 on cost and the entire Plan cost dimension is calibrated by two observations; a single new measured row can shift every Plan cost score materially at a re-freeze. This hurts the objective because the Plan ranking is the headline view for plan buyers and its cost sensitivity is invisible. Recommendation: publish, per basis and workload, the anchor-panel size and reference identities in `scores.json` beside the anchors, and add a leave-one-reference-out sensitivity (cost score and rank delta per dropped reference) whenever a panel has fewer than, say, four references; optionally widen padding adaptively (padding = max(ln 2, 1 × IQR of ln reference costs)) so thin panels do not create extreme compression.
- **E268 couples the AI Coding Daily leaf to Bug Hunt's harness choice.** The double-listed-board rule picks the AICD row whose harness equals the configuration's Bug Hunt record, so a Bug Hunt refresh can change the AICD leaf "although no AI Coding Daily row changed" . The draft discloses this and attributes it via the E177 replay (E334), but the selection rationale is a proxy: AICD harnesses already vary per model, so matching Bug Hunt's harness does not create within-board comparability — it creates cross-board coupling without a stated estimand. Recommendation: state the estimand explicitly (same model-plus-agent combination measured on both boards) and publish, as a cheap sensitivity beside E224's cross-harness list, the leaf and rank each affected row would take under the fallback rule (latest test date, then largest N); today that is one row (DeepSeek V4.1 Flash 1017 max), so the cost is negligible.
- **O193's asymmetric-migration path is decided but not implemented.** When API references pass and Plan references do not, the API basis should migrate while the Plan basis reads "unavailable for the new version"; the draft states the build does not carry that path and stops until the state is met . The stop is safe, but the state is reachable (measured Plan rows are scarce), and hitting it unimplemented holds a release under O12 for want of code rather than evidence. Recommendation: implement the O193 branch with its named fixtures (two API references with one measured Plan reference, and with none) before the next Plan-evidence shift, and add a fixture for the historical-labelling of the Plan basis's prior outputs.
- **Anchor unavailability on a subset workload leaves a row's ranking status ambiguous.** A subset workload left with fewer than two eligible references "takes the unavailable state" and its configurations "get no cost score" , but the part does not say whether such a row stays ranked without a value score or becomes listed. Readers cannot distinguish "not comparable" from "unranked for lack of anchors". Recommendation: add a release-manifest entry naming rows that lost scores to anchor unavailability, distinct from missing-leaf listed rows (O36/O38), and state the ranking status in the same sentence as the unavailable state.

## 2. Methodology design recommendations

1. **Anchor-panel robustness layer (highest priority).** For every anchor object, publish panel size, reference identities, and a leave-one-reference-out replay: recompute c_L, c_H, every row's cost score, value and rank with each reference dropped in turn; flag any basis whose median rank shift under a single dropped reference exceeds the published noise margin (O42/O128). This is implementable entirely from already-frozen reference data, costs nothing new to capture, and directly quantifies the two-reference fragility above.
2. **AICD selection sensitivity.** Publish the alternate selection (latest test date, then largest N) for every E268-affected row beside the Bug Hunt cross-harness list in `scores.json`, with the induced quality, value and rank deltas, mirroring E224's disclosure pattern .
3. **Anchor-unavailability manifest entry.** One structured entry per workload in the unavailable state: affected rows, their previous release's status, and the label readers should attach ("no cost score — anchors unavailable, not a quality gap") .
4. **Constants table.** A single published table of fixed numeric constants (factor-2 padding, factor-2 gate limit, 10% clip fraction, 3-point SD threshold, 4.5-point noise margin) with one-line rationales and version bridges, so future recalibrations are visible migrations rather than silent edits. The LiveBench noise machinery already sets this standard for its own constants (√7 envelope, √14 joint stress, half-count bracket), which I verified is mathematically sound — the Cauchy–Schwarz bound (Σw·SD)²/Σw²SD² ≤ 7 is correct for non-negative dependence .
5. **Disclosed-unit fix for the O58 table** (from the Low above): one-line format change, factor and anchor value per row.
