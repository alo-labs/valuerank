## 1. Findings by severity

**Critical**

None.

**High**

1. **Per-event label certification with no family-wise control (E77, E198a).** The 90% label is met when the Clopper–Pearson lower bound (per-look δ = 0.05/16) reaches 0.90, and the draft correctly notes the guarantee is per event, "not corrected across the candidates a bar lists." The problem is scale: at the stated per-event error of 0.003125, roughly 40 certified events per release give about a 12% chance that at least one label crosses spuriously, and ~80 events give about 22% (my computation from the draft's own δ). Labels ("cheapest above bar," scenario-supported cheapest) are the ranking's headline claims, so an unquantified, monotonically growing family-wise error directly undercuts the credibility the sequential rule is built to provide. The CP machinery itself is correctly specified — the Beta-quantile endpoints, the closed forms at k = n and k = 0, and the SciPy argument note all check out against the standard formula  — so the fix is cheap: (a) publish the certified-event count and the implied family-wise bound beside every label table, and (b) add a Holm step-down companion within each bar's candidate family, at zero data cost, so a reader can see which labels survive multiplicity correction. This is not in the decision ledger as adopted or rejected. [en.wikipedia](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval)

**Medium**

1. **"Cost noise cannot be drawn" is stated too absolutely for the separability machinery.** Part 12 says the separability threshold (O42) draws quality noise only because "AA publishes one cost run per configuration with no per-task cost dispersion, so cost noise cannot be drawn," and concedes the net direction of omitting cost "is not established." Yet the same part's workload cross-check says "paired task-level costs and outcomes, where public, are resampled jointly" (E68), and O27 defines the Coding Agent Index cost as a pooled per-task-attempt average — i.e., per-task cost observations exist at least for that component, and Vals publishes per-run standard errors that the draft already consumes elsewhere (E256; tbench.ai and Vals both publish run-level dispersion publicly ). Cost is 25% of the value score, so quality-only noise bands, separability statements, and the bar noise margin (O44/O128) are missing a first-order noise input the draft elsewhere admits is partially available. Recommended change: scope the "cannot" claim to exactly which components lack public dispersion, and add a named cost-resampling stream (task-clustered bootstrap of per-task costs for components that publish them) restating the separability pairs and noise margin beside the quality-only ones. *Owner decision challenge (O42/O128, which keep a single quality-only margin):* the challenge is narrow — not to change the headline margin, but to publish a cost-inclusive companion where public per-task cost data exists, since the draft already resamples such data in E68. [datacamp](https://www.datacamp.com/blog/terminal-bench-4)

2. **GDPval-AA ratings drawn independently despite acknowledged Crowd-BT covariance.** The draft discloses that fitted ratings "covary through shared matchups, so pairwise rating differences may be over- or under-dispersed" and corrects nothing. Rank comparisons are exactly pairwise differences, so this is the quantity S1T is used to assess. The draft already solved this exact problem for Bug Hunt with a −1/0/+1 covariance specification stress (E309); the same pattern needs no new public data. Recommended change: add a shared-matchup factor stress for the GDPval leaves (draw a common factor at correlation −1, 0, +1 across rows) and restate the separability statement under it, published in scores.json beside `bugHuntCovariance`.

3. **The like-for-like gate keys on a self-inclusive statistic.** *Owner decision challenge (O182/O183/O187):* the label-withholding gate reads basket cost against Terminal-Bench cost per attempted task, and the draft itself notes the check "includes its own Terminal-Bench component, so a pass shows agreement with that component." Correlating a basket against its own largest single component mechanically inflates τ_b, making the gate more permissive precisely where it is meant to be skeptical — a ranking could pass the gate while its non-TB components disagree with execution cost. The leave-TB-out τ_b is already computed and printed beside it, so the fix is a one-line comparator change: gate on the leave-TB-out statistic (or on both, withholding if either fails), keeping the self-inclusive reading as the published diagnostic.

4. **Single-source dependence has no quantified output.** Leave-AA-out is "not identifiable under the coverage rule" (34% and 22% retained weight), so the ranking's dominant robustness question — how much it depends on one publisher — currently has no scenario number at all, only E62's matched-panel statistics. Recommended change: register a leave-AA-out *evidence-unavailability* branch (the distinct branch type E146 already defines, so no name collision) even if its bounds are wide, and add a conventional, labelled specification stress that shrinks each AA-published leaf halfway toward the cohort median of that leaf, reporting rank shifts and τ_b on the common panel (E65). Both are computable from captured data each release.

**Low**

1. **Arithmetic slip in a derived constant.** The draft says the Jeffreys Beta draw's SD is smaller than the plug-in SD "by a factor √(n/(n+2)) (1.5% at 66 tasks, 0.2% at 1,000)." The 66-task figure is right (1.48%); at n = 1,000 the factor gives 0.10%, not 0.2% (my computation). Immaterial to any conclusion — the plug-in summary stays the larger — but E265 says every figure is build-rendered and checked, and this one is a prose-derived constant that slipped through; render such constants from the build too.

2. **S1T's kernel specification is not executable as written.** The per-leaf draw laws (Beta posterior for binomial leaves, clipped normal with plug-in SD for non-binary bounded leaves, Poisson-floor unplanted counts, LiveBench's variance bound, Vals SEs, the GDPval interval reading) are packed into a single run-on sentence of roughly 1,500 words that interleaves draw laws, reported analytic summaries, covariances and sensitivities, and ends "drawn from a normal clipped to 0–100 like every leaf" for Bug Hunt even though binomial leaves draw from Beta under O142. The underlying design is sound — the Jeffreys posterior Beta(k+½, n−k+½) matches the standard Jeffreys update, and the variance and mean-shift relations check out — but an implementer must disambiguate which value is a draw and which a reported summary. Recommended change: emit a per-leaf S1T kernel table (leaf, kernel family, parameters, reported analytic SD, clipping, covariance stress, mean-shift fields) into scores.json beside the existing `samplingMeanShift` object, and keep the prose as commentary. [casrai](https://casrai.org/guides/prior-distributions)

## 2. Methodology design recommendations

Prioritized:

1. **Cost-noise companion stream (highest value).** For every basket component that publishes per-task or per-run cost dispersion — the Coding Agent Index per-task metric (O27) and Vals' per-run standard errors are the candidates; tbench.ai likewise publishes run-level intervals  — register a named stream that task-cluster-resamples cost, redraws the value score V = 0.25·S_C + 0.75·Q, and restates the noise bands, separability pairs and the bar noise margin with cost included. Components without public dispersion stay at reporting precision, labelled. This closes the disclosed-but-unquantified gap between the 25% cost weight and the quality-only uncertainty outputs, without touching O25 (the stream is a separately named scenario layer, exactly like S1T). [datacamp](https://www.datacamp.com/blog/terminal-bench-4)

2. **Multiplicity companion for labels.** Beside each label table, print the number of certified events and a Holm step-down variant within each bar's candidate family; if Holm unresolves a label, it is published as "scenario threshold unresolved under multiplicity correction," not silently dropped. Zero data cost; the CP endpoint machinery is already correct. [en.wikipedia](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval)

3. **GDPval shared-factor stress.** A common-factor draw across GDPval-AA rows at correlation −1/0/+1, mirroring E309's `bugHuntCovariance`, with the separability statement restated under each; discloses whether the admitted independence assumption widens or narrows perceived separability.

4. **AA-dependence stress.** Half-shrink of AA-published leaves toward the cohort leaf median as a labelled conventional S2 branch, plus the registered evidence-unavailability leave-AA-out bounds branch; both refreshable from captured data each release and reported with τ_b and rank shifts on the E65 common panel.

5. **Machine-readable S1T kernel registry.** As in Low 2 — a per-leaf kernel object in scores.json, since the draft's own framing ("executable specification") and the E25 draw-kernel machinery already require exactly this shape for every other sampled input.
