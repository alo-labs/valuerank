## 1. Findings by severity

**Critical**

None.

**High**

None.

**Medium**

1. **Per-competitor mixed kernel assignments are never solved (part 14, kernel checks).** In the registered v1 design every competitor component maps to one "competitors" role group, so A = {uniform, arcsine}^G checks only the all-uniform and all-arcsine competitor worlds. The draft discloses this ("a label states that it holds under the registered role-group kernel checks, not under every per-competitor kernel combination"), but the disclosed caveat understates the practical gap: the plausible stress is *heterogeneous* — one competitor's identification primitives heavy-tailed (arcsine concentrates mass near the endpoints ) while the rest stay uniform — and that is precisely the case never solved. A label can therefore read "supported under all registered role-group kernel checks" while a single-component arcsine world drops the qualifying-and-cheapest event below 90%. Concrete change: register an additional stress family of one assignment per competitor component c — arcsine(c), uniform everywhere else — plus the symmetric candidate-component variant; publish min frequency and the argmin component name beside the existing published range, and (stronger option) require the E77 lower bound ≥ 0.90 on these too before authorising the label. Cost is bounded: one extra solve per competitor component per decision. [en.wikipedia](https://en.wikipedia.org/wiki/Arcsine_distribution)

2. **The O171 pointwise screen reads superseded-price blockers at their published cost (part 13).** The screen's comparison panel (E341) is "every non-provisional main-workload row on the answer's basis at its published cost, blockers included." For O94/O98/O196 blockers this is conservative, since their hulls extend only upward from C. But an E170-outcome-3 / O29 row competes over "the hull of its published record and its current-tariff bound" — and when the current tariff is *cheaper* than the superseded price, that hull reaches below the published record (via E335's repricing multiplier). The screen can print "passes the screen" while such a blocker is in fact cheaper than the answer at current tariffs. The label layer catches this through BlockerSafe's hull read; the screen, printed beside the headline displayed-record answer as reassurance, does not, and unlike the screen's other disclosed limits this is a directional bias, not mere imprecision. Concrete change: when a cheaper row in the screen panel is an E170-outcome-3/O29 blocker whose current-tariff hull reaches below the answer's cost, print a named caveat beside the screen status (e.g. `screen.blockerCaveat` with the row and hull lower endpoint), and optionally compute that row's Δ at the hull's lower-cost endpoint as a flagged variant.

**Low**

3. **The E228 window-start fallback has undefined scope for non-report routes (part 14).** UniqueLabelEligible's E228 clause uses "its window start, else 29 days before publication." Under O194 an unstated-window report admits nothing, so report-based routes always state a window and cannot reach the fallback. But the authorized non-report routes — OpenCode's published dollar limit (O198), SemiAnalysis figures (O45/O151) — have no defined "publication" or measurement window in these parts, and O46 ceilings are provider-derived, not measurements. If any admitted route can reach the fallback, a limit or price change dated inside its true evidence span but before the fallback window start would not flag the route. Concrete change: state which route kinds may use the fallback; for each route that does, record "window asserted, not measured"; or drop the fallback and require a stated window for every route, consistent with O194.

4. **Owner decision challenge — O100 exact-text footnote matching (part 13).** Classification "once by its exact text" means any whitespace, ordering, or date-in-text change to an AA footnote stops the build until manual reclassification, on every release, even when the registered substantive fields (pricing-omission status, largest factor) are unchanged; O103's expansion to model pages, the Coding Agent Index and the cost charts multiplies the surface. New argument, distinct from the ledger's rejection of loosened gates: the register already isolates the substantive content, so matching can compare a canonicalized form (whitespace-, case- and punctuation-normalized) before exact-text comparison while keeping the stop-on-substantive-edit semantics identical. This removes routine holds that sit awkwardly with the requirement that the ranking be refreshable routinely, without weakening any guard.

## 2. Methodology design recommendations

1. **Single-component arcsine kernel stress (from Medium 1).** For each decision, for each compiled competitor component c in the decision's kernel-check object, add assignment A_c = {arcsine on c, uniform on all other non-empty groups}; publish min_c frequency and argmin beside the existing per-assignment range and hash. If the owner wants it authorising, the label condition becomes: every assignment in A ∪ {A_c} completes with E77 lower bound ≥ 0.90. Bounded, deterministic, and implementable from the already-compiled component graph.

2. **Hull-aware blocker caveat on the O171 screen (from Medium 2).** In `displayedCheapest.<basis>.bars[].noise`, add a `blockerCaveat` list naming cheaper E170-outcome-3/O29 blockers whose current-tariff hull lower endpoint is below the answer's cost, and a flagged variant of each such row's Δ computed at that endpoint. Mirrors E186's BlockerSafe at the diagnostic layer at negligible cost, since the hulls are already computed for the interval outputs.

3. **Annotate E201c's unchecked cheaper siblings with shared-subset workload cost.** The sibling pointer currently compares only AA total Index cost and "cannot name a sibling that is dearer on the Index but cheaper on the workload." Where exact-variant evidence exists for a sibling on components shared with the ranking's workload (e.g., Coding Agent Index per-task cost × tasks, per O27), publish that sibling's shared-subset cost beside the pointer with the E173-style disclosure of the missing components' expenditure share and the direction-unknown caveat. Still a pointer, never a claim; it narrows the blind spot using only already-captured public data.

4. **Cross-reference the two noise constructs.** O44's companion (1.96·√2·median σ, today 3.6/5.8 points) and O171's screen (per-row Δ with the setter's frozen σ_H) use different pair-noise scales — median-based vs setter-SD-based. Print one line beside both stating which output reads which construct and that they are not numerically comparable, so readers do not read the screen's Δ = 1.96 threshold as the margin divided by something.
