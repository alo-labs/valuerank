1. Findings by severity

Critical
None. The normative machinery in these parts is exceptionally well bolted down; I found no unreconciled contradiction or score-corrupting defect.

High

Agent-measured cost against bare-model quality in the leading ranking — Owner decision challenge (O123, O200). In the max-effort ranking the Coding Agent Index is an admitted basket component whose cost is produced inside vendor agents (Codex, Claude Code, etc.), while every quality leaf comes from AA's bare-model runs, and the draft itself reports the agent-priced share spanning 16–74% of basket cost across rows. AA's own methodology confirms the agent index blends model, harness and agent behavior into one pay-per-token figure. The value score therefore attributes agent harness efficiency (or waste) to the model in exactly the ranking that "leads" the site and README. What is new versus the ledger: the S2 harness stress (O123) is unevaluable today and will stay unevaluable whenever AA lists each model under one agent, so the mitigation that exists cannot bind; meanwhile an uncontaminated cost basis already exists in public and in the build — the six Index SDLC evaluations, which are exactly the AI Coding Daily ranking's admitted basket and are already the subset workload MiMo-V2.6-Pro is scored on. Recommended change: publish, each release, a bare-model API re-ranking of the max-effort rows using the six-evaluation basket under the same anchors, with value and rank deltas beside the headline (diagnostic-tier, scores unchanged, like E187/E205 rebuilds). Zero new capture is needed.

Medium

Terminal-Bench priced twice, quality-credited once, with a differential distortion — Owner decision challenge (O24). The basket prices Terminal-Bench 4.0 once as an Index component and again inside the pooled Coding Agent Index cost, while the quality side credits it in a single leaf. The ledger records "both priced executions stay; overlap disclosed"; the new argument is that the distortion is not a uniform additive disclosure: because the agent pool's share of basket cost varies 16–74% across rows, the duplicated execution reweights relative (ratio) costs between rows differentially, and the size of each row's duplication is publicly unquantifiable because the pooled agent cost cannot be decomposed (the same non-separability the draft registers for SWE-Atlas QnA). Recommended change: do not re-litigate O24; add a per-execution-family "cost share vs quality weight share" table per release (family cost share of basket versus the family's quality weight, flagging ratios above 1.5, echoing the matched-cost warning algebra), so the asymmetry is quantified per family rather than acknowledged in one sentence.

Separability threshold omits a computable cost-noise component — new point, not a repeat. The draft honestly states that omitting cost noise narrows the O39 threshold and overstates the separable count (E340), and excuses it because "no public cost SD exists". That excuse is only partly right: the accounting identity in Part 3 reconstructs Index totals as Σ cost per task × task counts with ≤10⁻⁶ relative error (E209/O175), which means per-task cost vectors are captured; AA also publicly exposes per-task costs on its coding-agent pages. An empirical per-task cost dispersion is therefore computable for at least the six Index evaluations. Today the printed separability ("2 of 7" and "0 of 19" adjacent API ranks) is read by users as evidence about the ranking, and its most controllable bias is left untreated while a grid is offered only for the unobservable correlation ρ. This is not the rejected "precision-aware weight shrinkage" (which touched score weights); this touches only the separability statement. Recommended change in Section 2, item 1.

Low

Unrewarded-cost disclosure uses an equal-cost point estimate where the draft itself states the bound is [none, all]. The SWE-Atlas QnA share is printed as "about 43%… on the labelled assumption that every task costs the same", with the true range acknowledged in prose only. Recommended change: print the numeric bracket [E203 share, E203 share + pooled agent-index share] per row; the point estimate may stay, labelled as it is.

Cohort framing reads ambiguously at the top of Part 2. The first bullet describes the 27 plotted configurations "at the cutoff… from 9 families", which reads as the cohort definition, while the operative cohort is 37 configurations (plotted ∪ retained, E310) over what later emerges as 15 families ("9 of the 15 cohort families"). The text is eventually consistent, but the opening count invites misreading of every downstream number (admission thresholds, retained-row diagnostics) that keys off cohort size. Recommended change: state "the cohort holds 37 configurations: 27 plotted plus 10 retained under O145" in the first sentence.

Plan-basis presentation ordering. The headline Outputs lead with Plan row counts, flag counts and overlap arithmetic before any API-basis claim appears, and the Plan basis currently supports no claims at all (0 of 30 and 0 of 74 plan rows identified). The disclosures are required by the ledger; ordering is not. Recommended change: present the API claim-bearing outputs first and the Plan exploratory block after, so the README default view leads with what the methodology can actually support.
