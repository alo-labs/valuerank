## 1. Findings by severity

**Critical**

None.

**High**

None.

**Medium**

1. **E268 couples the AI Coding Daily leaf to Bug Hunt harness selection** . Issue: the AICD row for a twice-listed configuration is chosen by the harness name of its Bug Hunt record, so a Bug Hunt refresh — a new larger-N run on a different CLI under E206 — can flip the AICD leaf "although no AI Coding Daily row changed." E268/E334 are adopted and disclose the mechanism, but the new argument is the error channel: the two leaves' selection errors become correlated, while S1T's noise treatment is per-leaf (the only cross-leaf dependence stress is LiveBench's E354/E356), so a single harness churn event can move a configuration's composite by more than the published noise bands imply. It also prefers a harness match over a later test date, favouring stale evidence. Why it hurts: the objective is a defensible public value ranking; quality swings driven by selection churn on a different board are not model-value signal. Change: either decouple (order selection as documented default harness for the model, then latest test date, keeping `alternates` published) or keep E268 and add a coupled-selection stress to S1T: flip both affected leaves to their alternates and recompute separability, plus a per-release selection-flip counter in the manifest.
2. **The O193 asymmetric migration path is specified but unbuilt** . Issue: the draft states that when API references pass and Plan references do not, the API basis should migrate alone with the Plan basis reading "unavailable for the new version" — but "the build does not yet carry that path and stops as above." Why it hurts: O157 needs ≥2 measured Plan rows, so a single Plan-reference lapse at the next workload migration would hold both rankings' release, contradicting O193's intent and delaying the public ranking on a state the methodology already decided how to handle. Change: implement the O193 branch, with fixtures for the asymmetric output (Plan outputs labelled historical, no anchor from assumption/fallback/expired evidence), before the next workload migration; until built, name this stop-state explicitly in the release runbook so it is not mistaken for a gate failure.
3. **The joint adverse stresses are buried in diagnostics while the headline carries one noise margin** — *Owner decision challenge* to O44/O128 . Issue: the single noise margin rests on per-leaf SDs, including LiveBench's independence approximation with task counts carried over from the 2026-10-14 release; the conservative instruments that bound these approximations (√7 liveBenchDependence, the half-count √2 bracket, jointAdverseStress at LiveBench √14) exist only in `scores.json` diagnostics. What is new versus O128's settlement: E356's jointAdverseStress postdates it and bundles channels the single margin was never designed to carry, and E354 quantified the LiveBench dependence envelope after O128. Why it hurts: a reader using the margin to judge adjacent-rank separability can be overconfident exactly where several approximation channels fire together — on a 15%-weight leaf. Change: print the jointAdverseStress separability count (and the √7 dependence reading) beside the O171 noise companion; this is a disclosure addition beside the margin, not a second margin.

## 2. Methodology design recommendations

Prioritised, all implementable from public data:

1. **Coupled-selection stress for Bug Hunt × AI Coding Daily** (pairs with Medium 1): in each release's S1T run, recompute separability with every configuration that has an E268 alternates list flipped to its alternate row, and report the count of adjacent-rank pairs whose separability changes. Data: `data/swe_tracks.json` `alternates`, already captured.
2. **Build the O193 asymmetric-migration branch now**, with the two existing stop-state fixtures plus one asymmetric fixture: two API references, one measured Plan reference, output showing Plan outputs labelled "historical" and the API basis migrated. This converts a known release-blocking gap into a tested path.
3. **Surface jointAdverseStress in the published noise companion**: beside the O171 margin, print "adjacent ranks separable: N (single-margin basis) / M (joint adverse stress)" and the LiveBench √7 reading. Pure presentation over existing computed values; no score changes.
4. **Cross-basis non-comparability statement** with the already-published per-basis cost-doubling table repeated in the headline section, so a Plan-vs-API value comparison is explicitly ruled out.
5. **Ratify or pre-register the Bug Hunt equal-N preference** (provider-native harness first, then largest-N, then recorded reason), removing the pending owner-review reason.
6. **Cohort-relative Bug Hunt scale diagnostic** (optional): beside `bugHuntScaleStress`'s ±10%, publish the leaf recomputed with P_max/U_max over cohort rows only. This shows sensitivity to live-board composition (non-cohort models moving the scale) beyond the ±10% stress, at zero new capture cost.
7. **Anchor identity digest** (Low 1): include a references digest in the anchor object id in scores.json `workloads`.
