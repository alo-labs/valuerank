**Low**

1. **Numerical error in the S1T precision note (E353).** Part 11 states the O142 Beta draw's SD is smaller than the plug-in SD "by a factor √(n/(n+2)) (1.5% at 66 tasks, 0.2% at 1,000)." At n = 66 the SD reduction is 1 − √(66/68) ≈ 1.5% (correct), but at n = 1,000 it is 1 − √(1000/1002) ≈ **0.1%**, not 0.2%; 0.2% is the *variance* reduction at n = 1,000, so the parenthetical mixes SD and variance framings. This hurts the objective only mildly (it is a disclosed descriptive constant, not a scored quantity), but a published precision statement that misstates its own magnitude invites reviewer churn. **Recommendation:** correct to ≈0.1%, and render such derived parenthetical constants from the build rather than hardcoding them, the same way E265 renders figures.

2. **Ambiguous kernel-assignment clause closing the S1T leaf enumeration.** The long S1T sentence specifies bespoke kernels for LiveBench 2.0 Overall ("never a binomial or Beta draw"), Bug Hunt (composite planted/unplanted kernel, E326/E309) and AI Coding Daily (n = 6 judged points), then ends with ", each drawn as above (a binomial leaf from its Beta posterior, O142)". Read literally, "each" can be taken to override the bespoke kernels just specified. In a section titled "executable specification," an ambiguous kernel assignment is a build-drift risk: an implementer following the closing clause alone would draw LiveBench and Bug Hunt from Beta posteriors they must not use. **Recommendation:** restate as "each *binomial* leaf is drawn from its Beta posterior (O142); LiveBench 2.0 Overall, Bug Hunt, AI Coding Daily, AA-Omniscience, GDPval-AA and the Vals boards keep the kernels stated above."

## 2. Methodology design recommendations

1. **Publish a cost-noise stress bracket beside the O42/O128 noise margin (named S2 branch; highest value).** Part 12 concedes that the separability threshold "draws quality noise only," that AA publishes one cost run per configuration with no per-task cost dispersion, and that the net direction of omitting cost variation "is not established." This is the one place where the value score (25% cost) has no uncertainty counterpart while quality has an elaborate one. A public, refreshable calibration exists: paired per-attempted-task cost disagreement between AA's Index run and the Coding Agent Index on shared configurations (E285 already publishes these side by side; both metrics are defined comparably — mean pay-per-token API cost per task including cache pricing, missing telemetry excluded ). Concretely: compute s = the SD of paired log-cost differences on shared rows; in a named S2 branch draw a per-configuration log-cost multiplier ~ Normal(0, s²) (shared within a source, independent across rows), restate the separability pairs, noise bands and the O44 margin under it, labelled a specification stress. This does not claim deployment-level truth (the draft correctly declines that), but it bounds how much of the 0-of-N separability result is cost-side fragility rather than genuine quality indistinguishability. It changes no score and respects O128 (the single margin stays; this is published beside it, like the O154 recentred alternative beside S1T). 2. **Render the attemptCheck figures (Medium finding 1).** The gate is the ranking's label-issuance policy; its current reading belongs in the section text with the same build-rendering discipline as the τ_b values already printed.

4. **Disambiguate the S1T closing clause (Low finding 2)** — a one-sentence editorial fix that removes the only reading under which the executable specification contradicts itself.

5. **Prioritise capturing AI Coding Daily's per-project points.** The draft already publishes both readings (n = 6 wide, n = 60 narrow) and states the replacement rule, but the reported swing is material — median threshold 4.48 → 3.12 API, 0-of-19 → 1-of-42 separable — and it is currently the widest single assumption in S1T.
