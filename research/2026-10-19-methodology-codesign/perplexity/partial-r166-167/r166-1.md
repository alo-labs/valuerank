## 1. Findings by severity

**Critical**

None.

**High**

- **H1 — The E203 "unrewarded share" disclosure omits FrontierCode 1.1 Main inside the Coding Agent Index.** Part 3 states that inside the index "SWE-Atlas QnA (124 of its 290 tasks) has no quality leaf either… about 43% (124/290)", while the same bullet establishes that the index's FrontierCode 1.1 Main (100 tasks) is "a different version and task set from the Index's FrontierCode 2.0, so the two components never price the same tasks". The quality leaf is FrontierCode 2.0 only (registered version in E237), and the draft's own exact-variant policy forbids credit transfer between versions. So on the methodology's own logic, FrontierCode 1.1's cost buys no credited quality either: the within-index unrewarded share is (124+100)/290 ≈ 77% on the same equal-cost reading, not 43%. With the index spanning 16–74% of basket cost in the max-effort ranking (the only ranking admitting it), the printed median unrewarded share materially understates how much price buys uncredited work — the exact transparency E203 exists to give API buyers. *Recommended change:* extend E203's within-index enumeration to every sub-benchmark without a registered-version quality leaf (today SWE-Atlas QnA and FrontierCode 1.1 Main; Terminal-Bench 4.0 stays rewarded via its same-version leaf), print the combined task-share reading (77% equal-cost) with the same [0, all-of-index-cost] non-bound caveat, and build-check the enumeration against the index manifest (O64) so a future sub-benchmark change cannot silently re-introduce the gap.
- **H2 — The frozen a4 anchor references are stale under the methodology's own eligibility rule, because a rule change (O175), not new data, reclassified the three Claude Opus 5.5 rows to "confirmed complete".** Part 4 admits this directly: "the frozen a4 anchor references were set while those rows were unresolved, so they stay out of the anchor references until the next versioned re-freeze". Every cost score, the exchange rate, and the E60 disclosures rest on those anchors, and the excluded rows are a frontier family's primary configurations. This is not a repeat of the rejected "loosen the freeze" argument: the new point is the *trigger type*. O120/O169/E184 freeze anchors against data movement between freezes, which is sound; here the underlying cost observations did not change — the completeness *legal test* did (O141's 10⁻⁶ → O175's 0.1%), so the anchor object is now demonstrably mis-specified under the rules currently in force, which is the same category of defect the E120/O65 re-capture logic already treats as cutoff-moving. *Recommended change:* add a narrow correction path — when an owner or editor rule adopted between freezes changes a row's FullCost/anchor eligibility on unchanged evidence, permit a dual-run-checked anchor correction within the release that adopts the rule (or, failing that, print the corrected anchors' exchange rate and every rank delta beside the frozen ones as a first-class output, not only inside the E187/E205 diagnostics which rebuild on different populations).

**Medium**

- **M1 — The O175 materiality band is expressed relative to the Index total, but the scored quantity C_W is built per component, so a "passing" residual can be a large component-level error, and the Opus residual is systematic.** Part 3 records that all three Opus 5.5 rows overshoot AA's published total by 0.03–0.04% with the same sign — "a pattern and not noise" — while "locating the excess would need a per-evaluation total beyond the six component costs AA lists, so its cause stays unregistered". 0.04% of the nine-evaluation total, if concentrated in a small component (e.g. GDP.pdf, 100 tasks), can be several percent of that component's cost, and it enters C_W with unknown direction. *Recommended change:* publish the residual-as-worst-case-component-concentration sensitivity — for each admitted component, the value-score shift at d value points per cost doubling if the entire residual sat in that component — and register candidate causes against the capture (e.g. the v5 catalog's "excluding repeats" cost definition interacting with per-task means), retiring the discrepancy when identified rather than carrying it indefinitely.
- **M2 — The selected SemiAnalysis analysis, the sole controlled-measurement donor for every Claude and Codex Plan route, enters the evidence bundle only as a manual transcription, not as an E159 "permitted capture".** Part 5: "the article itself is not captured in the evidence bundle, so no content hash is published". E159's own contract contemplates restricted-redistribution sources via a retained permitted capture with published hash and locator; a typed transcription has no integrity link to the source, so the O130 monthly re-read compares the article against the transcription, not against an anchored artifact — a transcription error made at selection is invisible to every later check, and no third party can audit the chain. *Recommended change:* retain a dated permitted capture of the figure table (screenshot or saved HTML kept private) with its hash and field locators published in the bundle; the O130 re-read then verifies against that capture, and any transcription drift stops the build like an E18 change detection.
- **M3 — Owner decision challenge — O24 double-prices Terminal-Bench 4.0's 66 tasks, distorting the workload composition, not merely adding an overlap to disclose.** The ledger shows the overlap is disclosed; the new argument is compositional: the basket is meant to price one deployment-equivalent pass of an SDLC workflow, yet the same 66 tasks are priced twice in two deployments (bare model in the Index, vendor agent inside the Coding Agent Index) — two execution modes a single API buyer does not simultaneously purchase for the same task population. Adding Terminal-Bench-Science's terminal-execution cost (E343) on top tilts the 25% cost leg toward terminal tasks beyond any stated demand model, inflating the printed coding-share medians and overweighting models that are cheap specifically on terminal workloads. *Recommended change if the owner re-opens it:* count the Index-run Terminal-Bench cost toward the workload and the vendor-agent-run cost as a *deployment-differential* diagnostic (agent overhead Δ per task), which preserves O123's "agent is part of the costed configuration" without duplicating the task pass; the Δ diagnostic is strictly more informative to the API buyer choosing between bare-API and agent-mediated use.

## 2. Methodology design recommendations

Prioritised; all are implementable from data the pipeline already captures or can retain.

1. **Correct and formula-ise the unrewarded-cost disclosure (fixes H1).** Per within-index sub-benchmark b: unrewarded share u_b = 1{k:b has no registered-version quality leaf}; equal-cost reading U_eq = Σ u_b·n_b / Σ n_b with total bound [0, s_i]. Add a manifest-driven build check that the numerator task list equals the O64/O148 unit registry, so the disclosure cannot drift from the index definition.
2. **Anchor-staleness correction path (fixes H2).** Trigger: a tagged rule adopted since the last freeze flips any row's E209/E170 anchor eligibility on unchanged evidence. Procedure: dual pre-registered run (E197), publish both anchor objects, exchange rates and rank deltas; adopt the corrected anchors only via owner sign-off inside the same release. Precisely scoped so it cannot be used to smuggle data-driven re-freezes past O120.
3. **Component-concentration residual stress (fixes M1).** For a row with residual r and component costs c_e: worst-case cost-score shift = d·log2(1 + r/c_e) per admitted component e, printed with the reconciliation record; if any shift exceeds that ranking's median separability threshold, the row's completeness status is published with the caveat.
4. **SemiAnalysis permitted capture (fixes M2).** One retained artifact + published hash per selection and per O40 addition; closes the only non-reproducible input in the bundle.
5. **Family-roster print (fixes L2).** Roster JSON: plotted families, retained-only families, union; build-checked count.
