Medium

Harness-span sensitivity flags are implemented only for bar answers in this section. E29/O162 publishes bugHuntHarnessSensitivity.labelFlags only for “a bar whose displayed-record cheapest configuration changes between the two ends,” while the same sensitivity machinery measures rank movements. The confirmed-cheapest label, K_r membership, frontier interval labels and the scenario-supported label all read the Bug Hunt leaf, yet no harness-end reevaluation is specified for them here. Why it hurts: a reviewer-facing “confirmed cheapest” row could rest on a leaf whose cross-harness spread (the draft itself cites a 40.7 vs 33.0 spread, E224) would flip the label, with no flag telling the reader. Recommended change: extend the sensitivity to recompute every label type whose inputs include a multi-harness Bug Hunt record at both harness ends, and flag any label that flips (reusing the existing branch machinery so it stays a named sensitivity, not a Θ change).
draft-r234-part-15-of-17.md

The Plan capacity solver has no registered grid-convergence rule. E39 fixes a 15-minute default grid, permits an “event-aligned grid,” and substitutes a “documented feasible conservative schedule” when enumeration is infeasible. Whether a route achieves point identification (lower = upper) can therefore depend on grid choice and on when the solver gives up — and no pre-registered compute budget or refinement stopping rule exists in these parts, unlike the kernel checks’ resource caps (E77). Why it hurts: whether M_W is identified gates Plan interval eligibility (E106), so a grid artifact could move a route between “identified” and “conservative achievable capacity only,” inconsistently across routes. Recommended change: register successive grid halving until feasible_lower_bound moves less than a stated tolerance (e.g. 1%), a per-route compute budget whose exhaustion is itself a published status, and the lower/upper gap percentage printed on every route record.
draft-r234-part-15-of-17.md

No cadence is registered for scoped change detection between releases. These parts define E18/E228 flagging, monthly cadence for freshness, and a weekly watch only for SemiAnalysis articles. A mid-cycle limit, price or credit change is detected only at the next build. This matters in practice: real subscription quota semantics shift without notice and are ambiguous even between public sources for the same vendor — Claude’s plans, for instance, layer a session-anchored 5-hour window under a weekly cap whose reset is variously documented as account-assigned fixed-day and as a rolling 7-day budget, exactly the ambiguity E115 anticipates. Why it hurts: the published Plan ranking can carry an unflagged superseded route for weeks despite the machinery to flag it existing. Recommended change: register a weekly automated scoped-diff monitor (pricing tables, rate-limit sections, availability matrices) emitting a flag-only bulletin — no mid-cycle re-rank, so O12/O25 are untouched — with detected changes folded into the next release via the existing E18/E228 path.

2. Methodology design recommendations

Prioritised, all implementable from routinely refreshable public data:

P1 — Label-flip harness sensitivity (from finding 1). Procedure: for each decision reading a Bug Hunt record with multiple harnesses, re-run the decision with the leaf at its lowest and highest harness records; publish labelFlags: [{decision_type, label, flips_at_low, flips_at_high}]. This extends existing build machinery rather than changing Θ or O25.

P2 — Capacity-solver convergence protocol (from finding 2). Formal: grid sequence g₀ = 15 min, g_{k+1} = g_k/2; stop when |L_{k+1} − L_k| / L_{k+1} < 0.01 or a registered compute budget exhausts (publish status “budget-exhausted”); carry [L_final, U_relaxed] into Θ as the structural bound; print the gap (U − L)/L on each route.

P3 — Plan evidence currency as a headline statistic. The lifecycle counts already exist (21 of 30 and 60 of 74 possibly-superseded-or-worse; staleListed rows). Promote a per-ranking “currency composition” (shares current / possibly superseded / expired-in-grace / fault-window / ceiling-derived) onto the Plan headline table, beside O166’s coverage share, so the official Plan order visibly carries its evidence age.
draft-r234-part-17-of-17.md

P4 — Weekly mid-cycle monitor (from finding 3). Snapshot the registered scoped sections weekly (same diff/classification logic as E18: a moved, renamed or vanished section is a change to classify), emit a flag-only bulletin, and reset no clocks; fold results into the next release.

P5 — τb power labels (from Low finding 2). Pre-register: if the configuration-bootstrap CI width for (a) or (b) exceeds a fixed bound (e.g. 0.5), print “low-powered” beside the statistic; keep the model-identity cluster bootstrap (E329) as the primary interval where it differs, since multiple efforts per model invalidate row-level resampling — τ_b is the right statistic here precisely because these panels are small and tie-heavy.
