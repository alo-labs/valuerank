The O64 manifest's closed-world guarantee has a capture hole for exactly the rows most likely to be new. The capture keeps only row objects carrying "an id, a display label and a cost or evaluation block", so a row AA lists with an id but no label or cost block — the typical state of a newly added, not-yet-priced model — is never captured, never reaches the manifest, and never trips the O64 stop ("the build stops when a captured row is not registered"). If such a row is a cohort configuration, it silently becomes a missing-cost subset row instead of forcing an editor classification, and the draft's claim that "the manifest sees every row AA lists" is false for these rows. This weakens the refresh safety net the 0.1% reliability of routine refreshes depends on. Recommended change: make the capture predicate "has an id" (keep label/cost as optional fields), extend the manifest's reason vocabulary with "not yet priced/labelled", and let the existing stop fire on any unregistered id-bearing object.

Low

Owner decision challenge (O158, new argument): the fallback re-pricing ends omit cache price classes that dominate the cost being re-priced. The re-pricing moves the fallback share "at the lower and the higher of the input and output price ratios", but AA's own coding-agent cost model is explicitly cache-priced — per-token pricing "including cache write pricing and cache discounts where available", combined with live measurements of typical cache hit rates. For agent-driven spend, the cache-read and cache-write ratios can lie outside the input/output bracket, so the published ends may not bracket the true re-priced cost. Recommended change: extend the two ends to the min and max over all published price-class ratios (input, output, cache read, cache write) from the same data/fallback_prices.json and the row's own price list; still a scores-unchanged sensitivity.

E140's lexicographic order (component count before panel size) can trade cohort coverage for components without the reader seeing the trade-off. A set of many components each barely clearing ⌈2N/3⌉ beats a smaller set covering the whole cohort, maximizing subset-row prevalence. The feasible alternatives are already enumerated, so the fix is free: publish, per ranking, the coverage–component frontier of feasible alternatives (admitted components vs |P(S)|) beside the existing admission object.

"Pending capture" mislabels a coverage problem as a capture problem (E26). ITBench-AA has exact cost for 2 of 9 max-effort rows — captured, but below threshold — yet is listed "pending capture". Recommend "pending admission (coverage x/y)" so a reader can distinguish un-captured evidence from thin coverage; the marginal-coverage table already carries the numbers.

O63 leaves a free capture-fidelity assertion unused. AA publishes refusedAttemptCount alongside hardStopAttemptCount and fallbackAttemptCount; the draft deliberately uses only the latter two. Add a build assertion that refusedAttemptCount = hardStopAttemptCount + fallbackAttemptCount wherever all three are published, stopping (or flagging, consistent with O100's register philosophy) on a mismatch — a zero-cost check that the per-evaluation attempt sums were captured whole.

The Coding Agent Index's cost is a current-price restatement, and the boundary record should say so. AA reports coding-agent cost as "average pay per token API cost per task, based on provider token pricing", recomputed with current per-token pricing and live typical cache-hit-rate measurements rather than the as-run expenditure. Part 3 describes it as "the published record of one deployment-equivalent pass (E9)" without naming the restatement basis. Recommend adding a boundary-record field for the CAI (current-price, typical-cache restatement), so E170's valuation-gate readers know this component is always valued at prices in force.
