1. Findings by severity

Critical

None.

High

Plan-row multiplicity leaks configuration weighting into every Plan-level aggregate except identification yield. Under O48 the Plan ranking has one row per configuration × plan (today 30 rows for 9 configurations in max-effort, 74 for 20 in AI Coding Daily). The draft itself acknowledges that this "weights a configuration by how many plans its provider sells" and corrects it in exactly one place — identificationYield.configurationBalancedYield — but scenario shares, bar qualifier counts (E198), separability panels, the measured-only view (E65 panel), and the E164 calibration panel all still range over plan rows. A configuration on four ChatGPT plans enters the "cheapest above the bar" scenario draws and label tests four times; a Kimi configuration once. Why it hurts the objective: the Plan headline silently becomes a statement about configurations × provider plan-catalog depth, not about which model is best value, and two providers with identical per-plan value but different catalog depth get different headline outcomes. This is not settled in the ledger: E258/E248 only handle within-configuration tie-breaking and band occupancy, and nothing in the rejected-claims list covers configuration-balanced scenario or bar outputs. Recommended change: extend E61's one-unit-per-configuration weighting to scenario shares and bar qualifier counts (publish both row-weighted and configuration-balanced versions, as E164 already does for anchors).

Medium

Quality is 66–78% single-vendor run, and only two leaves have a cross-source agreement check. Part 9 discloses the share of quality weight by data source: 66% AA-run (max-effort) and 78% (AI Coding Daily). AA leaves are not independent draws — they share one harness organisation, so a systematic evaluation fault (a scaffold change, a refusal-handling bug) moves most of the quality vector in the same direction for the same configuration, and the O42 correlation grid does not capture correlated source error. Cross-source agreement diagnostics exist only for Terminal-Bench (E229) and FrontierCode (E234). Recommended change: publish a headline flag when any single source exceeds a declared threshold (e.g., 60%) of quality weight, and extend the τ_b + mean-offset agreement check to at least one more independent-source leaf per release (GDPval-AA and Omniscience have third-party alternatives).

The 52/12 weekly→monthly conversion is declared not to establish billing-period capacity, yet it scores rows at a point value. Part 6 and part 7 both state the 4.333× factor is "an annualised display convention that does not establish capacity over any one billing period (reset phase and billing boundaries stay outside it)". But the converted weekly allowance is the admitted route value feeding Plan row multiples — i.e., a number the methodology says it cannot certify is used as the Plan cost denominator while interval machinery (O25, Θ) protects the published record everywhere else. Recommended change: carry the conversion uncertainty into the scenario layer as a range [4.0×, 31/7×] (29–31-day months against unknown reset phase), keeping the point value only for display. This is distinct from O19/O25 because it is a convention bound, not missing-evidence rounding.

Report pooling weights all observers equally regardless of measurement precision. A passing cell's value is the geometric mean of midpoints clipped to the O115 band, with each observer entering once (O174). An observer reporting one coarse meter fraction and an observer reporting per-token measurements over a full window contribute identically once clipped; a coarse interval's midpoint can sit far from the true allowance and pull the pooled value up to the band edge. Recommended change: inverse-halfwidth² weighting of log-midpoints within the clipped band (weights already computable from the recorded value ranges), with equal weights published as a sensitivity. Nothing in the ledger rejected precision weighting for the report pool (the rejected "precision-aware weight shrinkage" concerned quality-leaf weights).

Quality and cost read the same execution for Terminal-Bench, coupling measurement error across the two halves of the value score. Part 9 states the Terminal-Bench leaf is AA's own Index run "which is also the Terminal-Bench execution the cost basket prices, so quality and cost read the same run". If that run was anomalous for a configuration (harness flakiness, an AA-flagged refusal), both quality z and cost c shift together, and S1T/S1M treats leaf noise and cost noise as independent — understating value-score variance in exactly the tail the bars and labels rely on. Recommended change: add a named shared-execution correlation cell (e.g., ρ = 0.5) for Terminal-Bench quality-cost pairs in the O42 correlation grid, and/or price Terminal-Bench from the Coding Agent Index independent execution already retained under O24.

Low

The representative-row convention risks reading as a plan recommendation. A configuration's published Plan figures are those of its representative row (the comparator-winning plan); the README lists every plan row, but a reader skimming the configuration sees one multiple that is, in effect, the best plan's — while O22 retired all "recommended" machinery. Recommended change: print the configuration's plan-row multiple range [min, max] beside the representative figure, labelled "range over this provider's plans".

Owner decision challenge — Bug Hunt's live rescaling (O170/O173/O190) is the sole exception to the frozen-anchor principle the draft applies everywhere else. Part 9 requires that a change to any other leaf's anchors "is a methodology version with its bridge, never a silent re-derivation", and cost anchors are frozen per version with dual runs. Bug Hunt's denominator (P_max + U_max) instead moves every row's z each release from any model's new run, with only a ±10% stress printed. New argument beyond the ledger record: the draft now enforces frozen anchors three times in adjacent paragraphs (cost anchors E20/E247, quality anchors reviewer 77, O12 dual runs) — the live scale is a stated-principle inconsistency, and a third party posting one large run can flip two cohort rows' Bug Hunt ranks without any new evidence about either. Recommendation: freeze P_max + U_max within a methodology-version window and re-freeze via the same versioned-bridge path as leaf anchors.
