H1 — The agent effect in the max-effort cost is not merely currently unevaluable; under S2's own design it can be permanently unidentifiable, and public data now exists to bound it (Owner decision challenge, O123/O200). Part 3 charges the vendor agent's token use to the costed configuration, notes the S2 stress (log C = α_m + h_a, centred within connected agent groups) is "unevaluable while no model is listed under two agents", and states that a ranking pooled across disconnected groups is "not a common-agent counterfactual, since nothing observed fixes a baseline between groups". The new argument: if AA's agent assignment runs along provider lines (as the label grammar's examples — "Codex - GPT-6 Luna" — imply), the connected groups coincide with model families, so h_a is collinear with the model effect and no amount of future within-family two-agent data can fix a cross-family baseline. The stakes are concrete: the Coding Agent Index spans 16–74% of basket cost in the max-effort ranking, and public measurements show per-task token use varying by roughly 3–4× between major agents on identical tasks (e.g. ~1.5M vs ~6.2M tokens on a Figma-to-code task), with AA's own new Harness Comparisons surface reporting 5.6M–27M tokens per task and $0.11–$0.62 cost per task for the *same model* across harnesses. So the headline cost of the leading ranking carries an agent-confound plausibly comparable in size to model differences. Recommended change: (a) feed AA's Harness Comparisons (same model under many harnesses) into S2 as the source of h_a estimates, or as a prior where the S2 fit stays unevaluable; (b) print the agent-assignment table with an explicit "cross-family agent comparability unidentified" statement beside the max-effort ranking; (c) add a named scenario axis that rescales each row's Coding Agent Index cost by the harness-comparison spread for its model, labelled sensitivity. All of this is public data refreshable routinely, so it satisfies the implementation constraint.

M1 — Fallback serving-state consistency is enforced nowhere on the quality side, while the cost side is fully basis-gated. Part 3 says AA plots Claude Opus 5.5 and Claude Sonnet 5.5 only "with fallback", and that a third-party record silent on fallback "matches by model and effort, whichever way AA plots the model". The draft meticulously gates cost observations on valuation basis (E170, O29), so this is a one-sided asymmetry: the same class of basis mismatch that blocks labels on cost passes silently on quality. It hurts the objective because a value score divides a possibly no-fallback quality numerator by a with-fallback cost denominator (or the reverse in future captures). Recommended change: add a fallbackState field (with / without / silent) to the per-leaf evidence registry; where a family is plotted only with fallback and a matched leaf is silent, flag the row "quality leaf serving state unmatched" and publish a sensitivity that replaces that leaf with the provider's own result per the O36 ladder, or drops it, never changing the headline score.
