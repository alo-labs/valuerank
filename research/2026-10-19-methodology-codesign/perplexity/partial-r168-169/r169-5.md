**Medium**

1. **E268 couples the AI Coding Daily leaf to Bug Hunt's harness choice with no estimand basis.** The AICD row for a dual-listed configuration is selected by matching the harness name of its Bug Hunt record. Why it hurts: the two boards measure different things (Bug Hunt: TypeScript repos, vendor CLIs, model+harness estimand; AICD: Laravel/React-TS projects on Claude Code, Codex CLI, OpenCode, Devin or DeepSeek harnesses), so harness-name equality across them creates no comparability — it only imports Bug Hunt's largest-N selection noise into a different benchmark's leaf. A Bug Hunt scoreboard refresh can change a ranked row's AICD leaf, and thus its value and rank, with zero new AICD evidence; E334's replay explains the change but does not justify the rule. The fallback ("if no row or more than one row matches, the row with the latest test date") also shows the primary rule often cannot fire, so today's operative rule for unmatched rows is already a within-board one. Concrete change: select the AICD row by a within-board rule — the provider's own agent harness if the board lists one, else largest sample, else latest test date — and demote the Bug Hunt-harness agreement to a published diagnostic, removing the cross-leaf coupling entirely. Exact-variant evidence is unaffected: every candidate row still names the same model and effort.

2. **The ×2 anchor padding is the de facto cost–quality exchange-rate parameter, and no sensitivity to it is published.** c_L = min reference ÷ 2 and c_H = max reference × 2 fix ln(c_H − c_L) = ln(4·max/min), which alone determines how many value points a cost doubling is worth — and the parts show this differs materially across the four cells: 3.11 (max-effort API), 5.31 (max-effort Plan), 2.71 (AICD API), 4.11 (AICD Plan) value points per doubling. Why it hurts: the padding is presented as a technical convenience ("so the reference cohort itself never clips") when it is actually the parameter that sets how much cost differences matter relative to quality, and its effective value silently differs by basis and ranking because the reference populations differ. A reader comparing rankings cannot tell how much of a Plan-vs-API rank difference is anchor-range scaling rather than real cost differences. Concrete change: publish a `bugHuntScaleStress`-style diagnostic (O173 pattern) that recomputes S_C, value scores, ranks and bar answers with end padding ∈ {1.5, 3} instead of 2, per basis and ranking, changing no score — the same "named swing class" machinery already exists. (Note this is a sensitivity disclosure, not the rejected "recalibrating anchors to equalise influence": nothing is re-anchored.)

3. **E229's Terminal-Bench cross-source agreement has no minimum-panel rule, unlike E288.** The draft prints "τ_b 0.74 and offset +1.7 points on 5 rows" for the max-effort ranking and "undefined (panel too small)" for a 1-row panel, but draws no line between them. Why it hurts: Kendall's τ_b on n = 5 is essentially uninformative — even τ_b = 1.0 on five pairs is only marginally significant — and the offset it accompanies matters a great deal in this domain, because agent/harness choice is one of the largest score movers on Terminal-Bench-family tasks: audits report up to ~29.9 percentage points from changing only the harness, ~10-point macro spreads across 11 harnesses on the same models, and single-model contrasts such as 57.8% vs 52.1% and 32.6% vs 19.6% across harnesses. Printing an uninterpretable τ_b beside a gap-fill rule that mixes agents (Terminus 2, mini-SWE-agent, OpenHands, then vendor agents) understates this uncertainty. Concrete change: adopt E288's precedent (τ_b "from eight shared configurations up") for E229 — print "undefined (panel too small)" below n = 8, and always print n beside τ_b and the mean offset; optionally also print the per-agent composition of the matched panel, since a uniform offset cannot see agent-driven dispersion. ## 2. Methodology design recommendations

Prioritised, all implementable from public data within the existing build:

1. **Anchor-padding stress (from Medium 2).** Add `diagnostics.anchorPaddingStress` per basis and ranking: recompute S_C with end padding 1.5 and 3, replay value scores, ranks and bar answers under both, and publish the changed ranks and swing classes via the E177 replay. Zero score changes; the pattern is exactly `bugHuntScaleStress`.
2. **Decouple E268 (from Medium 1).** AICD row selection by within-board precedence: provider's own agent harness, then largest sample, then latest test date; Bug Hunt-harness agreement becomes a per-row diagnostic; E334's two-step attribution becomes unnecessary rather than merely automated.
3. **Minimum panel for E229 (from Medium 3).** n ≥ 8 for τ_b, following E288; always print n and the matched panel's agent composition. Also worth printing the E229 offset per agent pair when more than one agent appears in the matched panel, since the agent mix — not the model — can dominate the offset.
4. **Anchor-object stability diagnostic.** Per anchor object, publish reference count and the change in (c_L, c_H) across the last k re-freezes, and flag when the Plan span moves more than, say, 25% with unchanged evidence. E160's minimum of two makes each Plan re-freeze an extreme-order-statistic exercise on a handful of rows; the dual run exposes single-release swings but nothing shows drift across releases.
5. **Zero-cost branch and attempt-policy table (from Lows 3 and 5).** Both are one-line rule statements plus a manifest column.
