## 1. Findings by severity

**Critical**

None.

**High**

1. **The clipped-tolerance rule (E242/E272/E305) states its two operations in the direction that cannot change the row's value.** The rule says a row at cost C above the high anchor c_H "needs its multiple multiplied by (C/c_H)·2^(t/d)", and one below the low anchor c_L "needs it divided by (c_L/C)·2^(t/d)". With the cost score floored at 0 above c_H and capped at 100 below c_L (the draft's own regression test says cheaper never scores lower), a row above c_H only changes value when its multiple *falls* — by exactly (C/c_H)·2^(t/d), since the cost must first cross c_H (the "flat clipped stretch absorbed first") and then fall t/d further doublings; a row below c_L only changes value when its multiple *rises* — by (c_L/C)·2^(t/d). Both verbs are therefore swapped relative to the direction the same sentence declares ("the one direction that can change its value... the other direction moving nothing"), and the closing existence condition (2^(t/d) > c_H/c_L ⇒ "threshold exceeds the whole cost scale") matches the corrected derivation, not the text as written. This hurts the objective because this tolerance is the only published robustness measure for the assumption-based Plan rows that currently make up the entire Plan ranking; a reader applying the text as written learns the wrong direction of fragility. Recommended change: swap the verbs (above c_H: divided by (C/c_H)·2^(t/d); below c_L: multiplied by (c_L/C)·2^(t/d)), or restate as "the multiple can fall/rise by at most a factor of X before the value moves by t", and add a build-side direction test (raising an above-anchor row's multiple must leave its value unchanged; lowering it by the published factor must move it by ≈ t). If the build already implements the correct direction, this is a text–code divergence, which the draft's own preamble calls a defect.

## 2. Methodology design recommendations

1. **Highest priority — a published Plan evidence-gap table plus an M_W submission spec.** The Plan basis is the objective's differentiator, and today it supports no claim at all (no route has an identified M_W; 0 of 30 and 0 of 74 plan rows are API fallback; every measured-route row carries a flag). The bottleneck is evidence supply, and the machinery to fix it already exists (O71 staged search, O81 `data/plan_reports.json`, O124 hashed artifacts, O164 monthly per-cell research, E166 measurement objects, O126 meter denominations). Concretely: each release publishes a generated table of model × plan cells with the last three-stage search date, the reports held, and the exact artifact that would identify M_W for that cell (meter denomination, model-attributed consumption over a stated period, allowance consumed, per E166/O126); and a one-page public spec for O124 submissions describing the hashing recipe and qualifying formats. This converts the staged search from a private routine into a directed, community-assistable pipeline — implementable entirely from public data and the existing build.

2. **Cost-noise diagnostics from public doubles, feeding the separability statement.** Part 1 concedes no public cost SD exists and that omitting cost noise narrows the separability threshold (E340). Two implementable bounds: (a) the two priced Terminal-Bench executions (O24: the AA Index run and the Coding Agent Index vendor-agent run) give two independent cost observations per shared configuration — publish the per-row ratio distribution as an order-of-magnitude cost-noise bound, labelled structural and confounded by agent harness (E123/S2); (b) E172's leave-one-component-out cost family already exists — publish the value-rank spread under leave-one-component-out recomputation as a cost-model-sensitivity band beside each ranking. Neither claims a sampling cost SD; both quantify how much the admitted "no cost SD" concession actually costs.

3. **The cohort-gate mismatch diagnostic** (Medium 3 above): catalog configurations outside the gate, their general-Index gaps, their available SWE-leaf indicative quality and cost, and a count of near-misses on a SWE-value reading. Cheap, public, and directly informs whether the O51 gate truncates the objective's answer set.

4. **Pre-registered Vals migration checklist** (Low 1): a registry entry naming v1.1.1, its grader change, and the two permitted outcomes (versioned migration with anchor re-freeze and dual run, or pinned-and-labelled archive), so the E237 stop resolves in one decision rather than a stalled release.
