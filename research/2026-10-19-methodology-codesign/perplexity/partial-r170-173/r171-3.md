**Medium**

1. **OpenCode Go has no closed-world, build-checked manifest.** Part 6 admits OpenCode Go routes from "the plan's page archived with its SHA-256", but unlike the Coding Agent Index (O64: the build stops on an unregistered row) and the Terminal-Bench agent list (E225), nothing registers *which* models OpenCode lists, and the per-model pricing caveats (DeepSeek at peak prices, Gemini 4 Argon at list while the launch discount would double it, Haiku 5.5's 5× long-context tier, the 1.5–2× tier for the model named "GPT 6 Luna") are narrated in prose rather than carried as data. This hurts the objective because a page change silently adds or removes official Plan routes between releases — breaking release-to-release comparability of the Plan ranking — and the "optimistic for long requests by that factor" adjustment is unauditable. What is new versus the ledger: O64 and E225 established exactly this pattern for two other sources; O198/O199 (recent) introduced OpenCode Go with no equivalent. Recommended change: a versioned manifest (roster name, tier factor, price basis, dollar limit, fee) with SHA-pinned rows; the build stops on an unregistered or hash-changed row until a logged diff names what changed; the tier-adjusted multiple is computed from manifest fields, not narrated.

2. **Nothing forces an owner decision before the selected SemiAnalysis analysis expires.** E238 pins every Claude/OpenAI controlled measurement to the 2026-10-07 selection; the watcher for a later analysis is explicitly "report-only"; O130 only fails the build when the re-read is stale; and part 5's own clock expires the analysis on 2027-01-05, demoting it 2027-02-04. If no re-selection happens, all Claude/OpenAI Plan routes fall to API-cost fallback at once — the Plan basis (O3, full-utilisation Value Multiple) degrades on a calendar trigger, not an evidence event, and the only visible signal is the age dates buried in the evidence section. New versus the ledger: O130 governs re-reads, and the watcher's existence is recorded, but no decision-forcing mechanism before expiry appears anywhere in the ledger. Recommended change: at 30 days before the selected analysis's expiry (and on every E18-detected change to it), the build publishes an owner-decision notice enumerating later analyses the weekly watcher has found; the owner logs select-or-renew; notice-only, no release hold.

3. **The ≥2-reports admission tier has never fired, and no aggregate view shows why.** Both staged searches (2026-10-25 and 2026-11-05) "found no model and tier with two independent reports agreeing within the O11 margin over its comparability partition." E107 publishes per-route included/excluded report IDs with reasons, but there is no per-release aggregate funnel. This hurts the objective because the end-user-report tier is the Plan side's only structural redundancy against single-source dependence on one paywalled article; without a funnel, the owner cannot tell whether the binding gate is O11's ±20% concordance, E102's comparability-record requirement (a "public comparability record" is a high bar for forum posts), or simple observer scarcity — so the tier cannot be tuned on evidence. New versus the ledger: E278 is a coverage gate (build stops on unsearched cells); E107 is per-route; neither gives the aggregate. Recommended change: publish per release a funnel over all model × plan cells — reports discovered → excluded by reason code → comparable partitions → concordance pass/fail — plus the distribution of near-miss concordance ratios (largest/smallest), as diagnostics only, never labels.

## 2. Methodology design recommendations

Prioritised, all implementable from routinely refreshable public data:

1. **OpenCode Go closed-world manifest (pairs with Medium 1).** Fields: roster name (exact catalog spelling), tier factor, price basis (peak/list/discounted with dates), monthly dollar limit, plan fee, page SHA-256, capture date. Build rules mirroring O64/E225: stop on an unregistered row; stop on a hash change until a diff is logged and typed (limit, price, credit, availability, metering, reset — the existing record types); compute the tier-adjusted multiple and print the long-request optimism factor per route from the fields. This turns the prose caveats into computed, flagged quantities consistent with O125's "optimistic end" labelling.
2. **Selection-lifecycle decision gate (pairs with Medium 2).** Trigger: T_expiry − 30 days for the selected analysis, or any E18-detected change to it. Output: an owner-decision notice listing detected later analyses (from the watcher log in Low 2), the affected routes, and the expiry dates; the owner logs "re-select (URL, date)" or "renew (reason)". Default semantics: notice-only, no O12 hold, since expiry itself already has a defined degradation path.
3. **Report-admission funnel (pairs with Medium 3).** One table per release: cells searched, reports discovered, excluded by each reason code (independence, comparability, observation date, post-search date, alias resolution), partitions formed, concordance outcomes, and near-miss ratios (e.g., pairs failing at 1.20–1.35×) as scenario-layer diagnostics under the O19 boundary (analyst-side quantities never enter interval outputs). This is the Plan-side analog of E201's qualifier counts.
4. **Watcher logging (pairs with Low 2).** Record the weekly search (queries, sources reached/unreachable, findings) as `sourceEvidence.semianalysis.watcherLog`, aligned with the O130 re-read records.
5. **Plan-side flag-coverage print.** Beside the label qualifier counts, publish the share of Plan rows whose selected route carries a change flag at this release (currently, per part 6, every SemiAnalysis route is flagged). With O196's open-ended hulls for unclear-direction changes, this makes label scarcity on the Plan side self-explaining to readers rather than looking like a build defect.
