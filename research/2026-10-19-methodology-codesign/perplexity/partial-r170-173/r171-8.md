## 1. Findings by severity

**Critical**

None.

**High**

None.

**Medium**

1. **Session-end semantics are undefined in the governing Plan capacity formula (E39/E30).** The schedule contract defines when a session *starts* ("the first consuming step after the previous session ends") but never what *ends* a session — idle timeout, explicit close, or never. For a session-anchored window (e.g. a 5-hour cap per session), capacity differs by an order of magnitude between "one session per fee period" and "a session ends after every gap", so a point identification M_W could rest on an unstated assumption. This hurts the objective because the Plan Value Multiple is the headline Plan number, and an unidentified-but-asserted capacity would be a silent bias, not a disclosed bound. E115's admissible-semantics set S_r covers reset *mechanisms*, but session end is an intra-mechanism parameter the current text does not place in S_r. **Recommended change:** extend the E115 record with a session-end field; where no end rule is publicly established, bracket with the two extremes (session persists for the whole horizon; session ends after any non-consuming gap), carry the resulting [lower, upper] as a structural bound on M_W, and permit a point only when they coincide — plus a fixture where two admissible end rules give different capacities and no point is identified.

2. **Scenario draws remain coupled to the Python version, and no bridge covers scenario-share shifts.** The draft's own mitigation — recording the drawing Python version in `scenarios.generator` and treating a version change "like a change of draw order" — is correct as far as it goes, but a Python upgrade between releases can shift scenario shares (the only place run-to-run noise lives under O25) with no named cause, since E177's swing gate covers scores, not shares. Python's docs guarantee only that `random()` produces the same sequence for the same seed; the other samplers (Beta, normal) are explicitly subject to change across versions. **Recommended change:** define every scenario sampler as a documented deterministic transform of `random.random()` alone (e.g. inverse-CDF Beta, Box–Muller on `random()` pairs), so the guaranteed-stable primitive is the only dependency; do *not* migrate to NumPy's `Generator`, which carries no cross-version stream-compatibility guarantee. Until that lands, name the Python version among the bridge causes for scenario-share changes. [docs.python](https://docs.python.org/3/library/random.html)

3. **Owner decision challenge (O52/O53/O166): ranking coverage has no cumulative trigger.** The max-effort ranking ranks 9 of 37 cohort configurations and the AI Coding Daily ranking 20, with 12 in neither; O166 flags a *drop* versus the previous release, informationally. New argument: the flag is per-release and relative, so a slow multi-release slide (9 → 8 → 7 of 37) flags every time without ever forcing the benchmark-set balancing decision the owner already reserved to himself under O52; and nothing notices the two rankings' coverage *diverging* from each other. A public ranking whose leading ranking covers a quarter of its declared cohort weakens the "ranking of frontier AI models" claim more than any single flag conveys. **Recommended change:** a review trigger (never a hold): when a leading ranking's ranked share of the cohort stays below a stated floor (say one third) for two consecutive releases, the O52 balancing decision must be re-run and its outcome published.

**Low**

1. **The LP release-test fixtures do not state their window semantics.** "Two bursts one hour apart, each 60% of a 5-hour cap, are infeasible" is true for a sliding window but not for a fixed-reset window where the bursts straddle a reset boundary (60% + 60% in different windows is feasible). A correct implementation following a recorded fixed-reset semantics could fail this test. **Recommended change:** pin each fixture to its recorded semantics and reset phase (e.g. "sliding 5-hour window; both bursts within one window").

2. **The capacity certification gap is derivable but never surfaced.** feasible_lower_bound and relaxed_upper_bound are published per result, so a row degraded to "unidentified" by a wide gap looks the same as one narrowed by semantics. **Recommended change:** print the relative gap (upper − lower)/lower per route and flag it above a threshold (e.g. 10%); prefer the event-aligned grid as the default whenever boundary times are public (already permitted by E39/E56), since grid coarseness otherwise systematically depresses the feasible lower bound.

## 2. Methodology design recommendations

Prioritised, all implementable from refreshable public data:

1. **Session-end bracketing (pairs with Medium 1).** Add to the E115 route record: `session_end_status` (established / unresolved), `admissible_end_rules` with evidence, and lower/upper capacity computed under the bracketing extremes; point identification only on coincidence; fixture: two end rules → different capacities → "semantics unresolved; conservative achievable capacity only". No new data source needed — it reuses the existing solver and publish format.

2. **Version-independent samplers (pairs with Medium 2).** Specify in the spec that all draws reduce to documented transforms of `random.random()` (Beta via inverse CDF on two uniforms with a published formula; normal via a published Box–Muller on `random()` pairs), which Python guarantees stable across versions for a given seed. Keep `scenarios.generator` recording the transform version, which the build controls, instead of the interpreter version, which it does not. Add a regression test: regenerate a frozen scenario file on the current build and require byte equality. [docs.python](https://docs.python.org/3/library/random.html)

3. **Coverage review trigger (pairs with Medium 3).** Rule text: "if either leading ranking's ranked share of the cohort (scores.json `rankingCoverage`) is below 1/3 for two consecutive releases, the owner re-runs the O52 benchmark-set decision and publishes its outcome with the release." Informational like O166, but cumulative rather than first-difference.

4. **Solver hygiene (pairs with Low 1–2).** Pin fixture semantics; publish the certification gap with a flag; make event-aligned grids the default where public reset times permit. These are build-and-docs changes only.
