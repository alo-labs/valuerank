### High

**H1. Grader identity and grading-rule drift are unpinned for the judged leaves, and a live instance already exists.** The leaf definitions pin the harness, anchors and source version, but nothing pins who grades. FrontierCode — the largest leaf (15–25% depending on ranking) — is graded by "tests and rubric with an LLM judge," with the judge unnamed in the leaf table. Vibe Code Bench is graded by a browser-use agent, and Vals has since shipped **v1.1.1**, a grading update: a newer browser-testing agent powered by GPT-6 Luna, a second judge (Claude Sonnet 5.5) reviewing failed checks, and a stricter pass bar (a workflow now passes only when every step succeeds, replacing the ≥90%-of-substeps rule). Both grader models are themselves ranked cohort families, which adds a circularity concern beyond drift. Bug Hunt's judge is an unnamed "independent judge model" grading blind against a withheld answer key, and AI Coding Daily's judged points carry no pinned grader. Why it hurts the objective: the exact-variant policy forbids transferring scores across versions, yet a grading-rule change is a version change of the scoring instrument itself. Under O68 a re-grade that keeps all rows present (as v1.1.1 does) is read as ordinary movement, silently re-estimating the leaf's estimand against 0–100 anchors that cannot absorb a changed pass bar; comparability of the frozen leaf across releases degrades with no named cause. Recommended change: add grader fields (grader identity, grading-rule version, pass-bar rule, and a `gradedByCohortModel` flag) to each judged leaf's registry entry, capture them at every O68 re-read, stop or flag the build on change, and treat a confirmed grading-rule change as a new evidence version (the draft's Vibe Code Bench v1.1 pin will meet its v1.1.1 successor at the next release — precisely this case). [artificialanalysis](https://artificialanalysis.ai/methodology/intelligence-benchmarking)

**H2. Cost anchors are extremal statistics of a small panel and enter every output as exact constants.** The anchors are c_L = min reference cost ÷ 2 and c_H = max reference cost × 2; on the Plan basis O157/E304 require only ≥2 measured references, so the entire Plan cost scale — including the printed exchange rate ("a cost doubling is worth 5.31 value points… offset by 7.08 quality points") — can rest on two measurements individually admitted under a ±20% concordance band (O86). Under O25/E169, Θ covers reporting precision and missing evidence, but the anchors themselves are frozen constants of the release, so arguably the widest measurement uncertainty in the system (a measured extremal cost) appears in no interval output. A reference re-priced within its own band at the next freeze moves every row's cost score with no new evidence about those rows, bridged only after the fact by the dual run. Why it hurts: value ranks and their separability statements inherit anchor placement, and the draft's own disclosures show the leverage (the pre-O47 API span ran 4.19 → 12,078 USD on 27 references; today's listed-beyond-anchor rows reach 70.65× below the Plan low anchor). Recommended change (diagnostic only, no change to O25): at each freeze publish (a) leave-one-reference-out deltas — max |Δvalue| in points per removed reference, per basis; and (b) an anchor-bracket sensitivity recomputing S_C with each measured reference set to its concordance-band ends, governed exactly like the Bug Hunt `bugHuntScaleStress`; plus a "minimal panel" flag whenever a basis has fewer than three references.

## 2. Methodology design recommendations

1. **Grader registry with scoring-version semantics (implements H1; highest priority).** Extend the E129/E175 registry pattern: per judged leaf (FrontierCode, Vibe Code, Code Migration, Bug Hunt, AI Coding Daily, LiveBench's judged categories), record `graderModel`, `graderVersion`, `passBarRule`, `gradedByCohortModel`, each capture-dated. On O68 re-reads, diff these fields; on change, flag the leaf "grading drift detected" and offer the owner a binary: pin the old version (evidence frozen, labelled historical) or migrate as a versioned leaf change with bridge. Where boards publish no grader (Bug Hunt, AA), record `grader: unversioned` rather than omitting the field, so absence is visible. This is refreshable routinely from the same methodology pages the draft already verifies (as its GDPval citation practice shows).
2. **Anchor-stability package (implements H2).** Per anchor object and basis, at each freeze: (a) LOO table — for each reference r, recomputed c_L, c_H and max_i |V_i^(−r) − V_i| in value points; (b) band bracket — S_C recomputed with all measured references simultaneously at their O86/O115 band ends, reported as the induced rank τ_b and max rank move; (c) minimal-panel flag `references ∈ {2}` → "minimal panel" beside the exchange-rate line. All inputs already exist in scores.json and the report partitions; nothing changes scores, so O25 is untouched.
3. **Vendor-dependence sensitivity (implements M4).** Publish per release: τ_b(headline, composite with AA-run leaves ×0.5 renormalised) and, per row, a flag when one party supplies both the majority of quality weight and the cost evidence. Cheap, purely diagnostic, and it quantifies the risk the 66%/78% disclosure currently only states.
4. **Bug Hunt scale governance alignment (implements M3).** Whichever way the owner rules, add one rule so the regimes match: a release where P_max + U_max moves beyond the ±10% stress band must name the remedy in the gate output (as O120 does for clip holds) rather than only attributing the swing. Zero new data needed; extends E177/E346 bookkeeping.
5. **Harness-coupling decoupling (implements L5).** Reorder E268's selection: documented primary CLI → largest N → harness accord with Bug Hunt as final tie-break. Keeps E334's attribution, removes the induced-leaf-change path in the common case.
