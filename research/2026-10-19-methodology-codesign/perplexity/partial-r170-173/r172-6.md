## 1. Findings by severity

**Critical**

None. The layer architecture (S0/S1/S2/S1M/S1T), the Θ admissible-set discipline under O25/O19, the joint rounding law, and the E77 sequential Monte Carlo gate are internally coherent; fixtures check the identities that would silently break under naive implementations.

**High**

1. The label gate (O182/O183/O187) and the entire workload cross-check hang on one benchmark, Terminal-Bench — 11% of the max-effort quality weights — while sitting near its own n = 8 panel floor. The check d_ib = mean cost per attempted task ÷ resolved fraction is computed "per benchmark b (Terminal-Bench 4.0...)" only, yet the basket under O137 contains ITBench-AA and the Coding Agent Index, which produce matched per-row costs and outcomes on the same observation key, and the Coding Agent Index itself executes Terminal-Bench under a different agent (O123, O24). A single-benchmark τ_b of 0.35–0.91, with the fail-safe "cannot be computed → withhold all cheapest labels" branch (O187), means one 66-task board's idiosyncrasies can gate every interval label in both rankings. Why it hurts: ValueRank's objective is a defensible cheapest-above-bar answer; a gate with one fragile input, applied at the whole-ranking level (E349), is a single point of failure. Change: register the same-execution contract per basket component, not per benchmark — I_b built for Terminal-Bench (AA run), Terminal-Bench (Coding Agent Index vendor-agent run), ITBench-AA and FrontierCode-AA 2.0 wherever a public per-row cost and matched quality outcome exist; keep them never-pooled, publish each τ_b, and fire O182's gate on a pre-registered panel of checks (e.g., median τ_b across checks, with each check listed), so one dormant or sub-floor check degrades to a warning rather than withholding every label.

**Medium**

1. Rank separability structurally omits cost dispersion even though the draft admits the machinery exists. Part 11 states "public paired per-task or per-run cost observations for the exact configuration support resampling at their evidenced level," and part 12's cross-check already does "task-cluster resampling where task-level results exist"; yet the O42 threshold "draws quality noise only... cost noise cannot be drawn," with E340 noting only that omitting cost noise narrows separability. Since S1T already couples quality draws at the task level for every leaf, the asymmetric treatment (quality resampled, costs at reporting precision) makes the published "0 of N adjacent ranks separable" systematically optimistic-or-pessimistic by an unknown amount — acknowledged, but a note is weaker than the fix the draft itself describes. Change: extend S1T (or a named companion stream S1C) to jointly resample task-cluster costs wherever per-task costs are captured (the demand objects of E44 imply per-task cost data is at least partially in the registry), and restate separability on the joint draw; where per-task costs are not public, print the share of each ranking's basket cost that carries task-level cost telemetry so the gap is quantified rather than generic.

2. The AA-Omniscience S1T kernel assumes a trinomial support {+1, 0, −1} with w = h·(1−a), but AA's v1.1 grading has four outcomes, including PARTIAL_ANSWER. If partial answers carry any non-neutral score in AA's Net Score (or are folded into the hallucination rate with a different weight than full incorrect answers), then the published I = 100×(correct − incorrect) ÷ all and the variance 100²·(a + w − (a−w)²)/3000 both miss the partial mass, and z = (I + 100)/2 inherits the error. Why it hurts: Omniscience is a 10-point single-leaf reliability group (O28); a mis-modelled leaf kernel silently distorts both the leaf z and the S1T dispersion of every composite. Change: record the partial-answer rate p_part and AA's scoring of partials in the leaf's provenance object; if partial credit ≠ 0, extend the kernel to the quadrinomial variance; if AA scores partials at exactly 0 and the current formula is exact, add that as a build-checked equality so a future AA grading change (an E100/O100-class note) stops the build. [artificialanalysis](https://artificialanalysis.ai/methodology/intelligence-benchmarking)

3. GDPval-AA ratings are drawn independently across rows in S1T, but Crowd-BT ratings with a pinned anchor (DeepSeek V4.1 Flash at 1600 ) covary positively through shared matchups and the shared anchor; the draft discloses this ("approximation disclosed, not corrected") but does not stress it, while O42's 0/0.3/0.6 correlation grid operates on leaf-level quality noise, not on cross-row coupling of one fitted rating. Positive cross-row correlation shrinks the variance of rating differences, so independent draws overstate GDPval-driven rank churn — working against separability claims, but also against the interval-share stability the stream is meant to test. Change: run the same fixed correlation grid across rows for the fitted-rating leaf (ρ ∈ {0, 0.3, 0.6} on the latent scale), published beside the primary draw, mirroring E309's planted/unplanted correlation stress. This is an extension of an accepted sensitivity design, not a new estimand. [artificialanalysis](https://artificialanalysis.ai/methodology/intelligence-benchmarking)

4. Stream and diagnostic registrations are not version-keyed as tightly as the benchmarks they name. Part 11's S1M contract names "Terminal-Bench 4.0 on tbench.ai"; part 12's cross-check names Terminal-Bench 4.0; AA has already moved its Index run to Terminal-Bench 4.1 (same 66 tasks, updated verifiers) and tbench.ai now leads with 4.1. O203 defers the newer chart to the next release, so this is not a current-release error, but nothing in the registered objects keys (benchmark, version, source, harness) as one value: a capture that silently flips tbench.ai's default board from 4.0 to 4.1 would satisfy "Terminal-Bench on tbench.ai, whiskers = 95% CI" textually while changing task content, repeat counts and the applicability of the CI to AA's leaf. Change: make the interpretation contract and the cross-check's observation key carry an explicit benchmark_version field, and add the E100/O100-style register rule that any version-string change on a registered source stops the build until an editor record re-keys it (the registry already pins LiveBench release dates per E175; apply the same to the S1M object and d_ib contract). ## 2. Methodology design recommendations

Prioritised, all implementable from refreshable public data:

1. Multi-component cost-agreement gate (matches High 1). Define the gate statistic as the median of per-component matched-panel τ_b values over all basket components where a public per-row cost and exact-configuration outcome exist; publish each component's τ_b, panel size and list of rows. Gate on median < 0.5 with any individual component < 0.5 naming that component in the label warning. Data source: same AA Coding Agent Index executions already captured, ITBench-AA per-scenario outcomes, FrontierCode-AA 2.0 per-task scores. Collapse rule: fewer than two computable checks → fail safe exactly as O187 today.

2. Joint cost-noise stream (matches Medium 1). Register S1C = S1T with task-cluster resampling of per-task costs where public, joint with the quality draws on the same task support; separability threshold then reads from the joint (quality, cost) draw. Where per-task costs are unpublished, print `scenarios.costTelemetryShare` = share of basket cost (by row, weighted) backed by task-level cost telemetry, so reviewers can see whether "cost noise cannot be drawn" is 100% or 20% of the basket.

3. Fitted-rating cross-row correlation grid (matches Medium 3). For GDPval-AA (and any future fitted-rating leaf), draw the vector of row ratings with equicorrelation ρ on the latent scale at ρ ∈ {0, 0.3, 0.6}, primary at 0, grid published — the same fixed-rule pattern already accepted under O42 and E309, so no new convention is invented.

4. Omniscience quadrinomial kernel with provenance guard (matches Medium 2). Leaf provenance object records partial_rate and partial_credit as published by AA; variance formula selected by build rule from the recorded support; build fails if AA's methodology page changes its grading vocabulary (register rule as in recommendation 5).

5. Version-keyed source objects with a build stop (matches Medium 4). Add benchmark_version, harness_version and source_board_version to the S1M interpretation contract and the d_ib observation key; any mismatch against the registered string stops the build until re-keyed — a direct extension of E64/E225's closed-world principle to the uncertainty and diagnostic layer, which is currently the least version-protected layer in these two parts.

6. LiveBench Overall kernel weight check (supports Question 2). Print the E256/E311 kernel's category weight vector in scores.json alongside a build check that it equals LiveBench's published Overall weighting (Long Agentic ×2, Design ×1.5, Coding ×1.5, rest ×1 ) at the capture date; since O67/O61 made the leaf track "its own weighted Overall," the dispersion kernel must use the same weights as the point value or separability around this 15-point leaf is mis-sized. [livebench](https://livebench.ai/)
