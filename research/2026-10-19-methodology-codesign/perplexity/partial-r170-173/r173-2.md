## 1. Findings by severity

**Critical**

None.

**High**

- **O27's Coding Agent Index cost formula conflates "per task" with "per task-attempt".** The draft defines the component as "the average pay-per-token API cost per task, which AA computes as a pooled per-task-attempt average that excludes missing telemetry … × the required tasks, 290 since v2.0". "Cost per task" and "pooled per-task-attempt average" name different divisors: if AA divides total cost by *task-attempts* (attempts including retries, and O63 confirms blocked and fallback attempts exist in these runs), multiplying by 290 *tasks* understates the cost of configurations that need more than one attempt per task; if AA divides by *tasks*, the words "per-task-attempt" are simply wrong. AA's Intelligence Index cost basis is documented as token prices "divided by task count" with the Index "cost to run" excluding repeats, which matches E9's one-pass definition — but the same clarity is absent here for the Coding Agent Index, whose AA methodology page could not be verified from public search. Why it hurts: this component carries 16–74% of basket cost in the max-effort ranking and cost is 25% of the value score, so a divisor error systematically favours attempt-heavy rows in the headline. Concrete change: quote AA's exact field name and formula verbatim in the draft and in the E37 registry entry, state the divisor and how blocked, fallback and repeated attempts enter numerator and denominator, and — if AA publishes attempts per task per row — publish that per row and add a scenario-layer sensitivity scaling the index cost by the row's attempts-per-task relative to the reference-panel median. **Medium**

- **Owner decision challenge (O24): the Terminal-Bench double pricing now amplifies agent-attributed cost into the model ranking.** The existing defense ("different deployments, each is what a user of that deployment pays") is stated in the draft; the new argument is its interaction with O137 and O123: the same 66 Terminal-Bench 4.0 tasks are priced twice — once in AA's own bare-model run and once inside the Coding Agent Index's non-separable pooled agent cost — and the only mechanism designed to correct agent attribution (the S2 stress, O123) is explicitly "unevaluable" today. So the terminal-task share of C_W is roughly doubled under two different attribution regimes with no measured adjustment, in the ranking that leads. Concrete change within O24: publish per row the Terminal-Bench 4.0 share of C_W under each execution (the AA Index run separately; inside the CAI pool at the labelled equal-cost reading), so the amplification is visible next to the existing overlap disclosure, and adopt the cross-release S2 extension below.
- **The S2 harness-cost stress can never fire within a release.** log C = α_m + h_a is fitted over models AA lists under two or more agents, and the draft states it is unevaluable today; AA's coding-agent board pairs one agent per row under the E267 grammar, so within-release connected groups may never form, leaving O123's deliberate charging of agent tokens to the configuration uncorrected indefinitely. Concrete change: pool the last k releases (O145 retention keeps configurations one release after leaving the frontier, so adjacent releases share configurations), fit h_a centred within connected components of the pooled graph, and apply exp(−h_a) to the current release's rows read against its named reference agent, with an E184-style overlap bridge between releases; still sensitivity-only, refreshed every release.
- **E140's lexicographic admission order embeds an unstated preference for basket breadth over comparison breadth.** The admitted set maximizes component count first, then |P(S)|; against the two-thirds floor this can admit a larger basket on a smaller complete panel, sending more rows to subset workloads where, per O17/O184, they take no rank among the main-workload rows. Why it hurts: the objective is comparing models on value, and a reader cannot tell how much of the published ranking depends on breadth-first being chosen over panel-first. The feasible alternatives are already published, so the fix is cheap: print beside them the leading ranking computed under the largest-|P(S)| feasible alternative and its τ_b against the published ranking on shared rows (the E288 pattern), or one sentence justifying component-count-first.

## 2. Methodology design recommendations

1. **O27 formula registry precision (highest priority).** Registry entry for the Coding Agent Index unit: AA's verbatim field name, the exact divisor (tasks vs task-attempts), the treatment of blocked/fallback/repeat attempts in numerator and denominator, and the ×290 multiplication written as one displayed formula. If attempts per task is public per row: sensitivity cost CAI′ = CAI × (attempts-per-task_i ÷ median attempts-per-task over the reference panel), scenario layer only.
2. **Cross-release S2 estimator.** Pool releases t−1 and t (O145 gives shared configurations); nodes are (model, agent) rows, edges from co-listed models; fit log C = α_m + h_a by least squares centred within each connected component; publish per-release API ranks adjusted by exp(−h_a) against each group's named reference agent; report group membership and reference agents; unevaluable groups reported as today. Sensitivity only, never a score change.
3. **Admission-order sensitivity.** Beside E26's published feasible alternatives, print the leading ranking under the largest-|P(S)| alternative and its τ_b with the published ranking on shared rows (E288 pattern, defined from the shared configurations up).
4. **E267 unknown-effort stop branch** with the unseen token named in the build failure.
5. **Boundary-matrix reclassification** for the CAI's non-token classes to "not applicable (metric scope)".
6. **Matched-cost diagnostic calibration publication**: per-release R_i distribution, reversal counts, and priced-weight floor actually observed.
