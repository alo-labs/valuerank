**High**

**Medium**

1. **Crossing tight bounds can pass the within-observer concordance test and yield a pooled figure supported by no reading (O192/O189/E350, part 7).** The within-observer test is O86's ratio test over an observer's readings: largest lower ≤ 1.20 × smallest upper. Two disjoint readings — e.g.  and  — cross (tight bounds, an empty interval) yet pass, since 122 ≤ 144. The observer is then "concordant", its pooled midpoint (121) lies in neither recorded reading, its disclosed pooled range is ill-formed (lower > upper), and the clause "an observer's spread cannot create agreement its readings never had" is defeated exactly in this ≤ 1.20 gap region. This sits inside the admission gate for Plan routes, so it can co-admit a route on internally contradictory evidence. Recommended change: within-observer concordance = (LL ≤ SU) **and** (LL ≤ 1.20 × SU); publish the observer's disclosed range as the convex hull [min lower, max upper] so E350's widening property is preserved, and keep the pooled midpoint from the tight bounds only when they do not cross.[100][120][122][150]

2. **Owner decision challenge (O76, part 7).** Converting a speed-mode report at the provider's published multiplier (OpenAI Fast 2.5×, Ultrafast 8×) inserts an unverified provider figure into the Value Multiple numerator — the one place the fixed evidence policy forbids provider numbers — and a converted report can satisfy the ≥2-concordant-reports admission rule where the raw figure could not. It is flagged, but flags don't gate admission. New argument beyond the flag: the multiplier scales consumption multiplicatively, so the conversion can also manufacture concordance between a speed-mode report and a standard-mode report that the raw figures would have failed under O86. Recommended change: treat converted reports as provisional under the O159 machinery until one standard-mode observer concords, or publish the unconverted figure as the conservative end for every label, blocker and interval decision (the converted figure remaining display-only), mirroring how O125 prices MiMo credits at the recorded rather than the highest rate.

**Low**

3. **O88 cross-effort validity assumes an unweighted token meter, but O126's "tokens or credits" test does not exclude weighted meters (part 8).** A meter that denominates "tokens" while weighting token classes or efforts differently (reasoning tokens at >1, per-effort burn coefficients) breaks the effort-invariance argument ("an allowance is effort-invariant, which holds because the plan's meter counts tokens"), yet the build would still admit the O88 route as measured. Recommended change: add a `tokenWeighting` field to `evidencePolicy.meterDenominations` (uniform / class-weighted / effort-weighted / unknown) sourced from provider documentation; O88 routes count as measured only on uniform (or verified-equivalent) meters, else they demote to labelled assumptions.

4. **E201a's window-straddling recomputation assumes the report's aggregation is linear in periods (part 7).** Where a report states per-period readings, the registry recomputes the multiple "from them by the report's own aggregation" — but if that aggregation is non-linear (a maximum, a per-period average re-averaged, a worst-case bound), silently applying an additive/geometric recomposition misstates it. Recommended change: apply the sub-period recomputation only where the report's stated aggregation is additive or geometric in periods; otherwise fall back to the end-date rule with the "window-straddling" flag, and record the aggregation type with the report.

5. **E246's bare-name binding is undefined if AA ever plots more than one configuration under the same bare model name (part 8).** The rule binds "to the configuration AA plots under the bare model name" (singular; today each is the max row). Recommended change: have the build fail on a plural bare-name plot rather than silently picking one, consistent with the E204/E225-style stop-on-ambiguity pattern the draft already uses elsewhere.

## 2. Methodology design recommendations

Prioritised, all implementable from the draft's existing registries and build:

1. **Harden the observer-concordance gate (finding 1).** Within-observer test: concord iff LL ≤ SU and LL ≤ 1.20 × SU, computed from the `readings` list; pooled range = hull [min lower, max upper]; pooled midpoint from tight bounds only if non-crossing, else the observer is discordant (excluded, still blocking its partition per O191). One-line change to the E270/O192/O189 test order, no new data needed.

2. **Conservative dual treatment of speed-mode conversions (finding 2).** In `planAllowanceCells`, publish both `valueRaw` and `valueConverted` for any cell with a converted report; route admission uses whichever the owner fixes as governing, but label, BlockerSafe and interval tests read the conservative (unconverted) figure; flag `speedModeConverted` with the multiplier's capture date in the registry so a provider multiplier change becomes an E18 change event.

3. **Meter-weighting guard for O88 routes (finding 3).** Extend O126's registry record as above and add a build check: an O88 route on a meter recorded as class- or effort-weighted stops being classified O90 measured evidence and becomes a labelled assumption, keeping the measured-only Plan view (E113) honest about what "measured" means.

4. **Publication-side robustness (findings 4–5).** Restrict E201a recomposition to stated-linear aggregations; fail the build on ambiguous bare-name plots. Both are stop-or-flag rules with no new evidence requirements, so they preserve routine refreshability.

I deliberately do not propose changes to the cohort rule, exact-variant evidence, transfer set, or the O46/O198 ceilings — those are owner-fixed and the parts' disclosure apparatus (brackets, `categoryMultipleRange`, optimistic-end flags, the E321 exploratory label) already handles their residual risk in a way I find sound.
