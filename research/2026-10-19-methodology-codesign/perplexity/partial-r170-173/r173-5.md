## 1. Findings by severity

**Critical**

None.

**High**

None.

**Medium**

1. **Owner decision challenge (O170/E346/O173): the live Bug Hunt scale imports non-cohort evidence into cohort scores.** Issue: P_max and U_max are taken "over every run on the live board, any model or harness", so a cohort row's z (and therefore its value score at 8/12/15% nominal weight) depends on results of models outside the ranked cohort. Why it hurts the objective: ValueRank's core discipline is exact-variant evidence with no transfer between configurations; a denominator set by an unrelated model's outlier run is a channel through which another party's result changes a ranked row's score with no new evidence about that row. E346's within-Θ fix and O173's ±10% stress handle noise and disclosure, but not the influence coupling itself: two releases with identical cohort evidence can publish different composites because the leaf's realized dispersion (hence its effective influence at fixed nominal weight) moved. The leaf's *ranking* is invariant (z is a common positive scaling of x), so the damage is confined to cross-leaf weighting and cross-release comparability — which is why this is Medium, not High. Concrete change: restrict P_max/U_max to runs of cohort configurations (still live, still recomputed each release, still carrying the bugHuntScale swing class), or freeze the constants per methodology version with the standard version bridge, as every other leaf's anchors are frozen. The counterargument for the whole board — a stable 0–100 meaning and no inflation when the cohort is weak — should be weighed by the owner; what is new here is the exact-variant-consistency argument, not the stability one already settled.

2. **E268 couples the AI Coding Daily leaf to Bug Hunt's sampling.** Issue: the AI Coding Daily row for a doubly-listed configuration is chosen by the harness of its Bug Hunt record, and that record is chosen by largest-N over harnesses and routes (E206). Why it hurts the objective: a Bug Hunt refresh in which a different CLI run acquires the largest N changes the AI Coding Daily leaf although no AI Coding Daily row changed — the leaf's value then reflects another benchmark's run counts, not evidence about the configuration on that board. It is disclosed and attributed (E334), but the attribution machinery exists only because of the coupling. Concrete change: select the AI Coding Daily row by a registered, versioned harness preference list exactly as E225 does for tbench.ai gap fills (e.g. provider-native CLI first, then the configuration's Bug Hunt harness as tiebreak, then latest test date), so the selection depends only on AI Coding Daily's own board plus a pre-registered rule. Build-stops on ambiguity stay.

3. **No corroboration statistic for the 66% AA-run quality weight.** Issue: the draft publishes the share of quality weight by data source (66% AA-run in the max-effort ranking; 78% in AI Coding Daily) but never tests whether the independent minority agrees with the AA-run majority. Why it hurts the objective: a public value ranking whose quality vector is two-thirds one party's measurements is credible exactly insofar as the independent third corroborates it; today a reader can see the concentration but not the agreement. E234 (FrontierCode AA vs Cognition) and E287/E288 cover single-leaf and cross-ranking checks, not this split. Concrete change: per ranking, publish Kendall τ_b and the mean offset between the AA-run partial composite and the independent partial composite (weights renormalised within each side) over the common ranked rows, beside the source-share table — implementable from data already in the build.

4. **Ranked Plan rows outside the clip-gate population have no published cost-clipping disclosure.** Issue: O157 sets owner-assumption and API-fallback Plan rows outside G, and the gate output discloses only *listed* rows beyond the anchors (O58); E110's clipping audit covers quality leaves. Why it hurts the objective: a flagged assumption row (e.g. an O46 provider-derived ceiling) whose cost clips to a saturated 0 or 100 cost score carries a full 25%-weight input with no visible signal, while the same clipping in a gate-population row would hold the release. Concrete change: extend the per-anchor-object output with a clipped-rows disclosure split by gate-population vs outside-gate, in the O58 format (basis, side, factor, whether past the factor-2 limit), e.g. a `gates.clip.plan[].clippedOutsideGate` array in scores.json.

**Low**

5. **Zero-cost rows are ungated and formally unscored.** G is defined over rows "with a positive cost on that basis", and S_C's ln c is undefined at c = 0 (the limit is 100). E185 contemplates free categories in force, so a zero-cost Plan row is possible in principle. Recommend an explicit rule: score by the limit, treat c = 0 as beyond the low anchor for the factor rule (or exclude from the value score with disclosure), so the case cannot arrive undefined.

6. **GDPval drift-since-addition is never measured, only release-to-release.** The draft itself states the leaf "can differ from AA's own Index input by the drift accumulated since a configuration's addition", yet `gdpvalMovement` compares only consecutive captures; a small per-release refit drift would accumulate invisibly. ValueRank holds pinned captures per release, so the first-capture Elo of every configuration exists in its own archive. Recommend publishing, per ranked row, the current displayed Elo minus the Elo at that configuration's first ValueRank capture, as a diagnostic magnitude.

7. **Judge-regime drift on Bug Hunt "extras" is unmonitored.** Unplanted counts are verified by the board owner's blind judge; a change in judge leniency would shift every row's numerator without moving P_max/U_max, so `bugHuntScale` would not catch it (E309's planted/unplanted correlation stress is a different check). Recommend a per-release board-wide unplanted-to-planted ratio (all runs) as a judge-regime flag, with the swing replay carrying it as a named class if it moves materially.

## 2. Methodology design recommendations

Prioritised:

1. **Cohort-restricted (or version-frozen) Bug Hunt normalisation constants** — z = 100 × x / (P_max + U_max) with P_max, U_max computed over runs of cohort configurations only, recomputed each release, keeping the bugHuntScale swing class, the build stop above P_max + U_max, and the maxPlantedRuns/maxUnplantedRuns attribution. This preserves O170's live 0–100 form while removing non-cohort influence; a version-frozen alternative uses the existing anchor-bridge machinery instead.
2. **Registered harness preference for AI Coding Daily row selection** — a versioned, closed list (as E225 does for tbench.ai) that names the harness order, with the Bug-Hunt-harness match demoted to tiebreak; E334's attribution retires when the coupling does.
3. **AA-run vs independent partial-composite agreement** — per ranking, τ_b and mean offset over common ranked rows with weights renormalised within each side; publish beside the source-share table and add it to the drift-flag's informational set.
4. **Cost-clipping disclosure for outside-gate Plan rows** — an O58-format array per Plan anchor object listing assumption/fallback/expired rows whose cost clips, so saturated flagged cost scores are visible without holding the release (consistent with O157's intent not to let them distort anchors).
5. **Zero-cost row rule** — define scoring (limit) and gating (beyond-anchor by the factor rule) for c = 0 before a free-category row can arrive.
6. **GDPval accumulated-drift table** — current displayed Elo vs first-capture Elo per ranked row, from the pinned capture archive; zero cost, directly quantifies the estimand gap E90 names but never measures.
7. **Bug Hunt judge-regime ratio** — board-wide unplanted/planted ratio per release as a flag; cheap and closes the one verification channel no other diagnostic watches.
