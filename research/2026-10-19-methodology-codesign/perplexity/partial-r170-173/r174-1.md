## 1. Findings by severity

**Critical**

None.

**High**

1. **Ordinal Plan ranks are the primary display while zero Plan routes have an identified M_W** *(Owner decision challenge: O152 "ranks stay primary")*. Part 1's Outputs state that all 30 and 74 Plan rows rest on owner assumptions, provider quota ceilings, or unidentified multiples, that flags are listed per row, and that "no Plan frontier or bar claim is supported (E61, E67)" — yet the headline Plan ranking still presents ordinal ranks with noise bands, which a reader will consume as supported comparisons. The settled O4/O7 debate was about whether transfers can *identify* M_W (correctly: they cannot); the new argument here is about *display governance*: when identified-M_W coverage is 0/30 and 0/74, ordinal ordering conveys a false ordinal claim even with flag columns and the E242 transfer tolerance. Change: make the band-ordered table the primary Plan display while identified-M_W coverage is 0%, keeping numeric ranks in a collapsed "exploratory arithmetic" view, and restore O152's ranks-as-primary display automatically at a coverage threshold (e.g., ≥50% of compared pairs on identified routes).

**Medium**

1. **Frontier membership — the governance-critical input — rests on a single SVG extraction with no redundant extractor.** E195's build checks (vertices matched, one point per vertex, strictly rising path, 0.5 px tolerance, hover de-duplication of overlapping circles) verify *internal consistency* of one capture pass, but there is no independent re-extraction. This matters because AA re-runs its benchmark every 6 hours and republishes coordinates continuously, so the rendered chart is a moving target; cohort membership, the near-gap edge, O145 retention state, and thus bar populations and anchor diagnostics all derive from this one artifact. A rendering change (viewport-dependent circle packing, AA chart update) could flip a point's vertex match with no second signal to catch it. Change: bundle two independent extractions (different viewport and a second capture round within the capture window), publish the vertex table with extraction hashes, and stop the build on disagreement. [artificialanalysis](https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index)

2. **The E217 ≤7-day window between chart capture and model-page snapshots has no conflict rule.** Part 1 states membership is read from the frontier capture and rounded tooltip values are never used to recompute membership, but part 2's near-gap edge diagnostic (configurations one rounded point either side of the edge) and per-model data come from snapshots that may be up to a week apart; if a configuration crosses the near-gap edge between the two captures, nothing in these parts states which capture governs or whether the build fails. Given AA's 6-hour refresh cadence, cross-window flips are realistic, not hypothetical. Change: pin membership and near-gap membership strictly to the frontier capture, and add a build stop when a model-page snapshot's Index contradicts the membership read from the frontier capture. [artificialanalysis](https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index)

3. **O145 retention application moved the cutoff and re-captured every source (O65 cascade).** Part 2 records: "applying O145 moved the release cutoff (O65) and re-captured every source." The same note appears at O51's O47 episode. Because retention is defined by comparing consecutive releases' plottings, every release where O145 engages can retrigger O65 — a churn loop that delays shipping and re-opens settled captures (report windows, anchors' valuation gate). This is not an argument against O65; it is a sequencing defect: retention evaluation should run *inside* the chart-capture stage (the first AA read defines candidate retention before the cutoff is pinned), rather than as a post-cutoff discovery that invalidates the pinned clock.

## 2. Methodology design recommendations

Prioritised:

1. **Identified-M_W coverage as a headline KPI and display gate** (implements finding High 1). Publish per release, per ranking: share of adjacent Plan pairs whose value order is supported by at least one identified-M_W route, and share of Plan rows on identified routes. Define the display gate on the pair-coverage statistic (≥50% restores ordinal-primary display). Both are computable from the existing `planRows[].flags` records with no new data.
2. **Dual-extraction frontier pipeline** (implements Medium 1). Two independent capture runs (viewport 1280 px and 1920 px, ordered rounds within the chart-capture window); build fails unless the two vertex tables and near-gap sets agree exactly. Bundle both artifacts with hashes; publish disagreements when the build is held.
3. **Retention-in-capture sequencing** (implements Medium 3). Evaluate O145 states (E306 plotted/retained/out) from the current frontier capture against the previous release's bundled capture as part of the first capture stage, before the cutoff is pinned, so O145 can never retroactively move an already-pinned V. Add a regression test: simulating a one-family exit must not change V.
4. **Near-gap flip changelog** (implements the dual of Medium 2). At each release, diff the rounded-edge membership against the previous capture; publish flips as a named cohort-diagnostic table (candidates already named in part 2), and require any flip that would change cohort N to be listed in the release's swing causes (E177/E275 family).
5. **Optional, low priority: confidence-set primary view.** As a sensitivity column beside ordinal ranks, publish the minimal set of configurations that are top-k in ≥50% of scenario draws per basis — a draw-count quantity complementary to the E328 bands and computable from the existing scenario runs.
