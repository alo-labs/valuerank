## 1. Findings by severity

**Critical**

**High**

**Medium**

1. **Concordance of range-valued reports does not require interval overlap, and pooling can land in the gap between the intervals.** E33/O86 pass a partition when max lower ≤ 1.20 × min upper; O115 then clips each midpoint to `[largest lower / 1.20, 1.20 × smallest upper]` and pools by geometric mean. Reports  and  pass (105 ≤ 108) although the intervals do not overlap; the pooled geometric mean (~97) sits in the gap 90–105, a value neither observer's range supports. Because the pooled figure feeds the Plan cost input and hence the headline Plan value score, a passing partition can publish an allowance that no evidence point supports. Recommended change: add an overlap precondition — admit only partitions where `max_k lower_k ≤ min_k upper_k` — and publish the pooled interval `[max lower, min upper]`. Non-overlapping but tail-close partitions (like the example) should publish under a `gap-pooled` mechanism flag or stay diagnostic. Add the / fixture to the build; the change is local to the E33/O115 code path and refreshable from the same report data.[80][90][105][120]

2. **No treatment for report windows that straddle a registered limit/price change.** O156 explicitly types readings spanning meter resets; O110 bounds a reading's start no earlier than model launch; O83/O99 split *partitions* at registered changes. But nothing prevents or flags a report whose stated measurement window straddles a registered limit or price change date: with a stated window (required by O194) and a straddling average, the report joins the post-change partition at face value, and at ±20% concordance a two-regime average can pass against a genuinely post-change reading. Recommended change: at admission, intersect each report's stated window with the registered change records for its plan and meter family; a straddling report is typed `regime-straddling` and admitted only into the pre-change partition (or excluded with that reason). This is one additional join over data the registry already holds.

3. **Change detection uses the same evidentiary bar as change recording; single-observer undocumented-change reports are discarded rather than pursued.** E18's two-report rule rejected the 2026-10-13 five-hour change outright. Yet detection is cheap and precautionary while admission is load-bearing: the known A/B-test episode on Claude Max — SemiAnalysis measuring ~20% lower monthly API value on some accounts — shows single early signals can be real. A discarded single report leaves the flagged-but-selected SemiAnalysis route as the row's only evidence with no opened cell. Recommended change: a `watch` state — one observer's undocumented-change observation opens that provider's cells for a targeted staged search within the release-time clock (7 days), without recording a change, flagging, or splitting. Only a confirmed pair (current E18 bar) records the change. New argument relative to the ledger: this does not loosen admission; it separates the *search trigger* bar from the *record* bar, which the ledger's E18 items do not address. [x](https://x.com/AGTPinsights/status/2113516377227337870)

4. **Archival asymmetry between the most load-bearing source and end-user reports.** O165/O168 require a SHA-256-archived copy for staged-search reports and O124 for form submissions, but the SemiAnalysis figure table — which currently determines every Claude and GPT Plan row — exists in the bundle only as a transcription, hashed, with periodic re-reads (O130) and no hash of the fetched bytes. If the paywalled page is revised in place and the transcription disputed, no third party can verify which transcription was faithful at capture. Recommended change: store, per read, the fetch instant and SHA-256 of the fetched bytes (not the content, which is paywalled) for the selected SemiAnalysis article and every re-read, exactly as O165 does for public pages. Content secrecy is preserved; auditable fixity is gained. This complements O130 rather than repeating it: O130 governs change detection of figures, this governs verifiability of the transcription itself.

5. **Published-limit conventions are conservative by varying, route-specific degrees, so cross-route comparability of Plan multiples is uneven.** OpenCode Go routes take the multiple at peak prices (off-peak would double it) and Gemini 4 Argon at list prices (the launch discount halves cash), while the full-utilisation definition elsewhere in the draft is the *maximum* attainable API-equivalent consumption under evidenced constraints. Confirmed detail: OpenCode Go defines per-model monthly dollar limits (e.g., $100 for DeepSeek V4.1 Flash vs $15 for GLM-5.3/Kimi K3/Grok 4.7 on the $10 plan) with 5-hour (20%) and weekly (50%) sub-limits  — the monthly figure is indeed the binding constraint under spread usage, so O198's choice of it is sound, but the price-point convention is not. Recommended change: for published-limit routes, compute and publish the schedule-induced multiple range `[M_min, M_max]` (peak→off-peak; list→discount), display `M_min` labelled as the conservative end, and expose `M_max` in the route-alternative table so the asymmetry across routes is a displayed interval, not an invisible convention choice. ## 2. Methodology design recommendations

Prioritised:

1. **Overlap-gated concordance for range reports (finding M1).** Admission predicate: `max_k lower_k ≤ min_k upper_k AND max_k lower_k ≤ 1.20 · min_k upper_k`. Pooled point: geometric mean of midpoints clipped to the intersection `[max lower, min upper]`; pooled interval published as that intersection. Fixture:  +  must *not* admit;  +  admits, pool = √(90·115) with interval {100}. This is the most decision-relevant change because it directly governs a number that divides the Plan cost input.[80][90][100][105][120][130]
2. **Straddle typing at intake (finding M2).** At report admission, join `report.window` against the registry's typed change records for the route's plan and meter family; emit `regime-straddling` and restrict the report to the pre-change partition. One build fixture (window 2026-10-10→2026-10-24 against the 2026-10-17 shared-meter change) suffices.
3. **Two-tier change-detection bar (finding M3).** Single-observer plausible signal → `watch` list, opens that provider's cells for a targeted staged search within 7 days; the existing two-report bar still gates the change record, flags, partitions and splits. Publishes as `searchLog[].watchTriggered`.
4. **Fixity evidence for paywalled controlled measurements (finding M4).** `sourceEvidence.semianalysis.rereads[]` gains `(fetchInstant, sha256OfFetchedBytes)` per read, in addition to the transcribed figure table. Third parties with a subscription can then verify the transcription retroactively; the bundle never stores paywalled content.
5. **Schedule-bounded multiples for published-limit routes (finding M5).** Formula: `M_route ∈ [L/(F · r_max), L/(F · r_min)]` where `L` is the published dollar limit and `r` ranges over the plan's posted price/discount schedule; headline uses the lower end (conservative), the route-alternative table shows the range. Same pattern applies to O46 ceilings if Xiaomi publishes tiered credit rates.
6. **Per-route displayed allowance uncertainty.** Beside each pooled multiple, print `min`/`max` of the contributing clipped report midpoints — a zero-cost, assumption-free spread that lets readers see whether the headline rests on a 100/110 pair or a 100/120 pair. Fits naturally in the E171 route-alternative table.
