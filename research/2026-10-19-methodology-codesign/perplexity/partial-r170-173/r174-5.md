## 1. Findings by severity

**Critical**

**High**

- **Owner decision challenge (O28) — abstain-all floor z = 50 has rank-moving magnitude. New argument:** the ledger debated monotonicity, but no prior round quantified the floor against O39's own separability result. Reliability carries 10 quality points, so an everything-abstained configuration banks z = 50 → 5 quality points → 3.75 value points, while the printed separability is ~3.3 value points with 0 of 30 adjacent ranks separable. A configuration contributing zero reliability evidence can therefore overtake honest partial answerers within published noise, and because O25 keeps this inside the protected published record, the E128 z_pen sensitivity never disciplines it. Recommendation: label-eligibility and bar tests use an answer-coverage-scaled z\* = 50 + (I/2)·(1 − a/T) (monotone within a configuration; total abstention → 50 × (1 − 1) → floor at 0 contribution), with plain z kept as the published diagnostic.
- **E268's harness coupling lets one benchmark's sampling artefact edit another benchmark's leaf.** The AI Coding Daily record is selected by the harness of the configuration's Bug Hunt record, and Bug Hunt's record is itself the largest-N result over harnesses (E206). So a new Bug Hunt run with a bigger N on CLI B silently flips the AICD leaf "although no AI Coding Daily row changed" — the draft's own words. E334 attributes the swing after the fact, but attribution doesn't justify a design in which incidental sample sizes, not configuration comparability, choose evidence. New argument: O123 now publishes the costed vendor agent per row, so the draft has a principled anchor it lacked when E268 was drafted. Recommendation: re-key AICD selection to the configuration's published costed agent (falling back to Bug Hunt's harness, then latest test date); editor decision, so no owner gate needed.

**Medium**

- **LiveBench Overall silently renormalises on missing categories.** LiveBench computes Overall as the weighted mean "of the suites with a score"  — a configuration missing a category gets a renormalised six-suite mean, a different estimand from peers on the full seven, and O52's "rank configurations that have all of it" is applied at leaf level, not category level within the Overall leaf. E256's plug-in SD also assumes seven categories over the released weights, and O122's build stop checks only the `_overall_weights` vector, not per-record category presence. Recommendation: a build check that every ranked LiveBench record carries all seven categories; a record short of one is flagged with its renormalised weights and excluded from interval outputs, exactly the O36/O38 pattern. ## 2. Methodology design recommendations

1. **Coverage-scaled reliability score** (design above): z\* = 50 + (I/2)·(1 − a/T), publication of (a, p) counts alongside; labels and bars consume z\*, headline keeps z for continuity with O28 until a versioned change.
2. **LiveBench category-completeness gate**: build stop on a ranked LiveBench record with a missing category or non-standard `_overall_weights`; flagged renormalised records contribute to ranking but not interval outputs; SD recomputed over the observed categories with the missing-suite variance removed from the plug-in (not set to max-variance).
3. **Attempt-policy parity matrix**: one published column per leaf (policy, attempts priced, match boolean); label eligibility requires match where both sides are public; unevaluable cells printed as such, following the O123 S2 "unevaluable" pattern.
4. **Anchor fragility diagnostic**: leave-one-reference-out recomputation per freeze; a reference whose removal moves any row's S_C by more than the ~3.3-point separability floor is named at freeze and at the O12 dual run. Also applicable to the small Plan measured-row panels O157 admits.
5. **Owner decision challenge (O170/O173) — robust, freezeable Bug Hunt scale**: normalise by a trimmed statistic (e.g., the board's q90 of planted+unplanted totals) frozen at each anchor re-freeze with an old/new bridge, instead of the live per-release maximum. New argument: the maximum is an extreme order statistic with the highest possible variance across the normalisation constants in the draft — every other leaf and both cost bases use frozen anchors for exactly this reason, and O173's ±10% stress quantifies the symptom rather than removing the cause.
