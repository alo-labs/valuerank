**Medium**

- **A blocker or provider-claimed row can set a frozen bar, with no disclosure.** Part 14's E92 parenthetical states that "a provider-claimed row that is not provisional still counts in the bar population, since a bar is a displayed-quality level" — and E183 makes such rows blockers that compete but can never earn a label. Because O34's ladder is an element of the order, a provider-claimed displayed quality can literally be the headline bar level H that every confirmed/possible qualification and every E45 cheapest answer is measured against, while that row itself could never be certified at the bar it set. Nothing in `barCurrency`, the bar record, or the O44/O171 companions currently flags this state. The E203 "displayed record, not a claim" caveat covers page displays, but H is not a page display — it is the reference object of the interval and scenario machinery (E52). This hurts the objective because the ranking's claim substrate can rest on an unverifiable record at exactly the point readers care most about. Recommended change: (a) record the setter's row status (blocker kind, provider-claimed leaves) in the frozen bar record, frozen with it like `levelSd`; (b) publish a verified-only ladder sensitivity (bar population less blockers) beside `costed_bar_ladder`; (c) when a live bar's setter is a blocker, print a one-line flag with the bar results. All implementable from data the registry already holds. I found no prior ledger entry covering a blocker-setter policy, so I believe this is new. [github_mcp_direct]
- **Owner decision challenge (O28): all-abstention maps to z = 50, mid-scale credit for not answering.** Part 14's own fixtures disclose it ("all-abstention → 50"), and the fixture (60,0,10,30) → (60,0,9,31) shows that converting a wrong answer into an abstention strictly *raises* z. Wisely, the leaf is only 10% of quality and the swing is sub-noise today, but the selective-prediction literature standard is to report coverage and risk separately precisely because a single scalar that grants mid-credit for withholding answers creates a gaming incentive, and incentive-aligned evaluations need explicit abstention treatment rather than accidental mid-credit.  New argument (not raised in the ledger for O28; the rejected items concerned the (2A+N)/3 form and the N denominator, not the abstention-midpoint property): the fix need not touch the owner's formula — publish participation rate (c+p+i)/T as a standing per-row diagnostic and flag rows below the cohort lower quartile in the headline, so an evasive configuration is visible where the z value alone hides it. Labelled as a challenge; the z form itself stays. [arxiv](https://arxiv.org/html/2610.16318v1)

## 2. Methodology design recommendations

Prioritised, all implementable from data already captured:

1. **Blocker-aware bar integrity (from the Medium finding).** Extend the bar policy object with `setterRowStatus` (ranked-clean / blocker-kind) frozen at the re-freeze, and add a `verified_bar_ladder` sensitivity computed by dropping B_W rows from the ladder population before applying floor((n−1)k/4). No formula changes; the population filter is a one-line registry join. If both ladders differ, print both with the flag naming the setter.
2. **Harmonise the S1-core kernel suite with O142.** The label kernel checks currently enumerate A = {uniform, arcsine}^G with two conventional families (E112/E137 machinery), which the draft itself warns "never implies… broader distributional robustness". O142 already moved S1T's binomial leaves to a Jeffreys Beta posterior. Register a Jeffreys-Beta identification kernel as a third assignment family for missing-leaf primitives in the S1 core, and a point-mass kernel at the observed-leaf value as the degenerate robustness probe; publish the expanded frequency range exactly as today. While O36 holds this is dormant, so the marginal cost is registry entries plus fixtures, not solver work.
3. **Reliability-leaf participation diagnostic (from the owner-decision challenge).** Per row, publish participation p_i = (c+p+i)/T and coverage-adjusted risk i/(c+p+i) beside the Omniscience leaf; add a headline flag when p_i falls below the cohort's lower quartile. Formulas need only the counts AA already publishes and the draft already captures at full precision.
4. **Close the scenario-event convention (from Low 1).** One sentence in E100 plus one fixture: "the author's share is #s(wins)/#s(drawn); a scenario where any role in the event is undefined counts as drawn and not a win."
5. **Pin E204 capture geometry** (from Low 2): store device pixel ratio, chart bounding box and axis mapping with the E216 model-page snapshot; code the 0.5 px test against those recorded values.
