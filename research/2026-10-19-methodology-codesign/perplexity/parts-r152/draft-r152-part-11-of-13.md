- **Interval decision procedure (E40, amended by E43).** Interval labels are decided by deterministic, decision-specific feasibility problems over Θ, never from scenario draws. Primitive domains have a box enclosure (per-row input boxes and a box of declared shared factors, e.g. a common price list or a donor multiple shared by several rows); Θ itself is the constrained subset defined by E73, and a product-box representation may replace it only under a decision-specific equivalence proof (E169). **Constrained evidence model (E73)**: the primitive-variable constraint graph Θ = {v : ℓ ≤ v ≤ u, h(v) = 0, g(v) ≤ 0} is authoritative; costs, quality, capacities and multiples are derived quantities of v (an identity such as API-valued capacity = λ × C_API survives uncertainty propagation). A box reduction is used only with a decision-specific equivalence proof; otherwise the box is an outer enclosure for pruning, and every witness is certified against the original constraints (release fixture: an enclosing box containing a favourable state the original constraints exclude must never return a certified possible membership). **Separability condition (E89)**: with no shared factor **and no row-local coupling** — each row's C and Q depend on disjoint primitives with no joint constraint, so the row's feasible set is the product of its C and Q ranges — each label is decided exactly by monotone extremes (Q is linear in leaf values; basket cost is monotone in component costs; each row's inputs move only its own C and Q): e.g. possible-frontier membership of i is established by setting i to its best corner and every j to its worst. A row-local primitive or constraint that enters both C_i and Q_i is a coupled variable and is branched over like a shared factor; a constraint class the solver does not support returns unresolved (release test: i with C_i = 1 + t, Q_i = t, t ∈ [0, 1]; j with C = 1, Q = 0.5; k with C = 1.5, Q = 1 — i is dominated for every t although its box corner (1, 1) is undominated, so the solver must return disproved and never a possible membership). In v1 every row's C and Q come from distinct published records, so the condition holds and is asserted per release. With shared factors or row-local coupling, labels are decided by **certified interval branch-and-bound** over the shared-factor box: on each sub-box, interval bounds either certify the condition for every point (witness), refute it for every point (prune), or the sub-box is split, up to a published depth; a sub-box still undecided at that depth returns **unresolved**. Endpoint search alone is not sufficient (release test: competitors with Q_j = 2t and Q_k = 2(1 − t), C_j = C_k = 0, and i with C_i = 1, Q_i = 1.2: i is a possible-frontier member via the interior witness t = 0.5). Possible-frontier membership solves, in one common θ, for every j ≠ i: C_j(θ) > C_i(θ) ∨ Q_j(θ) < Q_i(θ) ∨ [C_j(θ) = C_i(θ) ∧ Q_j(θ) = Q_i(θ)]; definite membership is disproved by one θ and one dominating j; strict inequalities are decided exactly, never by tolerance alone. Every returned witness is re-checked against the original equations and shared constraints. The monotone-corner shortcut is used only for decisions with a documented corner-reduction proof; dependencies are compiled from the complete decision equations, so a varying reference quality Q_r is a shared variable for every qualification condition even when all row inputs are independent (E50; a frozen bar level is a constant and adds no shared variable, but the rule binds any registered varying reference): bar decisions partition at qualification breakpoints (exact enumeration for affine one-dimensional thresholds) or use the certified branch-and-bound (regression test: i with C = 1, Q = 5; j with C = 0, Q = 4; Q_r ∈ [0, 10] — i ∈ K_r via the interior witness Q_r = 4.5, which neither endpoint shows). Feasible witnesses and infeasibility certificates have separate proof obligations, and numerical bounds may not discard feasible points through floating-point error. Statuses: certified / disproved / unresolved / unevaluable, with solver status, depth and witness (or counterexample) stored; an unresolved solve is never shown as certified. **Certification grammar (E108)**: each decision is compiled into (1) primitive domains and the original constraints, (2) a reduced problem obtained only by documented, equivalence-preserving substitutions (definitional equalities are eliminated by substitution wherever possible) and (3) a certificate checked independently against the original problem. Supported v1 classes: boxes, affine constraints decided in exact rational arithmetic on the published decimal inputs, separable monotone transforms and the documented corner reductions; a nonlinear equality is supported only with a validated existence certificate (e.g. a sign change of a continuous univariate function evaluated exactly at rational endpoints); every other class returns unresolved, and a small numerical residual is never a feasibility certificate (fixtures: x² = 2 with x ∈ [1, 2] is certified feasible without a rational witness; x² = 2 with x ∈ [1, 1.4] is certified infeasible; an approximate point with residual 10⁻⁶ certifies nothing). **Feasibility prerequisite (E79)**: before any decision, the decision's full constraint component (all connected shared variables and identities) must have a certified feasible witness checked against the original constraints; certified infeasible → "inconsistent evidence", no frontier or bar labels for the affected output, release-blocking for that output with the conflicting records listed; feasibility unresolved → "unresolved", no confirmed or definite label (fixtures: individually valid intervals whose shared identity has an empty intersection; a feasible outer box whose original constrained set is empty — neither may produce a confirmed, definite or certified-possible result).
- **Workday-feasible Plan multiple (diagnostic, E15).** Owner decision O3 keeps full utilisation as the scored estimand. Where the quota schema is evidenced, the same capacity program is also solved with consumption allowed only in a pre-registered 40-hour week (8 h × 5 days); M_workday and the ratio M_workday / M_full are published per route as a diagnostic, never scored. **Calendar (E117)**: both solves use the same recorded fee period, initial balances, purchase policy, reset-phase evidence and quota semantics; the workday solve adds only an availability indicator A(t) with y_t = 0 where A(t) = 0, from a versioned calendar (IANA time zone and daylight-saving treatment, local weekdays and daily hours, exact fee-period start and end, partial days and weeks); regression test: the workday maximum eligible consumption never exceeds the full-utilisation maximum (with consumption-dependent payments the multiple ratio is not assumed ≤ 1).
- **Harness stress branch (E19, premise corrected by E227).** Bug Hunt runs on vendor CLIs, AI Coding Daily on a harness chosen per model, and tbench.ai's matched rows mostly on vendor agents; Vals and LiveBench run one harness for every model; since O37 the Terminal-Bench leaf is AA's own run on one harness (mini-SWE-agent), so only a tbench.ai gap fill carries an agent. - **Target-basket readiness (E22, diagnostic).** Per target component: inclusion status, missing configurations, task multiplicity, cost availability, priced quality weight. Per scored model: expenditure share s_ie = n_e c_ie / C_i,W per component and concentration HHI_i = Σ_e s_ie². A **task-family overlap matrix** (E42) accompanies it (e.g. Terminal-Bench inside both the Index run and the Coding Agent Index); family-level concentration is "unidentified" where aggregate costs cannot be separated. No single unlabelled coverage percentage.
- **Robustness outputs (E13, amended by O22).** Separate, named columns: (1) displayed-score rank sensitivity (scalar displayed value score); (2) full-composite scenario-rank sensitivity (scalar V_i(θ) = 0.25 S_C(c_i(θ)) + 0.75 Q_i(θ)); (3) branch evaluability and exclusion reasons, with retained quality weight shown before any rank statistic. Numerical rank change is computed only within evaluable branches; an unevaluable branch gets no rank. **Paired panels (E65)**: every baseline-versus-branch rank difference is computed on the two runs' common evaluable panel I_b (ranks of both runs taken within I_b, one declared tie convention), with panel size, excluded rows, both scores, retained quality weight and workload hash published; a maximum across branches names its branch and panel; release-wide rank changes, if shown, are labelled as including composition effects. "S2 maximum rank change" refers to (1). **Standing sensitivity columns (E64)**: maximum rank change when the AA Index-run Terminal-Bench cost is removed from C_W (the double-priced execution, O24), and when Bug Hunt is left out of quality; the attempts reconciliation publishes a worked example of a deployment-policy bias bound.
- **Cohort rule (executable).** F(c) = best rounded Index among rendered-frontier configurations with cost ≤ c. A family is near-frontier when a plotted configuration's rounded Index ≥ F(c) − 3. **Membership (O51)**: the cohort is exactly the plotted configurations on the rendered frontier plus those with rounded Index ≥ F(c) − 3, each its own row; no other configuration enters it. A point cheaper than every rendered-frontier point has no F(c) and is not near-frontier; at that cost it would be on the frontier itself. **Left of the rendered line (E204)**: AA's line is used as observed, so the build checks that no plotted point lies left of the path's first vertex (by chart x-coordinate, tolerance 0.5 px). If one does, the build stops and names it until the owner records a dated, reasoned decision for it, so such a point can never drop out silently. Today none does: on the capture the first vertex, GPT-6 Luna (low) at $10.63, costs the same as the cheapest of the 190 plotted points ($10.63), and the build fails otherwise. Every near point publishes its cost ratio to the frontier for information only: its total Index cost divided by the lowest cost of a rendered-frontier point whose plotted (tooltip, rounded) Index is at least its own; the ratio never gates inclusion (AGENTS.md). A near-frontier family is deferred only by a dated, reasoned roster decision recorded in the reconciliation inventory, and it stays listed there. Ties go to the lower cost, then the name. The family key is the plotted model name with its trailing parenthesised qualifier (effort and "with fallback") removed. It must equal the catalog model's display name, and the build checks this.
- **Omniscience counts (O28).** From AA counts (c correct, p partial, i incorrect, a not attempted; T = c + p + i + a): I = 100 (c − i) / T and z = (I + 100)/2. Test vectors: c=60, p=0, i=10, a=30 → I = 50, z = 75; monotonicity fixtures — (98, 0, 1, 1) → z = 98.5 and (99, 0, 1, 0) → z = 99 (an abstention turned correct raises z); (60, 0, 10, 30) → (60, 0, 9, 31) raises z (a wrong answer turned abstention); all-abstention → 50. The reconstruction I = 100 [A − h (1 − A)] from AA's accuracy A and conditional hallucination rate h is tested against AA's published index each release.
- **Plan capacity under multiple pools.** Where public controlled measurements establish additive consumption per budget w (a_wk per token of category k, spendable capacity B_w over the fee period) and d_k = tokens of category k in one complete workload pass (d_iW, E94): λ_w = B_w / Σ_k a_wk d_k, λ = min_w λ_w (workload passes per fee period), M = λ × C_i,W / F_gross, where B_w must be attainable over the fee period: billing boundaries, reset phase (e.g. account-specific weekly reset times), carryover and evidenced throughput limits are recorded, and where windows and billing periods misalign capacity is computed by a small time-indexed linear program (maximise Σ_t y_t subject to the window constraints), or a conservative bound when scheduling feasibility is not established. **Window semantics (E30)**: each window is encoded as recorded in the quota schema — session-anchored windows start at first use; fixed-reset windows at their recorded reset times; sliding windows as ∀t: Σ_{τ∈(t, t+h]} a_wτ y_τ ≤ B_w; unknown semantics use the conservative sliding form for the achievable-capacity schedule only. **Semantics identification (E115)**: where the reset mechanism is not publicly established, the route records a set S_r of publicly admissible mechanisms (semantics_status established / unresolved, admissible_semantics with evidence, lower_bound_scope, upper_bound_scope, capacity_identified_across_semantics, initial-balance and reset-phase domains); the certified bounds must enclose the consumption-optimal, minimum-cash multiple (E105) under every s ∈ S_r — L_r = min over s of the verified lower bounds, U_r = max over s of the relaxed upper bounds — and a point is identified only when they coincide; if a covering upper bound cannot be established, the route reads "semantics unresolved; conservative achievable capacity only", the bound is a published one-sided diagnostic and M_W stays unidentified, so under E106 the displayed multiple remains M_observed (fixtures: sliding and fixed-reset both admissible with different capacities → no point identification; both give the same certified capacity because an independently established bottleneck binds → point identification permitted). Model-specific sub-caps inside a shared pool and model-specific burn coefficients are separate constraints, never borrowed from another model. **Schedule contract (E39)**: time is discretised on a published grid (default 15 minutes) with stated boundary treatment; fixed-phase windows are ordinary time-indexed constraints; session-anchored windows use explicit session-start variables (a session starts at the first consuming step after the previous session ends) or, equivalently, enumeration of admissible session schedules on the grid; where public semantics are insufficient, a documented feasible conservative schedule is used instead of an unconstrained optimum. Every identified capacity result publishes **feasible_lower_bound** (from a verified feasible schedule), **relaxed_upper_bound** (from a valid relaxation of the same public quota semantics), grid_resolution and optimality_scope (E56); an event-aligned grid is used where public reset times permit it; a point capacity is certified only when the two bounds coincide under the recorded semantics, otherwise the interval [lower, upper] is carried into Θ as a structural bound on M_W. A grid optimum is never reported as the target capacity optimum. This λ / time-indexed LP is the **only governing Plan formula** (release tests: loosening a non-binding 5-hour cap cannot change a plan whose weekly cap binds; two bursts one hour apart, each 60% of a 5-hour cap, are infeasible; the same bursts six hours apart are feasible). Harmonic-style category combination is used only where a common additive budget is established; otherwise the observed-mix multiple is kept with its mix-unmatched flag and target-mix capacity is reported as unidentified. Provider quota descriptions may document structure but never supply the numerator, except under the two owner exceptions (the O46 MiMo quota ceilings and the O76 speed-mode conversion). **Capacity target (E69)**: the scored Plan target is **token-equivalent capacity** — API-priced consumption, which is how value is defined on the Plan basis — so a divisible aggregate demand vector is the estimand, not a relaxation of it. Completed-work feasibility is a separate diagnostic: each route records a workload-execution mode (divisible / task-level resumable / task-level non-preemptible); where public task-level records exist, a verified feasible task schedule gives the completed-pass capacity; **same units (E76)** — token-equivalent capacity is first expressed in workload-equivalent passes (API-valued capacity ÷ cost of one deployment-equivalent pass of W) and the completion ratio completed ÷ token-equivalent is shown only when both cover the same complete workload, deployment policy, horizon, funding policy and valuation basis; partial task-level coverage is a named restricted-support diagnostic; otherwise completed-pass capacity is "not identified" and never substituted for the scored target.
- **Dependence.** Every uncertain input records interval meaning (rounding / published CI / observed range / identification bound / analyst stress range), sampling law with justification, and dependency identifier with supporting paired evidence. Costs and outcomes are resampled jointly only when paired task/run observations are public; otherwise shared factors (same price list) are kept and independent / positive / negative dependence stress branches are published; interval outputs use conservative joint bounds.
- **Bug Hunt estimand (E29).** The measurement is the mean of the published runs for the exact model, effort and harness (pooled fixed/105 per complete run; run count recorded; owner-published means and run-level results where public). Run-to-run spread from public repeated runs is measurement evidence; repository differences are a repository sensitivity, not repeats. Under O25 the record is the published mean (a single-run row's record is its single run), so run-to-run spread never enters Θ and, in v1, no scenario stream (E145, E155): it is published beside the leaf as measurement evidence and may enter only a separately named repeatability stream; any analyst repeatability band is sensitivity-only; cohort spread is never used as exact-variant evidence.
- **Provenance and exposure (E57).** Per leaf: dataset origin, execution organisation, harness, grader.
