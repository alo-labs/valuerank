- **Admission and persistence (E26).** A component is admitted to workload version W when exact-configuration cost exists for every configuration in W's frozen, named **reference panel**, published with W and containing at least two-thirds of the cohort rows at admission; until admitted it is listed as "pending capture". **Panel construction (E95, selection by E140)**: one panel per workload version, built deterministically before scores or ranks are inspected. With P(S) = the cohort rows with **complete cost evidence** (CompleteCostEvidence, E37 as set by O27: exact cost and no AA missing- or declined-task marker) on every component of S (E101), the admitted set is chosen by enumerating every subset S of the target components (2ⁿ subsets of the n targets; **admission units, E148**: the units are exactly the named targets of O15 as amended by O50 and O137, eight since the v5 basket (the six Index SDLC evaluations, the Coding Agent Index v2.0 and ITBench-AA; O137 retired O116's FrontierCode stand-in), each counted once whatever its accounting representation — the Coding Agent Index is one unit, not its three sub-benchmarks; a unit's complete evidence enters only at unit level, as an accepted aggregate or a complete compatible decomposition first composed by the accounting tree, so K_iu is identical under either representation; raw accounting children never enter admission and the build rejects any component outside the unit registry; adding a unit is a basket-version migration; fixture: N = 6, unit A complete on rows 1–4, units B and C on rows 3–6 — B + C is admitted, and A presented as its sub-benchmarks is rejected rather than counted as three units) with |P(S)| ≥ ⌈2N/3⌉ and maximising, lexicographically, the number of admitted components (O15 lists them without priorities), then |P(S)|, then the earliest components in the published target order; P(S) of the selected set is the reference panel, and the selected subset, its objective tuple and the feasible alternatives are published (fixture: components A on rows 1–5 and B and C each on rows 1, 2, 3, 6 with N = 6 — a greedy coverage order admits only A, enumeration admits B and C). - **Workload object W** (versioned, hashed): the set of unique execution components (e, n_e) with frozen task multiplicities, configuration and deployment policy; C_i,W = Σ_e n_e × c_ie, where c_ie is cost per workload task for **one deployment-equivalent pass** (extra evaluation repetitions excluded, matching AA's totals; E9). Aggregates (e.g. the Coding Agent Index total) and their components are mutually exclusive in the accounting tree — an aggregate is either a reconciliation check or a substitute, never additive; a machine-checkable accounting tree is published. Adding or removing a component is a workload migration with an overlap bridge (old vs new basket costs, scores and ranks for configurations evidenced under both) and Plan-transport revalidation.
- **Missing component for a row (O17)**: the row is scored on its available subset and stays ranked in the one ordinal ranking (owner decision O117, 2026-10-29), flagged "subset cost — cross-workload ordering not identified", with its cost compared on that same subset, never by summing fewer items against full-basket costs. **Subset calibration contract (E10)**: each subset used is a versioned workload W_S (hashed components and multiplicities) with its own frozen anchor object from the reference configurations evidenced on W_S, built by the same rule; paired full/subset costs, scores, exchange rates and rank differences are published wherever both are evidenced; missing component costs are never filled to build the bridge. The row keeps its owner-required score and table position with that label, and is "unevaluable" for the frontier and bar outputs on W. **Subset-workload interval outputs (E190)**: the frontier and bar outputs are also published on each subset workload W_S over every row with FullCost on W_S (today the subset rows are MiMo-V2.6-Pro in the max-effort ranking and none in the AI Coding Daily ranking, and the max-effort ranking's 1-row API subset stratum reads "undefined (panel too small)" and the max-effort ranking's 4-row Plan subset stratum reads "undefined (one configuration)"), labelled with their workload; the W outputs stay primary and orderings across W and W_S are not identified. **Missing-share disclosure (E173)**: beside each subset row the release publishes, for each missing component, its expenditure share among the rows evidenced on both W and W_S (median and range, from E22; scores.json `diagnostics.subsetBridges`) next to the paired full/subset summary above; the subset row is scored against W_S anchors from the reference configurations evidenced on W_S, so the direction of the subset effect depends on the row's unobserved share relative to theirs and is not stated as known. **Anchor applicability (E86)**: every row carries its workload ID, anchor-object ID and applicable cost-doubling exchange rate; the main-workload rate is shown above the table, subset rows are marked as using a different rate, and the cost-weight slider keeps each row's own anchor object. - **Matched-cost diagnostic (diagnostic only).** C_i^match = Σ_{g∈G} ω_g P_ig over canonical **execution families** g (E55; e.g. FrontierCode, Terminal-Bench as executed by AA): quality-weighted **complete benchmark passes** (E24), with P_ig = cost of one complete deployment-equivalent pass of family g for configuration i (Σ of its accounting subcomponents; published task count × mean cost per attempted task) and frozen diagnostic weights ω_g (Σ ω_g = 1, from the quality weights of the leaves that reference g, fixed with the panel before ranks are examined); a quality leaf references exactly one execution family; model API token charges only (input, cache read/write, reasoning, output × the primary price list; sandbox, environment-setup and verifier compute excluded; E17); where a source cannot separate retry or harness tokens the leaf is not priced for that row; tbench.ai cost columns are never joined. The execution family set G may include any leaf with exact-variant per-task cost (AA per-evaluation costs, FrontierCode, Terminal-Bench). Published warnings (reference cost C_i,W, never the Index total): (a) pairwise reversal — C^match orders two rows opposite to C_W with both intervals separated (overlap or tie = no reversal); (b) R_i = (C_i^match / C_i,W) / median_{j∈I}(C_j^match / C_j,W) > 1.5 or < 1/1.5 **and** a rank difference on C^match vs C_W of more than 3 places within the common model panel I. Below 40% priced quality weight, or when a row lacks the panel, the cross-check is "unidentified". A feasibility matrix (row × priced leaf: exact-variant and stack compatibility, available cost, panel weight) is published with the panel-selection rule fixed before ranks are examined. Cost per solved task is shown alongside. **Diagnostic object (E103)**: the matched-cost diagnostic is its own versioned object D = (family set G, weights ω_g, leaf-to-family map, price rule, panel rule) with an identity hash; a new cost observation under an unchanged D is a data refresh, while a changed family set, mapping or weight vector creates a new D, and reversal warnings are compared across releases only through an old/new bridge on the common evidenced panel that separates cost-data changes from diagnostic-composition changes.
