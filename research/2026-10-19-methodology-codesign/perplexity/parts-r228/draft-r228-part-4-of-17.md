- **Workload object W** (versioned, hashed): the set of unique execution components (e, n_e) with frozen task multiplicities, configuration and deployment policy; C_i,W = Σ_e n_e × c_ie, where c_ie is cost per workload task for **one deployment-equivalent pass** (extra evaluation repetitions excluded, matching AA's totals; E9). Aggregates (e.g. the Coding Agent Index total) and their components are mutually exclusive in the accounting tree — an aggregate is either a reconciliation check or a substitute, never additive; a machine-checkable accounting tree is published. Adding or removing a component is a workload migration with an overlap bridge (old vs new basket costs, scores and ranks for configurations evidenced under both) and Plan-transport revalidation.
- **Missing component for a row (O17)**: the row is scored on its available subset and stays in the ranking's table (owner decision O117, 2026-10-29) but, its cost being on another workload and anchor object, takes no rank among the main-workload rows: it is ranked within its own workload, shown as "N (own workload, O184)" (its rankWithinWorkload and rankNote fields where a ranking has such a row; owner decision O184, 2026-11-05, on reviewer 105), flagged "subset cost — cross-workload ordering not identified", with its cost compared on that same subset, never by summing fewer items against full-basket costs. **Subset calibration contract (E10)**: each subset used is a versioned workload W_S (hashed components and multiplicities) with its own frozen anchor object from the reference configurations evidenced on W_S, built by the same rule; paired full/subset costs, scores, exchange rates and rank differences are published wherever both are evidenced; missing component costs are never filled to build the bridge. - **Matched-cost diagnostic (diagnostic only).** C_i^match = Σ_{g∈G} ω_g P_ig over canonical **execution families** g (E55; e.g. FrontierCode, Terminal-Bench as executed by AA): quality-weighted **complete benchmark passes** (E24), with P_ig = cost of one complete deployment-equivalent pass of family g for configuration i (Σ of its accounting subcomponents; published task count × mean cost per attempted task) and frozen diagnostic weights ω_g (Σ ω_g = 1, from the quality weights of the leaves that reference g, fixed with the panel before ranks are examined); a quality leaf references exactly one execution family; model API token charges only (input, cache read/write, reasoning, output × the primary price list; sandbox, environment-setup and verifier compute excluded; E17); where a source cannot separate retry or harness tokens the leaf is not priced for that row; tbench.ai cost columns are never joined. The execution family set G may include any leaf with exact-variant per-task cost (AA per-evaluation costs, FrontierCode, Terminal-Bench). Published warnings (reference cost C_i,W, never the Index total): (a) pairwise reversal — C^match orders two rows opposite to C_W with both intervals separated (overlap or tie = no reversal); (b) R_i = (C_i^match / C_i,W) / median_{j∈I}(C_j^match / C_j,W) > 1.5 or < 1/1.5 **and** a rank difference on C^match vs C_W of more than 3 places within the common model panel I. Below 40% priced quality weight, or when a row lacks the panel, the cross-check is "unidentified". A feasibility matrix (row × priced leaf: exact-variant and stack compatibility, available cost, panel weight) is published with the panel-selection rule fixed before ranks are examined. Cost per solved task is shown alongside. **Diagnostic object (E103)**: the matched-cost diagnostic is its own versioned object D = (family set G, weights ω_g, leaf-to-family map, price rule, panel rule) with an identity hash; a new cost observation under an unchanged D is a data refresh, while a changed family set, mapping or weight vector creates a new D, and reversal warnings are compared across releases only through an old/new bridge on the common evidenced panel that separates cost-data changes from diagnostic-composition changes.
