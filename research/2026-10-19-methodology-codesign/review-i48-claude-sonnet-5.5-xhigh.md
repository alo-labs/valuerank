**M2. The README explains a cost allocation above 100% with the covariance the wrong way round, and E196's parenthetical ("or the reverse") is the ambiguity that allows it.**

- Where. Draft lines 48–50: a negative allocation "or one above 100%, which makes the other term negative … is printed as it is, with the sentence that the negative term offsets the other's spread instead of adding to it (dearer configurations scoring higher on quality, or the reverse)". Published: README.md line 11 now says "an allocation above 100% means quality's is negative: cheaper configurations score higher on quality, so quality offsets cost differences instead of adding spread of its own"; the code is `emit_docs.influence_text` (lines 385–390), added in r106 for I47 L1.
- Why it is wrong. The cost score S_C rises as cost falls. Quality's allocation is (0.75² Var(Q) + 0.75 × 0.25 Cov(S_C, Q)) / Var(V). It is negative only when Cov(S_C, Q) is strongly negative, that is when dearer configurations score higher on quality. If cheaper configurations scored higher on quality (Cov > 0), both terms would be positive and neither allocation could exceed 100% or go negative. From `scores.json` the max-effort API panel (7 rows) has Cov(S_C, Q) = −173.0 (Claude Opus 5.5 (max): cost score 12.2, quality 67.9; Claude Sonnet 5.5 (max): 13.0, 67.1; GPT-6 Luna (max): 87.8, 47.4), Var(Q) = 57.3 and Var(V) = 7.1, so quality's allocation is (32.2 − 32.4) / 7.1 = −3.1% and cost's is 103.1%, the figure the README prints. The branch for a negative cost allocation (the AI Coding Daily ranking, −90%) prints the correct "dearer configurations score higher on quality"; the >100% branch prints its opposite. My I47 L1 named the cause as "cheaper configurations score lower on quality"; the implementation reversed it.
- Why it hurts. This sentence is how the published README interprets the 25% weight in its lead paragraph, for the leading ranking's API basis. A reader is told the data show the opposite of what they show, and the draft's clause does not tell an implementer which reading is meant: "or the reverse" of "dearer configurations scoring higher on quality" is never a cause of a negative term (the same negative covariance drives both cases, and only which term is negative differs).
- Recommended change. Replace the parenthetical with a sign rule: "in both cases the covariance of cost score and quality is negative: dearer configurations score higher on quality, cheaper ones lower; the sentence names which term is negative". Print for the >100% case: "an allocation above 100% means quality's is negative: dearer configurations score higher on quality, so quality's differences work against cost's". Add a unit test that derives the expected direction from the sign of Cov(S_C, Q) on the fixture panel, so the sentence cannot contradict the panel it describes.
