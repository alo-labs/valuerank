## 2. Methodology design recommendations

1. **A cost-source pin-completeness gate (priority 1; addresses H1 and L4).** At each AA capture, for every cohort configuration list the Coding Agent Index records and the chart bars (ITBench-AA; FrontierCode if it ever returns) whose model identity and effort equal the configuration's. The build fails when such a record exists and the pin is `null` without a dated, reasoned decline, and when a pinned label is absent from the current capture without a recorded reason (the eight stale labels today). Publish the table as `scores.json` `diagnostics.costSourceMatch` (configuration × source: pinned record, none exists at AA, or declined with reason) and cite that field wherever the draft states "priced for N of M". Put the match rule in the specification: same model identity and effort, fallback token not required for AA's agent page, a vendor-agent preference list with a build stop on several single-model agent rows (E225's pattern), a mixed-model row never exact. This is the cost-side twin of E211 and E239 and costs one function.
2. **A record-selection contract for every third-party board (M2).** Generalise E206/E224/E225 into one registry rule: when a source lists a configuration more than once, the registry names the selection key (largest N where the source publishes one; same harness as the configuration's other agent evidence; latest test date; then a recorded reason), the build stops on an unresolved tie, and the unselected rows are published beside the leaf with the leaf's sensitivity (here 0.10 quality points). Apply it to AI Coding Daily now; it is already needed for Vals and LiveBench the day either lists a model twice.
3. **One clock for every route (M1).** Give every route record `evidenceDateBasis` (measurement window end, publication date, authorisation date, donor's date, or read date for an O46 ceiling) and have `evidence_date` return it with the basis; print the basis next to `rows[].plan.evidenceDate`. A reviewer can then see which sentence of the lifecycle applies without reading code.
4. **Extend the figures check to dated sentences that describe the current release (L5).** Provide placeholders for the reporting window, the search cutoff, the vertex count and the stage dates, and make the lint fail on a date or a count that equals a current registry value but is typed by hand, in any sentence. That finishes E265 for registry facts as the placeholders did for scores.
5. **A data-correction bridge.** When a pin or a capture changes after the anchors were frozen (as H1's fix will), the dual-run of E197 should be run automatically and its row-level value and rank changes printed in the release record, so a correction is visible as a correction and not as a drift. Today E197 is described for the clip gate only.
