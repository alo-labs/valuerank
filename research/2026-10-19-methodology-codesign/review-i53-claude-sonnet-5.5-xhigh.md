**M1. The E267 label grammar leaves out the one label that prices a ranked row.**
Where: Cost section, "Cost-source match (E267)" (folded lines 172–176, the sentence at 174: "The label is read in AA's two effort forms, ' (max)' and ' ({'reasoning_effort': 'max'})', compared case-sensitively as AA prints it; a label in any other form is not exact, so a row whose only record is in such a form is priced without it on its own subset workload and flagged (E254)"); `value_v3.parse_agent_label`.
Issue: of the 24 labels in `data/aa/coding_agents_capture.json`, one carries both forms at once: "Codex - GPT-6 Luna (max) ({'reasoning_effort': 'max'})". It is the only record for GPT-6 Luna (max), a row of both rankings, and it is what the draft's "8 of the max-effort ranking's 9 rows" counts. `parse_agent_label` reads each form independently, accepts the label when the efforts agree and returns None when they disagree (the E267 test covers only the disagreeing case, "Odd - X (max) ({'reasoning_effort': 'low'})"; the real Luna label is not a fixture). The draft states neither that the two forms may co-occur nor that they must agree. Read literally ("a label in any other form is not exact"), a label that is neither " (max)" alone nor the keyed form alone is not exact, so GPT-6 Luna (max) would be priced without the Coding Agent Index on the subset workload. Its value and rank, the main workload's reference panel (8 to 7 rows) and the anchors would then change, and the draft's own count would be 7 of 9. A related gap: the fallback token is stripped only as a trailing " (with fallback)", and the draft says only that the match "ignores" it; AA's chart form "(max with fallback)" would not be recognised, and nothing in the draft says so.
Why it hurts: two faithful implementers get different rankings from the same capture, and the draft's count contradicts its own rule. This is the fourth round in a row on the same link (I50 H1, I51 M1, I52 M1): the rule was rewritten from the code's intent and never run against the real label list.
Change: state the grammar once and exactly: label = agent " - " model [" (" effort ")"] [" ({'reasoning_effort': '" effort "'})"] [" (with fallback)"]; when both effort forms occur they must name the same effort; a disagreeing pair, a "+" label or any other form is not exact. Make the real Luna label and the disagreeing label fixtures. Add the silent-failure guard in Section 2 recommendation 2, so a new AA label form is reported instead of quietly moving a ranked row to a subset workload.

## 2. Methodology design recommendations

Prioritised.

1. **Close the class "a join keyed by a hand-formed string" with a brute-force audit, not another pin gate.** I50 H1, I51 M1, I52 M1 and now M3 are the same defect in four places: a lookup keyed by a label, pin or display name that silently drops rows. Add one test module that recomputes every cross-source panel and every external-record match independently from the two captures (Coding Agent Index labels by parsing, Cognition by (family, effort), tbench.ai, Bug Hunt, the three added boards) and asserts equality with what the build published, listing any row that has a candidate in the other source but is not in the panel. The test needs no new data and would have caught M3 and the Luna label.
2. **Make the E267 grammar total and loud.** Publish a census in `scores.json` (for example `diagnostics.agentRecordCensus`): for each captured label, its parse (agent, model, effort forms, fallback) and the configuration, if any, for which it is exact. Stop the build when a label fails the grammar and is not a "+" label. Today an unrecognised new AA form would not stop anything: the row would drop to a subset workload, flagged, and an admission decision (8 of 9 against a threshold of 6) could flip without anyone noticing.
3. **Give the search log a provider-coverage field and derive "all-provider" from it** (L1), so E218's 7-day gate rests on what was searched and not on a flag set by hand.
4. **Cover qualitative current-state claims the way numbers are covered.** M2 is a qualitative sentence about today with no digit in it. A small `{{claim:ID}}` mechanism (a predicate over `scores.json` that renders the sentence's variable part, as the 1-row stratum status and the "keeps its row in all three" line now do) would let the check reach the sentences it cannot lint: "today none:", "no ranked row is ...", "every bar keeps its row". Start with the dozen "today none/every" statements in the cost and uncertainty sections.
5. **Extend the lint to effort-less configuration names** (L3) and give historical sentences an explicit date marker (L2), so the name rule does not force placeholders into history.
