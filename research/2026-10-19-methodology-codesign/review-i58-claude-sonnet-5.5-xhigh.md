## 2. Methodology design recommendations

1. **Make every generated enumeration total (M1, L1).** In `draft_figures.py`, compute each "today the X are …" list as a partition with an explicit residual class and fail the render when the residual is non-empty. Do the same for sentence pairs that quote a count and a list (9 excluded and its classes; 4 in both and its names). This turns the recurring "a list went stale when a primary moved" class into a build error, in line with E265.
2. **Separate scrape instants from build stamps and register every board (M2, M3).** Give each non-AA source in a `sourceBoards` registry `{url, readAt, lastUpdate, lastRecordDate}`. Make the clocks read `readAt`. Add a gate "every board used by a ranking has `readAt` later than the previous release cutoff" so O68's re-read is mechanical, as O64's manifest made the Coding Agent Index closed-world. Then the scope question (which boards) becomes a registry entry, not a sentence.
3. **Refine O60 to the record level where a board publishes record dates (L4).** Fail, or require an owner note, when a matched record's own date is on or after the cutoff's day; mark a date derived from a relative age as "inferred" in `swe_tracks.json` with the instant of the read. This keeps O60's intent without changing any score today.
4. **Generate leaf-formula prose from the engine's own objects (M4, L2).** One source (the leaf table, `swe_tracks.json` source metrics and the weights object) should feed the draft's leaf table, `methodology.md`, the site notes and the S1T list, so a change such as O67 cannot leave a plain-mean description behind. Likewise publish `ownerStatedEfforts` (MiMo-V2.6-Pro high, Kimi K3.1 Pro max) in `scores.json` and render E206 and E267 examples from it.
5. **Publish a between-capture record-update line for AA values that E90 assumes frozen (L5).** Rows moved, largest absolute move, anchor model unchanged, per field. It costs one table and makes the "one published record" premise something the build tests.
6. **Optional, no priority:** when the cutoff is the model-page snapshot's instant, say so once (it explains why the chart capture, taken 3 minutes earlier, is "before the cutoff" and why O65 can move it), and drop the three scattered O47 attributions.
