## 2. Methodology design recommendations

Prioritised. All use public data refreshed routinely.

1. **Make O71 report admission a build-derived, machine-readable object (closes L1, L3, L4).** O75 puts three research stages into every release, so the next release is the first that could push a report pair through code that has only run on synthetic fixtures. Add `data/plan_reports.json` with one row per observer's report: `id`, `observer`, `upstreamSource`, `sourceUrl` and archive hash, `model` and `modelBasis` (stated / inferred), `tier` and `tierBasis`, region or currency, dates (`windowStart`, `windowEnd`, `reportDate`), `meterTie` (fraction / exhaustion / none) with the window kind (5-hour / weekly / monthly), `apiPricedUsd` as `[lo, hi]`, speed mode. A build step applies the profile and prints, per (model, plan) cell, each report's status with its reason, the partitions (split at the registry's dates, a spanning report counted only for isolated sub-periods), the max / min test over the union of every observer's values (so the whole-range rule is the ordinary 1.20 test), and the outcome. Route O78 through the same objects. Fixtures: a series that spans a split, an observer with two values, a range-valued report, an inferred model version, a 5-hour pair under a binding weekly cap, a fault-day report, and a straddling pair built through `route_candidates`. This also turns E107's "included and excluded report IDs with reasons" from prose in the research folder into a bundle artifact.
2. **Generate the Plan lifecycle vocabulary (L2).** Render E212's trigger and comparison cells, the comparator's grade list (including the 1.5 level) and E18's trigger list from `plan_routes` constants and the registry's `changeDetection.rule`, as E265 does for figures. This is the third consecutive round with a stale-sentence Low in this area (I62 L1, I63 L1, and L2 here).
3. **State the Plan exposure where the Plan ranking is introduced (L5).** Add to Output 1 a generated line: plan rows flagged possibly-superseded, rows on an unverified valuation basis, rows with an identified M_W (21 of 27, 25 of 27, 0 of 27 and 44 of 51, 48 of 51, 0 of 51 today), and that every non-ceiling, non-fallback row descends from one paywalled article. 4. **Publish a narrow reading for multi-attempt leaves in S1T (I63 recommendation 5, unrecorded in the ledger; new facts).** All 61 `terminalBench40` values in the snapshot are multiples of 1/198 (66 tasks × 3 attempts), and all 62 AA-LCR values are multiples of 1/300 (100 questions × 3 repeats); only 19 and 20 of them are multiples of 1/66 and 1/100. My recomputation: in the max-effort ranking the median API threshold falls from 2.76 to 2.51 and the separable adjacent API ranks rise from 0 to 1 of 8 (MiMo-V2.6-Pro to GPT-6 Luna, gap 2.59); in the AI Coding Daily ranking 4.43 becomes 4.21 and 1 of 15 stays. No score or label changes.
5. **Close the absence-vocabulary gap that L6 shows.** Add "documents no", "describes no" and "lists no" to `ABSENCE` in `draft_figures.py`, so that an unregistered claim about a provider's documentation fails the check and has to cite a record or be registered.
