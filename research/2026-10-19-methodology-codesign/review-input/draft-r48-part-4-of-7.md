
## Attempts reconciliation

The manifest records separately, per leaf: independent evaluation repetitions (e.g. DeepSWE pass@1 averaged over 3 repetitions — affects precision only) and deployment attempt policy (attempts permitted per task, retry/best-of-k/selection/verifier policy) with the cost coverage of those attempts. Only a genuine deployment-policy mismatch between the quality figure and the priced attempts is reconciled (as a bias bound in the identification layer); repetitions are not a bias.

## Uncertainty (three separate layers, one scenario engine)

A joint scenario simulation (N = 10,000) is the single engine. **Primitive sampling (E83)**: scenarios draw the primitive variables of the constrained evidence model (E73) under the selected branch and then derive costs, capacities, multiples, quality and value; derived quantities (e.g. Plan cost = C_W / M_W = F / λ under compatible identified transport) are never drawn independently; every scenario must pass the applicable identities and feasibility checks; infeasible combinations are never silently rejected and redrawn unless that conditional sampling law is itself declared; where public evidence supports no joint sampling mechanism, the branch publishes bounds or is unevaluable (fixtures: C/M = F/λ; gross cash changing with consumption under an evidenced payment rule; shared donor and price primitives propagating to every affected row; individually admissible draws that violate a joint constraint). **Cost is drawn too**: published rounding supports reporting-precision draws, and public paired per-task or per-run cost observations for the exact configuration support resampling at their evidenced level; an analyst-selected token-use range belongs only in a named S2 stress branch, and without supporting observations repeatability is reported as "not quantified", never zero and never an invented S0 distribution (E134; today S0 cost draws are reporting precision only, and the build rejects an S0 primitive whose parameter_derivation cites only an analyst convention). **Joint rounding law (E154)**: rounding is a conventional treatment, not an empirical error distribution. The build compiles each connected constraint component of rounded published records (records linked by an accounting identity, e.g. rounded component costs and a rounded aggregate) and gives it a registered joint-law object (constraint_component_id, published field IDs, free source coordinates, joint_law_id, sampler_version, sampling_status). A singleton component keeps its independent uniform kernel (arcsine alternative); a derived quantity is the identity applied to its drawn primitives — a basket cost is its exact components plus each rounded component's own draw, never one uniform on the summed interval; an affine-linked component uses the registered v1 convention, uniform volume on the feasible polytope in its declared free coordinates, sampled only by an explicitly registered exact algorithm within its resource limit; without a registered law, or beyond that limit, the component keeps deterministic bounds and the affected frequencies are withheld as "joint rounding law not evaluated" — feasibility alone never activates sampling (fixture: two rounded components and a rounded aggregate, every draw inside all three reporting intervals and satisfying the identity; equivalent accounting representations give the same derived-cost distribution). In v1 the admitted basket's costs are captured at source precision (AA's per-evaluation cost per task and the Coding Agent Index mean are unrounded) and the quality leaves are separately published records, so every compiled component is a singleton; aggregates (AA's Index total, the Coding Agent Index published sum) are deterministic validation identities, never sampling constraints, and the build fails if a multi-record component lacks a registered law. AA's published cost already embeds AA's cache-pricing protocol (registry: protocol and date), so cache-hit variation is a **named S2 specification-stress branch** around that protocol, not an S0 redraw (E34). **Layer membership (E122)**: S0 and S1 use the primary price rule only; the first-party-list versus cross-provider-median comparison is a named S2 specification branch with shared price primitives and all demand–cost identities kept within the branch; each stochastic primitive carries uncertainty_layer (S0 reporting precision or supported measurement variation under the primary rule / S1 missing evidence or identified transport / S2 alternative price rule, cache policy, quality mapping or weights / bounds-only), validated at build time so a methodological alternative never enters a measurement-labelled stratum. Cost and AA-run leaf values are coupled only as the Dependence rule allows (paired public observations; otherwise dependence stress branches). **Stream allowlist (E145)**: each stream's registered target profile is an explicit allowlist and takes precedence over the generic sampling instructions in this section — a primitive enters a stream only when the profile names its target. For v1: S0 varies only the published records' reporting precision (cost and leaf rounding); S1 adds the declared conventional identification draws (missing-leaf domains; Plan transport and transfer bounds only where identified — none today); S2 core adds hierarchical weight stress; source-supported uncertainty about expected performance (e.g. a fitted-rating confidence interval) or future runs (public run or task resamples) enters only a separately named stream whose documented estimand supports it, never S0–S2. **Expected-performance stream (E162)**: v1 has one such stream, **S1M** = S1 plus source-documented 95% confidence intervals: today only Terminal-Bench 4.0 documents one (tbench.ai: "The whiskers span the 95% confidence interval"; field accuracy_ci95_half_width, with n_trials), drawn on the z scale as an interval-only input (uniform, arcsine alternative, never assumed normal, clipped to the leaf's domain); every other leaf stays at reporting precision (DeepSWE and the AA Index fields publish no interval, and Bug Hunt's owner publishes run means and counts, not run values); S1M uses the full composite, is labelled "S1 plus Terminal-Bench's published 95% confidence interval (expected-performance uncertainty, one leaf)", is published beside S1 and never authorises a label (E100), in line with O25 (published confidence intervals are reported only through scenario shares). The build rejects a fitted-rating interval or a run range in S0–S2 and an analyst token-use range in S0 or S1; a run-level bootstrap can never be declared reporting precision; each stream's output publishes its permitted and actually varied targets, and its frequency label is derived from that object, not free text. Within its allowlist, each scenario draws leaf values from their kernels, multiples from their ranges, identification bounds for missing leaves, a **hierarchical** weight draw that preserves the nominal means — group weights ~ Dirichlet(100 × (0.60, 0.20, 0.10, 0.10)), within-group weights ~ Dirichlet(50 × nominal within-group proportions), except that a one-leaf group (today Reliability: AA-Omniscience) takes within-group weight exactly one with no draw (E99; fixture: the leaf's weight equals its group share in every scenario); intent is modest perturbation around 60/20/10/10, not alternative buyer preferences (realised per-leaf CV published), and (as named stress-test branches, not random events) source removal, the GDPval mapping alternative, cache-rate variation, the Bug Hunt harness band and the owner-authorised transfer on/off; shared multiples and price lists are drawn once per scenario. Strata are cumulative and computable from the registry: **S0 measurement** = renormalised composite over observed leaves with the reporting-precision leaf and cost draws its profile allows (E145); **S1** = S0 + identification draws (missing-leaf bounds, attempts bias, Plan transport and transfer bounds); **S2 core branch** = S1 + hierarchical weight draws (transfers off, all sources, linear GDPval map); other S2 branches are published separately with explicit reasons when unevaluable.

**Draw-kernel objects (E25)**: every sampled input carries interval_interpretation, kernel_family, kernel_parameters (incl. truncation and mode where relevant), parameter_derivation, dependency_id and alternative_kernel_id. Hierarchy: public paired observations → clustered resampling; rounding interval → uniform; published estimate with documented standard error and an applicable approximation → that declared approximate distribution; interval endpoints only → an explicitly conventional kernel (uniform on the interval) published with an endpoint-heavy alternative — the arcsine law, Beta(½, ½) rescaled to the same interval (E119) — (scenario outputs shown under both); no defensible convention → bounds-only, and no scenario-share claim may depend on that input. A "95% interval" is never assumed normal; Terminal-Bench intervals and AA fitted-rating intervals keep their source interpretations. An unspecified kernel fails the scenario build. **Scenario targets (E58)**: every stochastic input also carries scenario_target (expected benchmark performance / future deployment run / reporting precision / specification convention), sampling_level (task / repository / run / fitted parameter / shared factor), the public evidence supporting that target and level, and the interpretation label permitted beside the resulting scenario share; uncertainty about expected performance is kept separate from predictive run-to-run variation, and only interpretations the public evidence supports are published.

Results are published **per stratum** (S0, S1, S2; transfers on/off; leave-AA-out), never averaged into one figure, as scenario shares (e.g. share of scenarios with rank ≤ 3, on the frontier, qualifying at a bar; pairwise ordering shares), labelled as scenario frequencies, not probabilities. **Stream events (E161)**: each published frequency names its event and the quality equation that event uses — S0 "observed-only score frontier frequency" (Q̄_i, observed leaves renormalised), S1 "full-composite frontier frequency under conventional missing-evidence draws" (nominal-weight full composite), S2 "full-composite frontier frequency under missing-evidence and weight-stress draws"; F_i^(s)(v) = 1[∄ j ≠ i: C_j(v) ≤ C_i(v) ∧ Q_j^(s)(v) ≥ Q_i^(s)(v), one strict]; rank and bar events carry the same field, an S0-to-S1 difference is reported as a change of event target plus added identification draws, never as uncertainty alone, and frequencies are compared directly only when event, target and panel match (fixture: two configurations with different coverage whose observed-only order differs from an admissible full-composite order produce distinct S0 and S1 frontier events). **Rank events (E96)**: every published rank-frequency series has a declared panel I, fixed before the draws and named with its size; a branch exclusion changes the declared panel and never the denominator scenario by scenario; ranks are competition ranks, r_i(s) = 1 + #{j ∈ I∖{i}: V_j(s) > V_i(s)}, as in the displayed table, so ties can put more than k rows at rank ≤ k (disclosed beside each top-k series); pairwise results publish win, tie and loss frequencies f_ij^>, f_ij^=, f_ij^< separately; baseline-versus-branch frequency changes use the E65 common panel on both sides, and frequencies on different workload objects keep the label "cross-workload ordering not identified" (O17). **Monte Carlo precision (E72)**: every published scenario frequency carries its Monte Carlo standard error √(p̂(1 − p̂)/N), separate from the substantive layers; a frequency whose repeated-look-adjusted interval (Bonferroni over the 16 declared looks, E127 — not an anytime-valid confidence sequence) crosses a decision threshold (90%) triggers pre-registered expansion in batches of 10,000 up to 160,000 scenarios, and if it still crosses, the label is "scenario threshold unresolved"; small Monte Carlo differences never create extra ranking distinctions. **Sampling validity (E135)**: every frequency certified by E77 uses IID scenario replicates from one fixed declared law per event and kernel assignment — dependence required by the evidence model stays within each replicate, random numbers may be reused across alternative specifications, but the law, event definition, competitor panel and assignment never adapt within a certified stream; any other sampling design publishes descriptive frequencies only, unless it supplies its own matching error calculation. **Sequential rule (E77)**: looks at N = 10,000, 20,000, …, 160,000 (16 looks); at each look an exact equal-tailed binomial (Clopper–Pearson) interval with **per-look error allocation δ = 0.05/16** (confidence level 1 − δ = 0.996875, δ/2 in each tail; L = Beta⁻¹(δ/2; k, n−k+1), or 0 at k = 0; U = Beta⁻¹(1 − δ/2; k+1, n−k), or 1 at k = n; in SciPy the argument is confidence_level = 1 − δ, never δ — E150) per published event, each certificate recording per_look_error, confidence_level, tail_allocation, k, n, L and U (regression fixture: the closed-form endpoints (δ/2)^(1/n) at k = n and 1 − (δ/2)^(1/n) at k = 0) (the event family and its size are declared in the release manifest); the 90% label is met when the lower bound ≥ 0.90, not met when the upper bound < 0.90, otherwise the run continues to the next look or ends "scenario threshold unresolved" at the cap. The guarantee is per event, not simultaneous across the family; the plug-in standard error stays a separate descriptive quantity. Overlap is not treated as transitive tie groups. Layers:

- **Measurement**: published intervals, rounding ranges, task- or run-clustered resampling where per-task/per-run data exist.
- **Identification**: missing-data bounds; Plan transport (M_W given the measured multiple) and owner-named transfer bounds. **Plan uncertainty split (E12)**: each route stores a measurement object (receipts, meter, repeat-measurement uncertainty of M_observed — drawn only in a separately named measurement stream where public repeat measurements support it, otherwise "not quantified"; no Plan measurement publishes repeats today, E145) and a separate transport object (W hash, quota schema, mechanism, transport bounds; drawn from S1). Where public evidence cannot separate them the route is labelled "measurement and transport not separable" and its S0 result is not described as target-workload support.
- **Specification**: alternative leaf weights, leave-one-benchmark-out, leave-one-source-out (**leave-AA-out is a headline robustness column**), cost-weight slider, owner-authorised transfer on/off, cache-rate stress, Bug Hunt harness stress. **Deletion branches (E146)**: each registered branch names its removed leaf set R. *Displayed-score deletion sensitivity* removes R globally and renormalises the remaining observed weights, Q̄_i^(−R) = Σ_{b∈O_i∖R} w_b z_ib ÷ Σ_{b∈O_i∖R} w_b (a zero denominator leaves the row unevaluable in the branch, listed), keeping the primary workload, selected route, anchors and cost score; a branch whose retained nominal weight Σ_{b∉R} w_b is under 40% is "not identifiable under the coverage rule" (leave-AA-out today: 20%); rank changes and τ_b use the common panel (E65). *Evidence unavailability* — the full-composite target with the removed observations replaced by their admissible domains, reported as bounds or convention-dependent scenarios — is a distinct, separately named branch and never shares a deletion branch's name. Registered branches: one per leaf (leave-one-benchmark-out) and one per multi-leaf source (leave-AA-out); a single-leaf source (Bug Hunt Bench, Terminal-Bench) coincides with its leaf's branch, which carries both labels, and the Bug Hunt branch is the standing Bug Hunt removal. **Standing cost-component removal (E64, defined by E149)**: a cost-deletion object D_cost = (R_C, W∖R_C, anchor policy, route policy, multiple policy, panel rule), separate from quality deletion; R_C names execution components, not quality leaves. The standing column removes AA's Index-run Terminal-Bench 4.0 (the Coding Agent Index also executes Terminal-Bench v4) and publishes two named calculations on the main-workload panel, each compared with the primary ranks on the common panel (E65) with quality held at Q̄_i: (a) *cost-component removal, original anchors* — C_i^(−TB) = C_i,W − C_i,TB scored on the original anchor object A_W, V = 0.25·S_C(C_i^(−TB); A_W) + 0.75·Q̄_i (a sensitivity of the published scoring scale); (b) *alternative workload, recalibrated anchors* — W∖TB scored on anchors rebuilt by the freeze rule from its evidenced reference panel, with the new exchange rate published beside the rank changes so cost-composition and recalibration effects can be told apart. On the Plan basis each row keeps its selected route and displayed multiple, labelled "fixed-multiple arithmetic stress (not identified Plan economics for the altered workload)"; **basis typing (E152)**: with A_i the API basket cost, m_i the selected displayed multiple and P_i = A_i / m_i, the removal subtracts the API component cost before dividing — A_i^(−TB) = A_i − A_i,TB is scored only against API anchors and P_i^(−TB) = (A_i − A_i,TB) / m_i only against Plan anchors, in both calculations (fixture: A = 100, A_TB = 20, m = 4 gives P = 25 and P^(−TB) = 20 — never 25 − 20 = 5, never 80 against Plan anchors); API-fallback rows take P_i^(−TB) = A_i^(−TB), as on the primary workload; an M_W identified for W is reused for W∖TB only when its identification mechanism also covers W∖TB.
- **Workload cross-check (mandatory, diagnostic)**: per benchmark b (DeepSWE; Terminal-Bench 4.0), a common exact-configuration panel I_b; d_ib = mean cost per attempted task ÷ resolved fraction (∞ when zero, with uncertainty shown). **Same-execution contract (E68)**: numerator and denominator share one observation key (model, effort, fallback, harness and version, task support, deployment policy); for Terminal-Bench the resolved fraction is that of the AA-priced execution (AA's Index Terminal-Bench 4.0 score), never the tbench.ai quality leaf; for DeepSWE both come from AA's DeepSWE execution; a row without a matching pair is unpriced for this diagnostic. Paired task-level costs and outcomes, where public, are resampled jointly. Kendall τ-b between basket-cost rank and d_ib rank within I_b, separately per benchmark (never pooled); task-cluster resampling where task-level results exist, otherwise a model-row bootstrap labelled as matched-set sensitivity; below n = 8 rows in I_b the statistic is suppressed. **Pre-registered threshold (E41)**: a headline warning when the point estimate τ_b < 0.5 (a policy choice, not a statistical fact); "uncertain agreement" when the resampling interval spans 0.5; the exact matched configuration panel is published beside the statistic.

Shared dependencies move together (one multiple, price update or benchmark version affects all its rows jointly).

## Normative definitions (executable specification)

- **Coverage and scores.** p_i = Σ_{b∈O_i} w_b. Displayed observed-only quality Q̄_i = Σ_{b∈O_i} w_b z_ib / p_i. Full-composite score Q_i(θ) = Σ_{b∈O_i} w_b z_ib(θ) + Σ_{b∉O_i} w_b u_ib, u_ib ∈ [0,100]. **Formal bounds** (E35): Q_i^L = min_{θ∈Θ} Q_i(θ) and Q_i^U = max_{θ∈Θ} Q_i(θ) over the joint admissible set Θ below (measurement intervals of observed leaves and u_ib ∈ [0,100] for missing leaves); "missing at 0/100 at the point estimate" is not the bound. S0 uses Q̄_i; S1/S2 use the full-composite equation. Any sampling law for wholly missing leaves is a declared scenario convention (with one published alternative), never evidence; formal bounds are distribution-free.
