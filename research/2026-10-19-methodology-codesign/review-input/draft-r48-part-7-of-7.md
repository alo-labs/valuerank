
## Governance

Evidence classes (measured / claim / estimate / assumption); provider claims never overwrite independent measurements. Plan evidence carries a 30-day soft expiry with change detection (a plan is flagged "possibly superseded" when scoped change detection — pricing tables, rate-limit documentation sections and model-availability matrices, not full-page diffs — shows a change since measurement, or when ≥ 2 independent end-user reports (O11 independence) describe an undocumented limit change; E18) and a 90-day hard expiry; after a further 30-day grace an expired route is **demoted to diagnostic-only** and the model falls back to API cost (flagged) in the official Plan table (O13), labelled "cross-estimand ordering not identified" and excluded from Plan interval outputs (E36). **Release-time route order (E142)**: every measurement object is classified for eligibility and expiry first; diagnostic-only candidates (including demoted ones) leave the official selection; the E88 dominance filter and the E85/E111/E116 comparator then run over the surviving official-display-eligible route–measurement pairs, and the API-cost fallback of O13 applies only when none survives; the selection is frozen within the release's scenarios, and an eligibility-transition reason ("the evidence expired") is published separately from the comparator's selection reason (fixtures: the selected measurement expires while another measurement of the same route survives; every measurement of the selected route expires while another route survives; only an owner-named transfer whose donor measurement is current survives (E144); nothing survives → API fallback; a past release rebuilt with its original cutoff reproduces its selection). Each row stores its AA price-list date; score changes are decomposed into price change vs token-use change vs **benchmark-record update** (refit, re-anchoring or regrading of a published value with no new task execution; E90) vs method vs cohort, by a declared sequential bridge where effects interact; a component public evidence cannot separate is labelled "benchmark-record update — decomposition unavailable". The scenario engine uses a published RNG seed and draw order per release, and per-stratum outputs are released as data files. Plan rows publish fee F and full-utilisation capacity M × F in API-priced USD so light users can judge fit. Freshness: AA cost snapshot and price list max age 45 days, with change-triggered refresh; monthly cadence. **Tariff applicability (E141)**: each price record carries observed_at, effective_from, effective_until (only where publicly established), tariff_status (standard / promotional / grandfathered), applicability_conditions, scheduled_refresh_at (the next known effective boundary, refreshed on schedule independently of page diffs) and a source evidence ID; a release uses the prices applicable at its declared valuation timestamp; a promotion with an unknown end keeps the applicable price in the primary ranking, flagged "promotional tariff", with a named S2 standard-tariff branch only where the standard tariff is publicly documented and the consumption ledger supports repricing; an AA note that its cost omits a tariff component (on 2026-10-17: Claude Haiku 5.5's higher long-context pricing is not reflected in AA cost figures) is shown on the row as "AA cost caveat". Unknown boundaries stay unknown (no assumed dates). Each row publishes, per stratum and branch, its **row-level scenario dispersion** (E87; the former per-row "own normalised weighted spread" is dropped as undefined without a panel, E136 — the common-panel weighted spread and this decomposition answer the two questions): Var_s(V_i) = β²Var_s(S_C,i) + (1−β)²Var_s(Q_i) + 2β(1−β)Cov_s(S_C,i, Q_i), with the covariance term published separately and labelled scenario dispersion under the declared kernels (bounds-only rows: "no scenario SD defined"); cohort SD notation is reserved for the within-cohort influence diagnostic. Release gates (on failure the release is **held** — fix the data or re-anchor as a versioned migration with a dual-run comparison; O12): the clip gate defined under Cost, an unversioned AA chart/field change, or any score swing > 5 points without an attributed cause. The registry records, per row: chart field name; total cost and cost per task side by side; repeat inclusion; AA cache protocol and date; price rule (first-party list vs cross-provider median for open weights); fallback-token treatment; Elo anchor identity (e.g. GDPval-AA scale pinned to a named reference model), rating snapshot ID and integration-freeze status and judge-panel/grader versions for rubric-graded leaves. A change of rule in any of these is a methodology migration; a new value under an unchanged rule is a data refresh (see Versioning). Leave-AA-out is reported as "not identifiable under the coverage rule" when the remaining identified quality weight is under 40% (the case today, with ≈20% independent weight), and is excluded from any denominator. **Independent-source checks (E62, split by E66)**: on the same matched panel of rows with both independently executed leaves (Bug Hunt, Terminal-Bench), two named statistics with model-row bootstrap intervals (labelled matched-panel sensitivity): (a) **quality agreement** — Kendall τ_b between the observed-quality ranking and the independent-only quality ranking Q_ind = (z_BugHunt + z_TB)/2; (b) **quality-substitution value agreement** — τ_b between the displayed value ranking and value recomputed with Q_ind in place of quality, cost, anchors, basis and route held fixed (this substitutes quality evidence only; it does not validate costs or Plan multiples). A panel with insufficient rank variation returns "undefined". (c) **Disjoint-evidence agreement (E71)** — τ_b between AA-executed-only quality and independently-executed-only quality on the same panel, with retained leaves and weights published, labelled a restricted evidence comparison (not an eligible ranking); (a) and (b) share inputs with the composite and are described as such. Descriptive only, no scenario share. **Active-rules manifest (E63)**: each release lists every gate, flag and rule with its status (fired / passed / vacuous / unresolved) so readers can see which rules bound.

## Known limitations

Full-utilisation Plan cost overstates value for light users (workday diagnostic shown); AA cost uses AA's token mix and cache protocol; Terminal-Bench work is priced in two executions; Bug Hunt covers two repositories; DeepSWE/Bug Hunt/TB measure model+harness stacks; suite is primarily English text; FrontierCode and ITBench-AA remain pending until complete exact-variant cost evidence covers two-thirds of ranked rows jointly with the admitted components (E95, E101).
