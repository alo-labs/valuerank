# ValueRank methodology — draft r49

*Where prose and the Normative definitions differ, the Normative definitions govern.*

*Revision history: r16–r24 fixed the published-record interval target, plan capacity and identification rules and the Monte Carlo precision rule; r25–r46 completed the executable contracts (primitive sampling, route comparator and lifecycle, demand registry, kernel checks, admission enumeration, tariffs, target profiles, deletion branches, bar policy); r47 adds a tariff-aware valuation contract, an explicit cost boundary and an immutable evidence bundle; r48 registers the anchor-panel policy, defines each stream's frontier event and adds the S1M stream for Terminal-Bench's published 95% confidence interval; r49 labels S1M a conventional range sensitivity under an interpretation contract, adds a measured-evidence calibration diagnostic to the measured-only Plan view and states the cohort's retained configurations. Every change is recorded with its rationale in the ledger.*

## Objective and claim scope

AA's Pareto frontier of Intelligence Index vs. total USD cost to run its Intelligence Index does not answer the question ValueRank exists for: **which frontier AI model is actually lowest cost for the value it delivers in practice**, once (a) subscription-plan economics are considered and (b) benchmarks geared to real software-engineering work are weighed alongside general capability. ValueRank serves two buyers, ranked separately: **API buyers** (pay per token, incl. third-party agents) and **Plan buyers** (provider subscription apps/CLIs: Claude Code, Codex, ChatGPT, SuperGrok…).

Claim scope: "value among the ranked configurations (AA-selected frontier and near-frontier configurations, plus configurations retained for exact DeepSWE and Bug Hunt evidence; see Cohort), under the published benchmark mix and evidence". Every ranked row is a **configuration** (model version, effort, fallback, route), with a compact configuration ID and an expandable per-leaf execution manifest; tables and claims say "configuration", not "model" (E78). Not a market-wide optimum across all configurations and workloads.

## Outputs

1. **Headline ranking** per basis by value score = 0.25 × cost score + 0.75 × quality score (owner decisions O2, cost weight 25%). There is **no "recommended" label** (O22). Uncertainty is shown beside each rank as per-stratum scenario shares (Uncertainty). Two named quantities are printed per basis: (a) the **anchor exchange rate** — in the unclipped region a cost doubling changes value by −100·β·ln2 / ln(c_H/c_L) points and is offset by +100·β·ln2 / ((1−β)·ln(c_H/c_L)) quality points, β = 0.25, from the active anchor version; (b) the **within-cohort influence** 0.25·SD(S_C) vs 0.75·SD(S_Q), computed on the declared **common-workload panel** (E91): the rows scored on the main workload W with its anchor object, the same rows for both SDs, with panel size and excluded rows shown beside it. Subset-workload strata get their own statistic (undefined below two rows); a statistic over the whole displayed table mixes anchor objects and may be shown only as "displayed-table dispersion"; a zero denominator returns "undefined — no composite dispersion". A release is flagged (not held) when cost's share of the common-workload influence, 0.25·SD(S_C) / (0.25·SD(S_C) + 0.75·SD(S_Q)), is under 10% ("cost not discriminating") or above 90% ("quality not discriminating", E126); the exchange rate of every anchor version is published as a series, and a trimmed-anchor diagnostic (10th and 90th percentile reference costs with the same ln 2 padding) reports rank shifts only, never replacing the primary anchors; the flag is informational and β never changes (owner decision O2). Cost-weight slider results appear in the main table. No quality floor (O8); provisional rows are flagged. **Basket version in the headline (E59)**: the headline names the active basket version and its components (today "SDLC basket v1: 7 AA Index SDLC evaluations + Coding Agent Index; pending FrontierCode, ITBench-AA"), and the target basket appears in the readiness table. **Cost-weight disclosure (E60)**: the anchor exchange rate (quality points that offset a cost doubling) and the within-cohort cost influence are printed beside the first table, with a sensitivity curve of the exchange rate over c_H/c_L.
2. **Cost–quality frontier** per basis, bound-aware: "definite" vs "possible" frontier members (Normative definitions).
3. **Cheapest above a quality bar**: each release pins named reference configurations (identity frozen at release, e.g. the model that was the median definite-frontier model at release time). Qualification and cheapest labels follow only the joint definitions in Normative definitions ("Cheapest above a bar").
4. **Diagnostics**: USD per AA Index point, AA Intelligence Index, total Index cost, AA tokens used to run the suite, output speed, raw values, evidence grades, measured-only Plan view with its measured-evidence calibration, matched-cost and workload cross-checks, SWE cost companion, target-basket readiness.

## Source contract (versioned registry)

**Evidence bundle (E159)**: each release is (method version, registry, evidence bundle, extractor versions, outputs). The bundle lists every captured artifact the build reads — source payloads or permitted captures, committed with the release — with its content hash, capture time and extractor, plus a bundle hash; every scored observation records its artifact, field locator and published value. Rebuilding from the bundle at the pinned publication clock must reproduce the admitted components, route selection, anchors, scores and deterministic interval statuses without consulting live pages (and the scenario outputs under the recorded RNG, seed and draw order); where redistribution is restricted, the permitted capture is retained and its hash and locator published. Machine-readable registry per release: AA chart identity, filters and snapshot timestamp (current: "Intelligence Index vs. Cost to Run Artificial Analysis Intelligence Index", x-axis "Cost to Run Intelligence Index (USD)", unit "USD to run all Intelligence Index evaluations", captured 2026-10-17); cost field, unit and accounting (as AA defines it, including AA's cache-pricing protocol and its date); per model: version, effort, fallback, serving route and per-benchmark stack; per benchmark: version, raw metric, **pinned source field**, population, attempts, aggregation, source revision/commit, observation and retrieval dates; explicit missingness reason (not evaluated / incompatible variant / no public evidence / withdrawn). Pinned fields today (E31): AutomationBench-AA = AA field `automationBenchPartialScore` (the value AA's Index uses); Omniscience = AA's Omniscience Index field `omniscience` (O28), with `omniscienceBreakdown.accuracy` and `omniscienceBreakdown.hallucinationRate` kept as diagnostics and reconciliation checks; Coding Agent Index cost = AA's per-task cost-to-run `mean.costUsd` × 303 required tasks (O27), with "Total Cost Across the Coding Agent Index" (`sums.costUsd`) kept as a reconciliation diagnostic (E104); Bug Hunt = owner-published run results and means. A change of AA chart or field is a versioned methodology migration, never a silent refresh.

## Cost (25% of the value score)

- **API cost input = SDLC cost basket (owner decision O15, as amended by O23).** C_i,W = Σ over admitted basket components of AA's published cost for the exact configuration. Target basket = the AA evaluations whose tasks are typically part of an end-to-end SDLC and DevOps/IT workflow: **Coding Agent Index** (DeepSWE v1.1, 113 tasks; SWE-Atlas QnA, 124; Terminal-Bench v4, 66), **FrontierCode**, **ITBench-AA**, **AA-Briefcase**, **GDPval-AA**, **GDP.pdf**, **AutomationBench-AA**, **Terminal-Bench 4.0** (AA Index run), **SciCode**, **AA-LCR**. Excluded: HLE, AA-Omniscience, CritPt (knowledge/science recall) and MMMU-Pro (academic multimodal QA; O23). **Cost boundary (E158)**: the primary dollar figure is the **contestant-model API token cost for the SDLC basket** — AA prices "the token counts reported by each model's API provider" — and is labelled as such beside every headline cost: it is not total agent or workflow operating cost. Each component carries a boundary record over the charge classes contestant-model tokens, other model calls (e.g. judges), external tools, execution environment, preparation (e.g. PDF parsing, OCR) and grading, each included / excluded / not applicable / unknown from the source's documentation (verified 2026-10-19 on AA's methodology page: GDP.pdf's "published costs cover contestant model calls only and exclude judge calls, PDF preparation, and OCR"; no other component states a boundary, so its other classes stay unknown); a supplementary operating-cost figure is published only where its services, public prices and measured quantities are evidenced for the exact execution, otherwise the matrix is published without a synthetic total. The basket itself is unchanged (O15).
- **Accounting identities.** AA's total Index cost decomposes exactly into its **ten** evaluations (Σ cost per task × task counts: Briefcase 91, GDPval 220, GDP.pdf 100, AutomationBench 657, Terminal-Bench 66, SciCode 288, LCR 100, HLE 2,158, CritPt 70, Omniscience 6,000; verified to < 0.002% for every row of the 2026-10-17 snapshot). C_W takes the seven SDLC evaluations; C_Index = C_7 + C_HLE + C_Omniscience + C_CritPt is reconciled to AA's chart each release, and that residual never enters C_W. **Coding Agent Index cost (owner decision O27)** = AA's documented cost-to-run metric — the average pay-per-token API cost per task, which AA computes as a pooled per-task-attempt average that excludes missing telemetry (AA coding-agents methodology, verified 2026-10-19) — × the 303 required tasks; this is the published record of one deployment-equivalent pass (E9). AA's `sums.costUsd` and the ratio sums ÷ mean are kept as a reconciliation diagnostic; unseen telemetry gaps and unequal attempt coverage are cost precision, reported in the scenario layer (O25). Chart-captured totals (FrontierCode, ITBench-AA) are rounded to USD 1 and treated as rounding intervals; AA's "*" mark ("the model or provider declined some tasks on safety grounds") also flags "partial component".
- **Capture status (2026-10-19).** Exact model-and-effort cost: Coding Agent Index 16 of 19 ranked rows (none for GPT-6 Astra (xhigh) — only max is run — or the two MiMo rows), all 16 complete under O27 (no AA missing- or declined-task marker); for 3 the published sum spans fewer task-equivalents than 303 (Gemini 4 Argon 302; GPT-6.1 Sol 301.6; Qwen3.8 Max 301.3), a diagnostic only; FrontierCode 11 of 19; ITBench-AA 7 of 19. Under the admission rule the seven AA Index SDLC evaluations (19 of 19 rows) and the Coding Agent Index (16 of 19) are admitted: **basket v1 = 8 of the 10 target components**; FrontierCode and ITBench-AA are "pending capture".
- **Cost completeness (E37, as set by O27).** Per row and component the registry stores component identity, the AA field and its aggregation (unit, operator, repetition treatment), required / executed task counts and attempt counts where published, completeness status and reason. CompleteCostEvidence(i, e) ⇔ AA's documented cost metric for e is published for the exact configuration **and AA marks no tasks of that run as missing or declined** (e.g. the "*" declined-tasks marker on chart totals, or an explicit missing-task note). Statuses: *complete (published record)* / *confirmed incomplete* (an AA marker, with its reason). An attempted task with missing telemetry is never counted as zero; AA's documented averaging handles it, and the resulting imprecision belongs to the scenario layer (O25). Attempt coverage (e.g. 905 of 909 attempts) is published beside the row as a precision diagnostic (E53). FullCost(i, W) ⇔ CompleteCostEvidence(i, e) for every admitted e. The **displayed** score uses the cost records, with a "partial component" flag where AA marks a run incomplete; the **interval outputs** require FullCost(i, W) (otherwise the row is unevaluable there).
- **Terminal-Bench (O24).** One task family appears in three executions: the AA Index run (priced), the Coding Agent Index run under vendor agents (priced, inside AA's single total and not separable), and the tbench.ai leaderboard (the quality leaf; not priced). Both priced executions stay in the basket as the owner listed them; the overlap is disclosed.
- **Admission and persistence (E26).** A component is admitted to workload version W when exact-configuration cost exists for every configuration in W's frozen, named **reference panel**, published with W and containing at least two-thirds of the ranked rows at admission; until admitted it is listed as "pending capture". **Panel construction (E95, selection by E140)**: one panel per workload version, built deterministically before scores or ranks are inspected. With P(S) = the ranked rows with **complete cost evidence** (CompleteCostEvidence, E37 as set by O27: exact cost and no AA missing- or declined-task marker) on every component of S (E101), the admitted set is chosen by enumerating every subset S of the target components (2¹⁰ = 1,024 today; **admission units, E148**: the units are exactly the ten named targets of O15, each counted once whatever its accounting representation — the Coding Agent Index is one unit, not its three sub-benchmarks; a unit's complete evidence enters only at unit level, as an accepted aggregate or a complete compatible decomposition first composed by the accounting tree, so K_iu is identical under either representation; raw accounting children never enter admission and the build rejects any component outside the unit registry; adding a unit is a basket-version migration; fixture: N = 6, unit A complete on rows 1–4, units B and C on rows 3–6 — B + C is admitted, and A presented as its sub-benchmarks is rejected rather than counted as three units) with |P(S)| ≥ ⌈2N/3⌉ and maximising, lexicographically, the number of admitted components (O15 lists them without priorities), then |P(S)|, then the earliest components in the published target order; P(S) of the selected set is the reference panel, and the selected subset, its objective tuple and the feasible alternatives are published (fixture: components A on rows 1–5 and B and C each on rows 1, 2, 3, 6 with N = 6 — a greedy coverage order admits only A, enumeration admits B and C). This replaces E95's greedy coverage order; the 2026-10-19 outcome is unchanged (eight components, 16-row panel). Two public matrices are published per release, A_ie = exact compatible cost available and K_ie = CompleteCostEvidence(i, e), with both joint panels P_A(W) and P_K(W); only P_K is called complete. The admission object (workload version, selection rule, timestamp, configuration IDs, ranked cohort size, required panel size, admitted components, complete-on-all-components IDs) is published, with marginal coverage per component and joint full-basket coverage side by side (fixtures: two components that each pass alone but not together — the higher-coverage one is admitted, the other stays pending; two-thirds of rows with exact costs, some carrying AA's declined-task marker — the component is admitted only if the unmarked rows reach two-thirds). Once admitted, membership is frozen for W. Later missingness (a new cohort row, withdrawn or failed evidence) invokes O17/E10 subset scoring for that row without changing W or its hash; adding cohort rows never invalidates an admission. The target-basket readiness table (E22) is published each release. Total Index cost and USD per Index point remain diagnostics.
- **Workload object W** (versioned, hashed): the set of unique execution components (e, n_e) with frozen task multiplicities, configuration and deployment policy; C_i,W = Σ_e n_e × c_ie, where c_ie is cost per workload task for **one deployment-equivalent pass** (extra evaluation repetitions excluded, matching AA's totals; E9). Aggregates (e.g. the Coding Agent Index total) and their components are mutually exclusive in the accounting tree — an aggregate is either a reconciliation check or a substitute, never additive; a machine-checkable accounting tree is published. Adding or removing a component is a workload migration with an overlap bridge (old vs new basket costs, scores and ranks for configurations evidenced under both) and Plan-transport revalidation.
- **Missing component for a row (O17)**: the row is scored on its available subset, flagged "subset cost — cross-workload ordering not identified", with its cost compared on that same subset, never by summing fewer items against full-basket costs. **Subset calibration contract (E10)**: each subset used is a versioned workload W_S (hashed components and multiplicities) with its own frozen anchor object from the reference configurations evidenced on W_S, built by the same rule; paired full/subset costs, scores, exchange rates and rank differences are published wherever both are evidenced; missing component costs are never filled to build the bridge. The row keeps its owner-required score and table position with that label, and is "unevaluable" for the frontier and bar outputs on W. **Anchor applicability (E86)**: every row carries its workload ID, anchor-object ID and applicable cost-doubling exchange rate; the main-workload rate is shown above the table, subset rows are marked as using a different rate, and the cost-weight slider keeps each row's own anchor object. Release assertion: the scored field is the basket sum, not cost per task, not AA's 7:2:1 blended price, not total Index cost.
