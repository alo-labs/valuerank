
## Governance

Evidence classes (measured / claim / estimate / assumption); provider claims never overwrite independent measurements. Plan evidence carries a 30-day soft expiry with change detection (a plan is flagged "possibly superseded" when scoped change detection — pricing tables, rate-limit documentation sections and model-availability matrices, not full-page diffs — shows a change since measurement, or when ≥ 2 independent end-user reports (O11 independence) describe an undocumented limit change; E18) and a 90-day hard expiry; after a further 30-day grace an expired route is **demoted to diagnostic-only** and the model falls back to API cost (flagged) in the official Plan table (O13), labelled "cross-estimand ordering not identified" and excluded from Plan interval outputs (E36). **Release-time route order (E142)**: every measurement object is classified for eligibility and expiry first; diagnostic-only candidates (including demoted ones) leave the official selection; the E88 dominance filter and the E85/E111/E116 comparator then run over the surviving official-display-eligible route–measurement pairs, and the API-cost fallback of O13 applies only when none survives; the selection is frozen within the release's scenarios, and an eligibility-transition reason ("the evidence expired") is published separately from the comparator's selection reason (fixtures: the selected measurement expires while another measurement of the same route survives; every measurement of the selected route expires while another route survives; only an owner-named transfer whose donor measurement is current survives (E144); nothing survives → API fallback; a past release rebuilt with its original cutoff reproduces its selection). Each row stores its AA price-list date; score changes are decomposed into price change vs token-use change vs **AA cache-rate update** (AA's Index category costs show a changed cache-read share with unchanged token totals and prices; E176) vs **benchmark-record update** (refit, re-anchoring or regrading of a published value with no new task execution; E90) vs method vs cohort, by a declared sequential bridge where effects interact; a component public evidence cannot separate is labelled "benchmark-record update — decomposition unavailable". **Swing attribution (E177)**: the bridge replays the build from the two releases' evidence bundles (E159), one input class at a time in the declared order, and publishes per row each step's change, the order-dependence term (forward minus reverse ordering) and the replay residual (the replayed final score minus the published score); a score change is attributed only when the replay residual is within 10⁻⁶ points and every step carrying more than 5 points names the changed bundle fields (artifact and field locator) or the versioned method or cohort change behind it. A benchmark-record update whose changed published field is named is attributed even when its decomposition is unavailable (E90). The gate compares rows ranked in both releases; a row ranked only in the new release is published as "cohort admission (no prior score)" and one ranked only in the old release as "cohort exit", and neither is held by this gate. The scenario engine uses a published RNG seed and draw order per release, and per-stratum outputs are released as data files. Plan rows state that the multiple values the measured workload's API-equivalent consumption only (other plan features are not valued) and publish the fee period, the cash paid (subscription fee plus declared additional cash, F_gross) and the selected multiple's API-priced amount M × F_gross so light users can judge fit, typed by the selected measurement object (E166): amount_kind measured-workload capacity / observed eligible consumption, capacity not established / assumed API-equivalent consumption (owner-named transfer, donor named) / identified target-workload capacity (bound to W), with the capacity status (E139), valuation status (E138) and an interpretation label generated from those fields; API-fallback rows publish no Plan amount, and the amount is never called capacity unless the measurement establishes it. **Amount lineage (E168)**: every amount records amount_target (measured-workload consumption / measured-workload capacity / assumed consumption / target-workload capacity), workload_id, measurement_object_id, capacity_solution_id, cash_object_id, purchase_policy_id and derivation (direct observation / solver projection / authorised assumption / valid multiplication). M × F reproduces an amount only within one object: the measurement record U_obs = M_obs × F_obs, or fixed positive cash U_W* = M_W × F_0. A target-workload capacity is the capacity solver's U_W* (bounds are the projections of the joint solution set, never products of separately projected multiple and cash endpoints; the displayed lower-bound multiple is a scoring convention), and is never the displayed multiple times cash from another object; when the target solution's cash lineage is not established, the measured amount stays publishable and no target capacity is manufactured (fixtures: fixed cash reproduces target capacity; consumption-dependent cash rejects cross-object multiplication; set identification by projection; missing target cash lineage). Freshness: AA cost snapshot and price list max age 45 days, with change-triggered refresh; monthly cadence. **Tariff applicability (E141)**: each price record carries observed_at, effective_from, effective_until (only where publicly established), tariff_status (standard / promotional / grandfathered), applicability_conditions, scheduled_refresh_at (the next known effective boundary, refreshed on schedule independently of page diffs) and a source evidence ID; a release uses the prices applicable at its declared valuation timestamp (a mismatch with the prices AA applied is resolved by E170); a promotion with an unknown end keeps the applicable price in the primary ranking, flagged "promotional tariff", with a named S2 standard-tariff branch only where the standard tariff is publicly documented and the consumption ledger supports repricing; an AA note that its cost omits a tariff component (on 2026-10-17: Claude Haiku 5.5's higher long-context pricing is not reflected in AA cost figures) is shown on the row as "AA cost caveat". Unknown boundaries stay unknown (no assumed dates). **Valuation-basis gate (E170; failure action = owner decision O29)**: the release declares one valuation timestamp V, its release cutoff (the cutoff that also governs evidence clocks, E151). Every scored cost observation names the basis it was actually valued on, not the date ValueRank retrieved it: for an AA cost, the per-category prices AA applied to the exact configuration (its displayed prices at capture, reconciled p·d = C where AA publishes category costs, E157) and the price record they match; for a Plan measurement, the price records of the model line whose consumption it values (E138). A compatibility join of each observation's basis with the price records in force at V (E141) returns exactly one outcome: (1) compatible as captured; (2) compatible after evidenced revaluation, which is exact only when every priced category and band with positive demand in the component moves by one common factor k (then C' = k·C for any demand mix; a category has zero demand only where a published category total shows it) or when E157's valuation sufficiency supplies the component's demand by category and band; (3) AA's applied price not in force at V (O29): the row keeps AA's cost at the price AA applied, flagged "AA cost at superseded price" (or "AA cost at standard price during a promotion", E141) with that price's effective dates, and stays in the value ranking; it earns no interval label of its own and competes in other rows' interval outputs over the hull of its published record and its current-tariff bound below, so it can block but never enable another row's label; its scenario outputs use its published record and carry the flag; it is never a reference in anchor derivation (E160) or in the measured-evidence calibration (E164); and its Plan cost divides only by a multiple valued on the same basis (E138's statuses are evaluated against the row's basis: an exact measurement valued at the new tariff is revalued to the row's basis under outcome 2 or is diagnostic-only; an owner-named transfer needs a donor measurement valued on price records in force during the applied price's effective dates; when no route survives, the row falls back to API cost, flagged, O13). Such a row also publishes the structural current-tariff bounds, with r = price in force at V ÷ applied price over the priced categories and bands with positive demand (for P', positive demand or measured consumption): C' ∈ [C·min r, C·max r], because C'/C is a demand-weighted mean of the r; and, on the Plan basis, P' ∈ [P·min r ÷ max r, P·max r ÷ min r], because M'/M is a consumption-weighted mean of the same ratios (diagnostic only). The release never computes one C/M across two bases, never holds for this reason and never moves V to an earlier date (O29). An AA basis that cannot be identified is flagged "valuation basis unverified" and is never interval-eligible (as E138); a band that AA's figure omits under an unchanged tariff stays under E157 (AA cost caveat), not this gate. The join is keyed by the observation's basis ID and the IDs of the price records in force at V, so a new or changed price record re-runs it even when no source payload changes (fixtures: a tariff change between AA's valuation and V with the AA payload unchanged, where a uniform k revalues (outcome 2) and a single-category change yields outcome 3; a Plan measurement revalued to the new tariff while the basket cannot be, which never yields a cross-basis C/M; a changed price record with every payload unchanged, which re-runs the join and changes the outcome; both bounds bracket the exactly repriced values for random demand and consumption vectors). Each row publishes, per stratum and branch, its **row-level scenario dispersion** (E87; the former per-row "own normalised weighted spread" is dropped as undefined without a panel, E136 — the common-panel weighted spread and this decomposition answer the two questions): Var_s(V_i) = β²Var_s(S_C,i) + (1−β)²Var_s(Q_i) + 2β(1−β)Cov_s(S_C,i, Q_i), with the covariance term published separately and labelled scenario dispersion under the declared kernels (bounds-only rows: "no scenario SD defined"); cohort SD notation is reserved for the within-cohort influence diagnostic. Release gates (on failure the release is **held** — fix the data or re-anchor as a versioned migration with a dual-run comparison; O12): the clip gate defined under Cost, an unversioned AA chart/field change, or any score swing > 5 points that E177 does not attribute. The registry records, per row: chart field name; total cost and cost per task side by side; repeat inclusion; AA cache protocol and date, including its rate provenance (AA values cached input at live measurements of the model's typical cache-hit rate, not the run's one-off rate; the measurement window is not published; E176); price rule (first-party list vs cross-provider median for open weights); token metering basis (provider-reported counts, AA's default, or AA's canonical-tokenizer fallback; "not published per configuration" where AA does not say which, as on 2026-10-20; E176); Elo anchor identity (e.g. GDPval-AA scale pinned to a named reference model), rating snapshot ID and integration-freeze status and judge-panel/grader versions for rubric-graded leaves. A change of rule in any of these is a methodology migration; a new value under an unchanged rule is a data refresh (see Versioning). Each release prints its metering mix (rows on provider-reported counts, on the fallback, and not published); where AA publishes the basis per configuration, two rows whose basket costs lie within a factor of 1.10 of each other on different bases carry a comparability caveat (E176). Leave-AA-out is reported as "not identifiable under the coverage rule" when the remaining identified quality weight is under 40% (the case today, with ≈20% independent weight), and is excluded from any denominator. **Independent-source checks (E62, split by E66)**: on the same matched panel of rows with both independently executed leaves (Bug Hunt, Terminal-Bench), two named statistics with model-row bootstrap intervals (labelled matched-panel sensitivity): (a) **quality agreement** — Kendall τ_b between the observed-quality ranking and the independent-only quality ranking Q_ind = (z_BugHunt + z_TB)/2; (b) **quality-substitution value agreement** — τ_b between the displayed value ranking and value recomputed with Q_ind in place of quality, cost, anchors, basis and route held fixed (this substitutes quality evidence only; it does not validate costs or Plan multiples). A panel with insufficient rank variation returns "undefined". (c) **Disjoint-evidence agreement (E71)** — τ_b between AA-executed-only quality and independently-executed-only quality on the same panel, with retained leaves and weights published, labelled a restricted evidence comparison (not an eligible ranking); (a) and (b) share inputs with the composite and are described as such. Descriptive only, no scenario share. **Active-rules manifest (E63)**: each release lists every gate, flag and rule with its status (fired / passed / vacuous / unresolved) so readers can see which rules bound.

## Known limitations

Full-utilisation Plan cost overstates value for light users (workday diagnostic shown); the Value Multiple values only the API-equivalent consumption of the measured workload, so plan features outside it (chat, image generation, other surfaces, pools shared with them) are not valued; AA cost uses AA's token mix and cache protocol; Terminal-Bench work is priced in two executions; Bug Hunt covers two repositories; DeepSWE/Bug Hunt/TB measure model+harness stacks; suite is primarily English text; FrontierCode and ITBench-AA remain pending until complete exact-variant cost evidence covers two-thirds of ranked rows jointly with the admitted components (E95, E101).
