What changed at general availability, at a glance

In its November 10 post, Google said developers, enterprises, scientists, and consumers can now try Gemini 4 Carbon. The same post says Carbon was released two weeks earlier to a set of cybersecurity defenders through the Fairwind Program. The model’s own benchmark and security details were covered in earlier articles, so this one concentrates on what was newly set at general availability: who can use it, what it costs, what the limits are, and what to change in existing code. For the model itself, see Gemini 4 Carbon staged rollout: security scores and pricing; for the external index ranking, see Gemini 4 Carbon Tops AA Index v5: What the 59 Means.

  • The audience widened. Google says availability moved from an earlier release to defenders to an offering addressed to developers, enterprises, scientists, and consumers.
  • The API is open to paying developers and enterprises. The post says it is available through Google AI Studio and Gemini for business to all paying developers and enterprises. The free tier is excluded.
  • The model ID is gemini-4-carbon. The model page lists gemini-4-carbon as the stable version identifier and shows the latest update as November 2026.
  • The price is an introductory price. Both the post and the pricing page say $2 input and $10 output through November 30, 2026, with $4 input and $20 output applying afterward.
  • It sits on the same price sheet as Argon. The docs say the two models share the 1M unified context window, built-in tools, and per-token pricing. The difference is how many thinking tokens each spends per turn.

  • The post says Carbon is at the same introductory price as Argon ($2 per million input tokens and $10 per million output tokens), and a footnote says that after the introductory period expires on November 30, 2026, $4 per 1M input tokens and $20 per 1M output tokens will apply.
  • On December 1 the standard input and output rates each double (calculation: 4.00 ÷ 2.00 and 20.00 ÷ 10.00). Dividing the two columns for Batch, Flex, and Priority gives the same ratio.
  • Only implicit caching is available. Explicit caching is not supported; the docs say implicit caching is on by default for prompts of at least 4,096 tokens and discounts cached input tokens by 95% on cache hits.
  • Every token the model processes is counted and billed. The pricing page says this includes thinking tokens and, when grounding is used, internal tool system instructions and function declarations.
  • Grounding with Google Search is billed separately: 5,000 free requests per month (shared across all Gemini 3 and newer models), then $14 per 1,000 requests, with a daily cap of 1,500 requests. A single request may trigger more than one search query, and each query is charged.

Carbon and Argon: same price per token, different token use

The “Choosing between Carbon, Argon, and other models” section of the Gemini API docs says the two models share the same 1M unified context window, built-in tools, and per-token pricing, and that the main difference is how many thinking tokens each spends per turn. The post likewise says Argon remains the ideal choice for the majority of software engineering and knowledge work, while Carbon is built for tasks that test the limits of a model’s intelligence.

  • Carbon. Built for tasks that push the limits of reasoning depth, per the docs. It spends more thinking tokens per turn to explore thoroughly and verify its work, which increases per-turn token use and latency compared with Argon. The docs name complex root-cause debugging, architectural design, dense multimodal synthesis, scientific proofs, and security auditing.
  • Argon. Described as ideal for most advanced software engineering and knowledge work. It offers faster responses and lower token spend per turn, and the docs point to interactive coding, day-to-day feature work, and fast production loops.
  • The cost implication is this: since the per-token price is the same, any difference arises from how many tokens the same job consumes. Neither the docs nor the post gives a comparison of tokens used by the two models on the same request.
  • Carbon has three thinking levels, low, medium, and high, with medium as the default. The docs summarize them in the table below.
Thinking levelToken useUse recommended by the docs
lowFewest tokens, lowest latencySimpler tasks and cost-sensitive work; also analysis and writing that need light thinking, though quality can drop on hard tasks
medium (default)BalancedRecommended for most tasks, including complex code and agentic use cases
highMost tokens, slowest first tokenComplex reasoning, hard math and science, and the most difficult code or agent tasks; pairs well with long decode for long outputs
  • The docs’ operating advice is to run your evaluations at all three levels and pick the lowest level that meets your quality bar.
  • To use fewer tokens, the docs say to lower the thinking level rather than the output limit.
  • The docs also say the Antigravity agent in Gemini Managed Agents now supports gemini-4-carbon.

Limits and features listed on the model page

The gemini-4-carbon model page lists limits and feature support in a table. What follows restates it in plain terms. The Carbon page alone does not show whether any value differs from Argon, but the model list gives the same context and maximum output for both models.

  • Context window. The unified input and output limit is 1,048,576 tokens. The docs say input, thinking, and output tokens share one window.
  • Maximum output. The default synchronous response is 65,536 tokens, and up to 1,048,576 tokens with long decode. The model list writes this as “65K / 1M tokens.”
  • To generate past 65K tokens. Synchronous responses stop at 65,536 tokens, so turn on background and raise the maximum output tokens above 65,536. The ceiling is the 1M unified window minus your input tokens.
  • Input and output formats. Inputs are text, image, video, audio, and PDF; output is text.
  • Supported features. Code execution, computer use, file search, function calling, grounding with Google Maps and Google Search, structured outputs, URL context, and thinking (low, medium, high) are marked supported. Agentic video understanding defaults to static.
  • Unsupported features. Audio generation, image generation, and the Live API are marked not supported. Context caching is supported for the implicit kind only.
  • Consumption options. Batch API, Flex inference, and Priority inference are marked supported, and the pricing page lists a rate for each.

The hop structure and billing conditions of long decode were covered first for its sibling model in Gemini 4 Argon now available: long decode, limits, pricing. The Carbon docs describe the same background execution method.

Performance and cost claims, read with their conditions

The post says that across “independent benchmarks,” Carbon pairs frontier accuracy with practical production economics. Here are those statements, split out with their conditions.

  • Workflow rankings. Google says Carbon ranks #1 on CursorBench 4.0, Perplexity’s WANDR, and Zapier’s AutomationBench, at more than 2X lower cost per task compared to the next best external model. The post does not name that model.
  • Multimodal knowledge agents. On the Multimodal Knowledge Agent (MKA) benchmark launched with Artificial Analysis, Carbon ranks #2 and is more than 6X lower in average cost per task than the top performing model. That wording states, along with the multiple, that Carbon is not first.
  • Finance evaluations. In pre-release evaluations, Carbon matched the best model tested on Hebbia’s E2E Financial Agentic evaluation and ranked at the top out of 23 frontier model configurations on Balyasny Asset Management’s General Financial Intelligence benchmark, according to the post.
  • Engineering. The post says Carbon performs exceptionally well on tasks that require multi-agent collaboration, such as multi-package migrations, cross-subsystem root-cause investigations, and complex architectural redesigns. For web apps, it says Carbon runs build-and-verify loops, recovers from errors, and checks both its code and the rendered UI.
  • /swarm in Antigravity. Google says it is previewing /swarm, which turns a single prompt into a coordinated team of agents you can track in real time. Carbon can be assigned roles that demand the deepest reasoning, such as design, coordination, and auditing, paired with faster, lighter models.

Here is when these numbers hold. The rankings are on the named benchmarks, and the cost-per-task comparisons are against the comparison targets Google chose (the next best external model, or the MKA top model). Your own cost per task depends on the thinking level and output limit, as seen above, so carrying the multiples from a ranking table straight into a budget goes beyond what the source allows.

  • Raw benchmark scores do not appear in the body of the post; only rankings and multiples are given.
  • The post describes the two finance evaluations as pre-release evaluations.

Safety and security figures within what Google reported

The post says Google strengthened misuse safeguards as the model’s cyber capabilities grew stronger. All figures below are Google’s, and each comes with a test environment and a comparison target.

  • Simulated attack tests. In simulated cyberattack environments seeded with ExploitBench and CyScenarioBench, Google says Carbon blocked 99% of attack trajectories from an adaptive red-teaming agent that can revisit its plans after each block.
  • Per-attempt breach rate. The post says Carbon’s safeguards lowered it to just 0.8%, down from 3.1% on Argon.
  • Gray Swan testing. The automated cyberattack query success rate was 2.17%, compared with 9.86% on Argon, Google says.
  • External testing. Trajectory Labs found zero new universal jailbreaks across 132 hours and over 13,000 requests, according to the post.
  • Honesty benchmark. On a 375-task agentic honesty benchmark, Carbon passed 92% of tasks (compared with 70% for Argon), declining to fill in missing experimental data 98% of the time and flagging methodological flaws 68% of the time.
  • Indirect prompt injection. Google says Carbon reached a 0% attack success rate on the Gray Swan IPI benchmark two weeks earlier, and adds in the same passage that prompt injection robustness remains an area for continued improvement and that its automated red teaming showed models could be further improved against sophisticated attacks in some distributions.

Security teams should note the last item. Google wrote the limitation in the same paragraph, so a design that does not rest injection defense on Carbon alone does not conflict with these figures.

What you can do now: decision criteria by situation

The items below split the migration checklist in the Gemini API’s what’s-new page (What’s new in Gemini 4 Carbon) by situation. No procedure that is absent from the docs has been added.

  • If you already run Argon. Change the model string from gemini-4-argon to gemini-4-carbon and test with the same request. The docs say no request schema changes are required.
  • Start from the lower thinking level. Keep the default medium, and raise to high only when a workload needs it. Evaluate at all three levels and pick the lowest that meets your quality bar.
  • Check the output limit. If an existing app’s limit is below 32K, the docs advise raising max output tokens to at least 32,768, because Carbon can spend more of the limit on thinking than earlier models. To use fewer tokens, lower the thinking level instead.
  • Use background for long outputs. For generation past 64K, turn on background and set max output tokens above 65,536. For complex reasoning and coding, the docs give 131,072 or 262,144 as starting values.
  • Lengthen timeouts. Hard prompts can take several minutes, so the docs advise using background execution or setting HTTP client timeouts to at least 15 minutes.
  • If you use explicit caching. Remove calls to cachedContents and caches.create and any reference to cached_content from your requests. Implicit caching is on by default for prompts of at least 4,096 tokens.
  • Remove sampling parameters. The docs say temperature, top_p, and top_k are ignored if provided.
  • Redo the cost estimate. All tokens are billed, so include internal tool instructions and function declarations when grounding, and run the numbers at both the pre- and post-December 1 rates. For multi-turn conversations, the docs advise keeping state on the server with previous_interaction_id.

The docs’ starter example follows. It is a request that sets the thinking level to medium explicitly.

from google import genai
                    
                    client = genai.Client()
                    
                    interaction = client.interactions.create(
                        model="gemini-4-carbon",
                        input="Analyze this payment processing pipeline for race conditions during retry attempts and rewrite the transaction locks safely.",
                        generation_config={
                            "thinking_level": "medium"  # balanced reasoning effort for complex tasks
                        }
                    )
                    print(interaction.output_text)

Frequently asked questions

How much does the Gemini 4 Carbon API cost?

Google says the standard rate is $2 per million input tokens and $10 per million output tokens (thinking tokens included) as an introductory price through November 30, 2026. From December 1 the price is $4 for input and $20 for output. It is not available on the free tier.

What account do I need to use Carbon?

Google says the API is available through Google AI Studio and Gemini for business to all paying developers and enterprises. The Gemini app and AI Mode in Search are rolling out to Google AI Ultra subscribers. It is not available on the free tier.

Do I have to rewrite much code to move from Argon to Carbon?

The official docs say no request schema changes are required: change the model string from gemini-4-argon to gemini-4-carbon. They do advise checking output limits and HTTP timeouts, because Carbon spends more thinking tokens on hard tasks.

Is Carbon more expensive than Argon?

The docs say the per-token price is the same. The difference is how many thinking tokens each model spends per turn, and the docs say Carbon increases per-turn token use and latency compared with Argon. No comparison of actual bills for the same request appears in the source.

As of when are the prices and conditions in this article?

They are based on Google’s announcement and the Gemini API docs as viewed on November 11, 2026. The end date of the intro price and the later rates are written in the docs, but terms can change. This is general information and not a substitute for purchasing or contract advice.
