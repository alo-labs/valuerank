Measured over 2026 11/16 – 11/23, a week of Claude Ultra (formerly Max 20x) is worth about $1,570 of official API usage (≈ $6,801 a month), 9.6× Pro ($163), not 20×. Measured on real subscription accounts and updated every Monday.

Data updated 2026-11-23

How much do Claude Pro, Max and Ultra give per week?

Paid Claude plans have two limits at once: a rolling 5-hour session limit and a weekly limit, and whichever runs out first stops you; verified Ultra accounts keep only the weekly one. A full week, measured on real accounts:

  • Claude Pro ($20/mo): ≈ $163 of API use a week (≈ $707/month) · 21.3M uncached tokens · ≈ 13 full 5-hour windows
  • Claude Max (Max 5x) ($100/mo): ≈ $844 of API use a week (≈ $3,657/month) · 100M uncached tokens · ≈ 12 full 5-hour windows · 5.2× Claude Pro
  • Claude Ultra (Max 20x) ($200/mo): ≈ $1,570 of API use a week (≈ $6,801/month) · 186M uncached tokens · ≈ 5.7 full 5-hour windows · 9.6× Claude Pro, not 20×

Why "how many tokens per week" has no single answer

Most tokens in a long session are cache reads, and cache reads barely count against a plan. The same weekly limit can carry several times more total tokens for someone with a high cache hit rate. Compare plans by tokens excluding cache reads, or by API value, never by total tokens.

  • Claude Pro: 73% cache reads, 85.0M tokens a week, of which only 21.3M are not cache reads
  • Claude Team Standard: 91% cache reads, 267M tokens a week, of which only 22.7M are not cache reads
  • Claude Max (Max 5x): 92% cache reads, 1.21B tokens a week, of which only 100M are not cache reads
  • Claude Team Premium: 90% cache reads, 978M tokens a week, of which only 96.4M are not cache reads
  • Claude Ultra (Max 20x): 92% cache reads, 2.25B tokens a week, of which only 186M are not cache reads

Subscription or pay-as-you-go

A plan is the best deal when you use all of it. Most people do not: below the share shown here, paying per token costs less than the subscription. When you hit the weekly limit, you can keep using the same model on Wokey.

What uses up your limit

  • Cache reads barely count: On Claude plans a cache-read token uses close to none of your limit. Most tokens in a long session are cache reads, so "tokens used" and "limit used" are very different numbers.
  • Cache writes ≈ uncached input: New context entering the cache costs about the same as uncached input. Starting fresh sessions or rewriting large context burns the limit fastest.
  • Output costs about 4–7× input: Within one model, each output token uses roughly 4–7 times the limit of an input token. Asking for long files or documents in one go drains it noticeably faster.
  • Opus 5.5 is cheaper on the limit: Per token, Opus 5.5 uses about 0.6× the limit of other Opus and Fable models. The same work on an older Opus or on Fable empties the week sooner.

How we measure

  • The data comes from limit changes on real subscription accounts behind the Wokey gateway, together with the traffic they served. When an account’s weekly usage rises by at least 10 percentage points, the requests in that span, divided by the rise, give a full week of traffic.
  • Each span needs at least 10 requests, with no more than 5% failed or boundary-crossing requests. A span is left out when its gateway traffic accounts for less than 70% of the limit it used, compared with the plan’s highest-reading accounts (the 90th percentile): that account was mostly used outside the gateway, and use outside the gateway only ever lowers a reading. Spans are first reduced to a median per account, then to a median across accounts, so every account counts once.
  • Traffic is priced at each model’s official API rates, including cache reads and 5-minute and 1-hour cache writes. Cache reads barely count against the limit while uncached input and output weigh heavily, so the same limit converts to more dollars in a cache-heavy week. To keep weeks comparable, for Claude we fit each week how much of the limit each token type uses, then value every plan at one fixed traffic split: Claude Code traffic on Wokey in the week to 2026-11-02, about 92% of tokens cache reads. The dollar figure means "what a full week of that traffic would cost on the official API"; it is not the unit the vendor meters in. Claude Fable 5.2 uses noticeably more of the limit per official-price dollar than other models, so its weight is fitted separately and its traffic is converted to the dollars the same share of the limit buys at the fixed traffic split.
  • Every Monday after 04:00 UTC the past 7 days are remeasured. A plan is published once at least 5 accounts are measured. If a value moves more than 15% from the previous week, it is checked by hand before the page updates.
  • The limit is worth more or less depending on the model mix: the same limit spent on a different main model converts to a different API value. Each plan lists its model mix.

These are measured estimates, not figures published by the vendors. Vendors can change limits at any time, and use outside the gateway or delayed metering can shift the results.

How many tokens does Claude Pro give per week?

A median account that uses the full week runs about 85.0M tokens, of which about 21.3M are not cache reads and 3.5M are output. At official API prices that is about $163 a week, 35× the monthly fee. Total tokens swing with your cache hit rate, so treat them as a rough guide.

Is Claude Ultra (formerly Max 20x) really 20 times Pro?

Not by the week. The weekly limit measures about 9.6× Pro, and since renaming Max 20x to Ultra on 2026-10-30 Anthropic itself states 10× Pro a week. The 20× applied to the 5-hour window (measured about 21×), which verified Ultra accounts no longer have; on accounts that still have it, a week holds only ≈ 5.7 full 5-hour windows.

Claude Max 5x vs Ultra (formerly Max 20x): how much more does Ultra give?

Ultra costs twice as much as Max 5x (now sold simply as Max) and measures 1.9× its weekly limit ($1,570 vs $844 of weekly API value).

How do the weekly limit and the 5-hour limit interact?

Both apply at once: the 5-hour window caps bursts and the weekly limit caps the 7-day total, and whichever runs out first stops you. Higher tiers have large 5-hour windows, so the weekly limit is usually the one you hit. The exception is Claude Ultra (formerly Max 20x): verified accounts have no 5-hour limit, only the weekly one.

Why does my Claude limit drain so fast?

Usually cache misses (new sessions, rewriting large context), very long outputs, or models that weigh more on the limit (older Opus, Fable). Cache reads barely count, cache writes cost like uncached input, and output costs about 4–7× input.

Is a subscription cheaper than the API?

If you use it fully, by far: a Claude Pro week is worth about $163 of official API usage for $20 a month. If you use less, pay-as-you-go can cost less; see "Subscription or pay-as-you-go" for the break-even share.

Why do these numbers differ from SemiAnalysis?

SemiAnalysis (2026-10-05) measured with controlled tests: a Claude Max 20x plan (now Ultra) spent entirely on Opus 5.5 is worth about $11,726 a month on an agentic workload (96.6% cache reads) and about $9,200 on a chat workload; Fable 5.1 can use only half the weekly limit, about $2,485 a month. We measure real traffic: Ultra is about $1,570 a week (≈ $6,801 a month). Two things explain the gap: we value every plan at a fixed traffic split that is about 92% cache reads, below 96.6%, and cache reads barely count against the limit while still costing money on the API, so the more cache reads, the higher the dollar value; and real traffic includes older Opus models that weigh more on the limit. The two agree on scale: theirs answers "the most one model can be worth", ours "what it is worth in real use".
