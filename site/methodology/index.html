Methodology 3.0.0

How ValueRank scores a model

A configuration's score is its value: a cost score carries a fixed 25% and benchmark quality the other 75%. That weight is nominal: on the current panel, cost accounts for 81% of the spread in API value and 62% in Plan value, because cost scores vary more across configurations than quality scores do. Cost is what it costs to run the SDLC basket once, scored on a log scale so cost ratios keep their size. Quality is the weighted mean of the benchmark leaves observed for that exact configuration: a missing leaf is left out and never filled in, and a configuration without a cost gets no value score.

Cost: the SDLC basket

The cost figure is the contestant-model API token cost for the SDLC basket (not total agent or workflow operating cost): Artificial Analysis' published cost of running Coding Agent Index, AA-Briefcase, GDPval-AA, GDP.pdf, AutomationBench-AA, Terminal-Bench 4.0 (AA Index run), SciCode, AA-LCR once at API rates (SDLC basket v1). Pending capture: FrontierCode, ITBench-AA. A configuration missing a component is scored on its own subset of the basket, flagged, and never compared as if it had run the whole basket.

The cost score is 100 × (ln cH − ln c) / (ln cH − ln cL), clipped to 0–100, against anchors frozen with anchor version v3-2026-10-21: API anchors $66.43 to $19,978.30 per basket run. At these anchors, doubling the cost costs 3.04 value points, which 4.05 quality points offset.

On the Plan basis the basket's API cost is divided by the selected subscription route's Value Multiple at full utilisation; a configuration without an admitted route falls back to its API cost, flagged. No Value Multiple is yet identified on the basket itself, so the Plan ranking is labelled exploratory.

Model inclusion

Frontier rule. Every model family on the Pareto frontier that Artificial Analysis (AA) renders on its Intelligence Index versus total cost to run chart is ranked at its highest point on that line (along the strictly rising line also its dearest). Frontier membership is AA's rendered line as observed; ValueRank never recomputes it from rounded values.

Near-frontier rule. A plotted configuration is near-frontier when its public (rounded integer) Intelligence Index is within 3 points of the rendered frontier's Index at its cost, meaning the highest Index among rendered-frontier points that cost no more. Every near-frontier family is ranked or is explicitly deferred by a dated, reasoned roster decision. Its selected configuration may differ from the near configuration: it is the configuration already ranked for exact DeepSWE and Bug Hunt evidence when there is one, else the near point with the smallest Index gap. The cost ratio to the frontier is reported for information only.

Policy as recorded: A plotted configuration is near-frontier when it lies within 3 Intelligence Index points of the rendered frontier at its cost. Every near-frontier model family must be in the primary ranking, with its own selected configuration, or be explicitly deferred with a dated, reasoned roster decision. The cost ratio to the cheapest frontier point of equal or higher intelligence is reported for information only.

What the uncertainty outputs cover

Frontier and cheapest-above-a-bar labels come from interval calculations that protect the published record against its reporting precision and against missing evidence. Scenario shares are frequencies over declared streams, never probabilities:

  • S0: published-record reporting precision
  • S1: published-record reporting precision + conventional identification of missing leaves
  • S2: published-record reporting precision + conventional identification of missing leaves + weight-specification stress
  • S1M: published-record reporting precision + conventional identification of missing leaves + conventional range sensitivity inside published 95% confidence intervals (no tail model)
  • benchmark repeatability beyond the conventional Terminal-Bench interval-range sensitivity in S1M (other published intervals, run-to-run ranges): not quantified in v1 scenario shares
  • fitted-parameter uncertainty (e.g. Elo rating intervals): not quantified in v1 scenario shares

The quality bar is a fixed quality level: quality 56.7 (the displayed quality of Grok 4.7 at freeze), the lower median of non-provisional ranked configurations with a displayed quality. It stays fixed for the anchor version.

Evidence grades

A model's grade is the weakest grade among the values inside its score.

  • User-measured Measured by the benchmark owner or in a controlled account measurement.
  • Provider claim Published by the model provider for the exact benchmark version and evaluated variant.
  • Modelled Owner estimate or projection anchored to a measurement.
  • Assumption Explicitly authorised assumption with no measurement.
  • Missing No eligible value; excluded from the score and the score is renormalised.

Limitations

  • Cost is the contestant-model API token cost of AA's runs, not total agent or workflow operating cost.
  • Cost scores use frozen anchors; a new anchor version is a published migration, never a silent change.
  • The basket is AA's SDLC-relevant evaluations at AA's token mix, not your own workload.
  • Results are never transferred between model versions or reasoning efforts; missing evidence stays missing.
  • Published values are rounded; interval outputs and scenario shares show which differences the evidence supports, and benchmark run-to-run noise is not yet quantified.
  • Subscription Value Multiples are measured on their own workloads; none is yet identified on the basket, so the Plan ranking is exploratory.

Questions

How is the value score calculated?

Cost carries a fixed 25% of the value score and quality the rest. The cost score compares what each configuration costs to run the SDLC cost basket once, on a log scale against frozen anchors, so equal cost ratios count equally. Quality is the weighted mean of eleven benchmark leaves on fixed 0-100 anchors.

What happens when a benchmark has no result for a model?

The leaf stays missing: quality is averaged over the leaves observed for that exact configuration, nothing is filled in, and the coverage and any provisional flag are shown. A configuration without a cost gets no value score.

What is the difference between the API ranking and the Plan ranking?

Both price the same SDLC basket. The API ranking uses Artificial Analysis' cost at API rates. The Plan ranking divides it by the selected subscription route's Value Multiple, the API-priced usage a plan delivers per dollar of fee at full utilisation; a model without an admitted route falls back to API cost, flagged.

What do the evidence grades mean?

Measured values come from the benchmark owner or a controlled account measurement. Estimates are concordant end-user reports, and assumptions are owner-authorised transfers of one model's measured multiple to another.

Why is a model not ranked?

The ranked cohort is fixed policy: configurations on Artificial Analysis' Intelligence-versus-cost frontier or near it. Other models still have pages with what we hold.
